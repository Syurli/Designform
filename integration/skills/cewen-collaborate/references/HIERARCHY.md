# 层级与排序（应用 0.7）

`PROJECT.md` 的 `systems` 为分类目录，每项保留 `id`、`title`、`color`，可选 `parent` 指向父分类 ID。文档的 `system` 指向主要分类；可选 `parent` 指向另一份 DD 的稳定文档 ID。子 DD 继承父 DD 的分类。分类与文档合计最多为总纲以下五层，不允许形成循环。

总纲是唯一根 GDD，没有 `system` 或 `parent`。其小节通常留在总纲内；只有用户明确分类时才用 `sectionSystems`。没有总纲的项目可以先维护 DD，不能为了图谱中心补造设计内容。

同级分类按 `systems` 数组顺序。文档顺序写入 `PROJECT.documentOrder`：直属分类成员以分类 ID 为键；子 DD 以 `document:<父文档ID>` 为键，值为文档 ID 数组。顺序不通过改标题或文件名实现。只修改当前公开文件，保留历史快照。

移动一个父 DD 到其他分类时，清除其旧 `parent`，将其后代 DD 的 `system` 一并更新；保留后代自己的 `parent`。分类调整、受影响文档和顺序应在同一批次提交。禁止把层级关系复制为文末手工关联。

用正文中的 `[文档名称](相对路径.md)` 引用另一份设计；这种引用与父子归属独立存在。拖入正文也产生相同 Markdown 链接，用户读到的是自然语句中的文档名称。镜头、方向、卡片位置和三维拖动只属 `.cewen/` 私人阅读状态。
