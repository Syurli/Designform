# 持续问询

问题标题直接描述要确认的设计，不添加优先级、登记范围或入库说明。背景只保留已有依据与具体未知；目标文档、轮次及来源身份放在头部，不重复写来源路径。没有明确摘录时不创建空锚点。预设选项仅包含设计候选，不加入软件操作项；自定义回答、空白暂缓和“题目有问题”由界面提供。

用户选择或输入即计为已回答，不要求逐题再次确认。回答自动追加到问题 Markdown；切题与退出无需保存、提交或逐题复核。汇总列出所有历史轮次，按轮收起；打开某轮后直接复制开场白。开场白只带短项目号、版本、题数与 @a 读取引用，直接用 cewen_context 读取，不先读 status 或全项目；问题和文档用 Q/D 短号，正文按引用后加 /D数字 读取。无需模型收发或核验 hash，提案可用同一引用、Q/D 短号、baseHash=null 和 dependencies={}，由软件补全正式身份和保存基准。没有 MCP 但可执行本机命令时用现有 CLI 的 answers 命令，无需先重启宿主。空白题保持暂缓，不代填。

只读取本轮相关公开文档及问题，记录基础修订。优先提出影响当前方向的少量问题，说明推荐方案的收益、代价与依据，并允许完全自定义。按稳定 ID 发布一问题一文件，后续题可写 follows/when；不填用户答案。用户完成后读取原始回答，分别记录你的解释及建议，按需形成可审核的修改提案；分析后说明下一轮建议目标，询问用户选择“开始下一轮／先修正本轮理解／暂时结束”，然后等待明确答复。用户同意前不得调用发题工具或通过其他方式写入新一轮问题。暂缓和否定前提都属于有效反馈，不能强行当成推荐选项。

回答、复制开场白和采纳提案都不自动授权下一轮。`cewen_quest_round` 同时写入摘要和新问题，不能用来仅保存分析；分析可在对话呈现，需要落入项目时提交候选修改。工具心跳不能证明模型已收到消息或正在推理。

文档内部块可使用 `<!-- cewen:block ID parent=父标题ID -->` 或 `parent=root` 明确章节归属；Markdown 源顺序是阅读顺序。移动段落保留身份及归属，不能根据画布坐标重排正文。

一轮是一批完整问题，同批跨文档共用轮次身份。已答题保持原题意和轮次；修改、修正前提或追问使用新问题 ID 与新轮次，可用 follows 关联旧题。来源正文和分析更新不要求逐题复核，不将旧回答重新变成待答。
