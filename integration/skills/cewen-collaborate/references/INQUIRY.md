# 持续问询

问题标题直接描述要确认的设计，不添加优先级、登记范围或入库说明。背景只保留已有依据与具体未知；目标文档、轮次及来源身份放在头部，不重复写来源路径。没有明确摘录时不创建空锚点。预设选项仅包含设计候选，不加入软件操作项；自定义回答、空白暂缓和“题目有问题”由界面提供。

用户选择或输入即计为已回答，不要求逐题再次确认。汇总末尾复制或预览开场白时，软件将本轮回答追加保存到问题 Markdown 并创建一个版本；开场白带实际版本、问题与回答 ID 及数量。模型只读取这些已保存原始回答；没有 MCP 但可执行本机命令时，优先使用现有 CLI 的 context 命令读取，不要求用户为了分析先重启客户端。其他轮草稿和空白题不代填、不自动写入。

只读取本轮相关公开文档及问题，记录基础修订。优先提出影响当前方向的少量问题，说明推荐方案的收益、代价与依据，并允许完全自定义。按稳定 ID 发布一问题一文件，后续题可写 follows/when；不填用户答案。用户完成后读取原始回答，分别记录你的解释及建议，按需形成可审核的修改提案；分析后说明下一轮建议目标，询问用户选择“开始下一轮／先修正本轮理解／暂时结束”，然后等待明确答复。用户同意前不得调用发题工具或通过其他方式写入新一轮问题。暂缓和否定前提都属于有效反馈，不能强行当成推荐选项。

提交答案、复制开场白和采纳提案都不自动授权下一轮。`cewen_quest_round` 同时写入摘要和新问题，不能用来仅保存分析；分析可在对话呈现，需要落入项目时提交候选修改。工具心跳不能证明模型已收到消息或正在推理。

文档内部块可使用 `<!-- cewen:block ID parent=父标题ID -->` 或 `parent=root` 明确章节归属；Markdown 源顺序是阅读顺序。移动段落保留身份及归属，不能根据画布坐标重排正文。
