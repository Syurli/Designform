# 策问 Designform

**面向游戏、叙事与影像创作的本地知识组织及 LLM 协作工作台。**

策问是 BAIGE（百舸）体系下的游戏策划工具，将游戏总纲（GDD）、专项设计（DD）、问询、设计关系与版本历史组织在同一个工作空间中。项目以可直接阅读的 Markdown 为权威源；LLM 可以参与阅读、问询与创作修改；已发起的普通任务自动保存暂定初稿，用户保留设计决策权，明确要求审核时使用提案采纳。

**当前版本：0.9.3 · 项目格式：1 / 2 · 接口协议：1**

回答分析进一步压缩：开场白使用短项目号、短版本号与单个读取引用；读取仅返回本轮问答和 Q/D 短号，文档正文按需获取。逐题 UUID、hash 和重复轮次不再交给模型，提案基准由软件自动补全。详见 [token 精简规范](docs/protocol/ANSWER_CONTEXT_0.9.3.md)。

2026-10-07 策问流程修订：作答区只保留题目与回答；空锚点不再误报来源不存在，问题反馈使用独立按钮。汇总自动收集本轮回答，末尾一键保存并复制分析开场白，无需逐题二次勾选或独立提交。开场白携带实际版本与回答数量，允许现有 CLI 接续分析。详见 [策问流程规范](docs/protocol/INQUIRY_FLOW_0.9.3.md)。

## 0.9.3 文档与协作工作台

项目策问拥有独立的范围、搜索、展开和作答位置；阅读筛选与标签保留。目录只显示有问题的分类、来源文档与问题，多来源题按稳定身份共用一个草稿和提交。未关联问题、条件未满足题和待复核旧草稿保留入口。上一题、下一题和返回阅读只暂存；本轮汇总按来源归组、自动收集本轮回答，其他轮回答按轮查看。两种文档视图的正文光标使用实际文字坐标与固定可见宽度，避免自由画布缩放产生错位。行为边界见 [项目策问协议](docs/protocol/PROJECT_QUESTIONS_0.9.2.md)。

文档栏：分类在原栏内按树状向下展开，选中上级分类汇总其全部后代文档，未选择分类显示全部文档。固定／标准／抽屉三种样式都以挤压方式给分类名称让位，深层路径压缩祖先行而不无限右移；右键期间保持展开，长按才显示拖动把手。路径在底部只作显示，顶栏色块柔和切换当前分类。目录与分页卡片库共用四种排序；卡片库只显示文档，正文或小节搜索命中归入所属文档，不另生成分类／小节卡片。滚轮与触控板按手势翻页，双击文档进入策划案；文档右键收为“卡片关系预览、改名、条目颜色、更多”四项。星标用于收藏，图钉用于当前分类置顶；拖入总置顶区新增快捷入口并保留原列表。

收藏支持一篇文档加入多个个人分类，也可多选文档批量设置。旧工作集合只读导入收藏分类，保留层级、说明、顺序和来源身份等个人整理元数据，原集合及正式归属不改写。两种文档视图的右侧统一为上方工具、下方约三分之一的紧凑属性；名称、标签、状态输入自动应用到当前草稿，“文件位置”在桌面打开对应位置。新文档和示例用标签表达原用途分类，旧资料只在用户实际修改当前文档属性时迁入标签。右键在原落点插入文字、图片或模块，已有图片支持重新导入；自由视图按最小文字块编辑，点击空白结束编辑。目录文档拖入文档视图形成带目标分类色的标题链接，拖入自由视图保留独立引用对象。保存草稿才写入正式项目。详见 [文档栏规则](docs/protocol/PROJECT_DIRECTORY_0.9.2.md) 与 [本地交互优化](docs/protocol/INTERACTION_0.9.2.md)。

**项目库 → 选择创作方向与组合设想 → 名称与位置 → 复制本项目开场白 → 暂定初稿与关键问题自动保存 → 逐题策问与分析 → 排演和素材制作。**

新建第二步采用宽屏组合区与大面积开场白编辑区，开场白可展开到整个内容区。六种原有方向保持；每种方向使用自身的辅助组合、目标、载体及制作条件，点击后明确提示加入的词条，手改开场白保留到主动重新生成。任务弹窗固定标题、关闭和底部操作；其他长面板的标题栏吸附。示例入口改为带学习说明的单选卡片。侧栏章节在文档视图和自由画布中均可跳转，并自动展开折叠的父章节。详见 [项目流程与章节定位](docs/protocol/PROJECT_FLOW_LAYOUT_0.9.2.md)。

项目预设只提供讨论起点，不决定固定空文档。全部格式2项目均可组合地图、角色、地点、剧情、场次、台词、分镜、声音和排演；游戏DD可以插入分镜，剧本可以引用地图，不按项目预设限制模块。地图源与战斗/剧情/镜头覆盖层分离，修改本处标注不会复制或污染共享源。

启动默认进入分页项目库，支持收藏、名称／创建时间／最后编辑时间排序及弹窗确认删除（无需输入名称）。保留原主面板、知识空间／策划案／卡片库、三种图谱及关系卡片；块状分类目录、标签画布和属性栏嵌入原策划案区域；问策、排演与生产从文档内模块进入。角色卡、地图卡、道具卡都是可编辑的普通文档预设，个人预设可从空白、官方副本或当前文档创建。预设不限制任何模块。示例入口按学习内容打开 3—4 份主题文档，综合工程作为进阶示例；示意图、合成音和预置问答不代表真实创作决定。

图片/配音生产包使用稳定任务身份和来源哈希。回导不等于采用，旧依据的结果不会自动覆盖当前镜头；桌面候选提供受控ComfyUI适配，但真实模型工作流仍需验收。排演可导出自包含HTML，不是完整剪辑软件或MP4渲染器。

新项目使用格式2，媒体在`assets/objects/<sha256>/`不可变存放，由历史清单引用。旧格式1项目保持读取，启用新能力前在用户指定副本升级，不原地改写旧历史。完整协议见 [创作模块](docs/protocol/CREATIVE_0.9.md)、[Quest](docs/protocol/QUEST_0.9.md) 和 [媒体/生产](docs/protocol/MEDIA_0.9.md)。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 策划编写 | 编写 GDD、DD 与问题文档，支持 Markdown 编辑、章节组织、引用、图片和草稿恢复。 |
| 知识组织 | 通过层级目录、三维星图、系统分层和设计脑图阅读同一份设计；分类归属、正文引用与手工关系各有明确来源。 |
| 统一设计文档 | 在同一份正文中组织对白、图片参考与色板；公开排版和共享注释使用伴随文件，不另建一套正文。 |
| 新手教程 | 从统一入口打开少量文档的可编辑示例，在正常画布中练习；不自动创建本地练习副本。 |
| LLM 协作 | 可编辑开场白、CLI/MCP 接入；本轮任务自动备份、文档锁、实时工作稿与完成保存，支持原始回答追溯和可选提案审核。 |
| 版本追溯 | 保存完整公开快照，支持版本比较、历史阅读、恢复、撤销计划和命名基线；恢复操作形成新修订。 |
| 资料交换 | 导入前预检身份、路径和差异，支持当前稿、历史包及完整备份导出，并提供本机自动恢复点。 |

连接摘要按真实 MCP 心跳判断在线，访问当前项目单独提示。同一个 Codex 程序可建立多个 MCP 会话；详情合并同类会话并显示会话数量，不能将其视为客户端程序数量。断开记录临时保留，不计入在线会话。桌面快捷方式更新不会自动迁移客户端已配置的 MCP 启动路径。

维护者可通过 `App/Current` 固定安装入口启动 MCP，并从该安装版读取 Skill、协议和使用说明。更新本地安装时同步切换 Current，客户端重连后使用新版；正常策划协作不需要软件开发工程。详细规则见 [安装版接入](docs/protocol/INTEGRATION.md)。

## 开始使用

### 选择发行形态

| | 独立网页版 | Windows 桌面版 |
| --- | --- | --- |
| 入口 | [GitHub Pages](https://syurli.github.io/Designform/) | [GitHub Releases](https://github.com/Syurli/Designform/releases) |
| 运行方式 | 使用支持文件夹授权的桌面 Chrome / Edge，通过 HTTPS 或 localhost 打开。 | 解压 Windows x64 便携包，运行 `策问 Designform.exe`。 |
| 项目存储 | 用户明确授权的本机文件夹。 | 用户指定的本机目录。 |
| LLM 接入 | 文件协作、交换包，或部署并配对独立本机 MCP 环境；页面与服务独立运行。 | 文件协作、CLI 与本地 stdio MCP。 |
| 安装要求 | 无需安装桌面程序。 | 内置运行时，无需另装 Node.js 或 npm。 |

两种形态共用业务规则与项目格式。同一项目应只保留一个策问写入端：先在当前端保存并关闭项目，再从另一端打开同一个目录。

### 建立第一个项目

1. 在项目库打开“示例与新手教程”，直接在正常文档工作台中编辑、播放；关闭后不保存，Ctrl+S 进入“项目另存为”。
2. “新建项目”先选游戏、叙事、剧本、微电影、综合或空白。非空白组合可多选、自定义或跳过的设想，再指定名称与位置；完成后直接复制绑定真实项目身份的开场白。空白直接指定名称与位置。项目简介只保存设想，私人手改开场白保留，文档由后续任务按内容组织。详见[创建协议](docs/protocol/PROJECT_CREATION_COLLABORATION.md)。
3. 新建基础文档时可选角色卡、地图卡或个人预设；在文档中自由组合图片、文字、字段、地图、对白等模块。Ctrl+S 保存当前文档，Ctrl+Alt+S 保存全部，Ctrl+Shift+S 将完整工作稿另存为。

学习示例的正文、布局、媒体和草稿仅存于本次页面会话内存，不创建项目目录，不写 localStorage、IndexedDB 或 OPFS 草稿。取消另存为保持临时编辑；确认后才创建独立工程。正式网页项目必须选择磁盘目录。文件权限与恢复边界见[双版本使用说明](docs/双版本开发与发布.md)。

桌面菜单“文件 → 在浏览器打开”会打开桌面程序提供的同一个本地工作台，而不是独立网页版；使用期间需保持桌面程序运行。

## 项目文件与数据边界

以下是策划项目的目录，不是软件源码目录：

```text
项目目录/
├── PROJECT.md          项目身份、说明与公开分类
├── docs/
│   ├── README.md       项目文档阅读说明
│   ├── gdd/            游戏总纲
│   ├── dd/             专项设计
│   ├── questions/      问题、用户原始回答与决定记录
│   ├── assets/         图片及其他相对路径附件
│   ├── layouts/        以文档 ID 命名的公开排版 JSON
│   └── annotations/    项目共享注释 Markdown 与笔画 JSON
├── assets/objects/     格式2的不可变图片与声音（以内容哈希定位）
├── versions/           公开快照、媒体引用、版本清单与基线
└── .cewen/             编辑器工作记录、草稿、提案、私人视图与索引等
```

`PROJECT.md` 与 `docs/` 是当前公开内容，`versions/` 用于追溯。公开布局和笔画是对应文档的伴随数据，不替代 Markdown 正文。`.cewen/` 包含不同共享范围的工作记录，不应整目录作为模型上下文；私人内容须经用户明确选择或发布。

应用的本地文件读写不会向 GitHub Pages 上传策划内容。用户主动把文档交给外部 LLM 时，数据处理范围取决于所用客户端、模型服务与授权设置，不能把“本地存储”理解为外部模型不会接收上下文。

## LLM 协作与 MCP

### 推荐工作流程

**核对连接与项目 → 读取相关文档 → 开始任务 → 登记实际目标 → 保存暂定初稿与关键问题 → 完成本轮并记录版本。**

普通已发起创作使用 `cewen_work_begin → cewen_work_documents → cewen_work_write → cewen_work_finish`，由软件备份原稿、锁定目标并实时展示工作稿；其他文档可继续编辑。初稿不是用户确认，不能替用户作答。用户明确要求审核时走提案；回答分析后仍须等待用户明确同意下一轮。真实参数、恢复与并发边界见[协作任务协议](docs/protocol/COLLABORATION_WORK.md)，界面见[实时协作界面](docs/protocol/COLLABORATION_UI.md)。

接入桌面版时，先启动策问，再使用连接区生成的开场白。发行包顶层的 `策问MCP.cmd` 是 stdio MCP 启动入口；`策问CLI.cmd help` 可查看 CLI 命令。客户端配置、服务发现及环境变量见[独立接入说明](docs/protocol/INTEGRATION.md)。

当前源码 MCP 注册 **38 个工具**（以客户端实际 `tools/list` 为准），其中六个协作任务工具负责登记、增量写入、完成、状态和控制。保留原20个工具，并新增能力发现、对象读取、Quest多轮接续、生产预览和图片/音频读取；还提供模块Schema资源与续轮Prompt。除项目列表、搜索、上下文、历史、问询、提案、导入预检与外部批次外，还提供当前协作状态、单文档分页读取、项目级提案状态、图片附件读取、命名基线、备份状态，以及恢复/撤销的只读计划。MCP 是受控的策划协作接口，目标是覆盖 LLM 实际需要的策划业务，而不是复制所有界面按钮。

公开 Markdown 与正文中的对白、色板设计块可通过受控任务自动保存；用户明确要求审核时，可用文本提案提交公开 Markdown 或受控的公开排版、笔画 JSON 候选。当前上下文会携带项目入口哈希、文件哈希、诊断与恢复状态，并支持按文档、条目、分组和显式项目批注选择；图片附件可由 `cewen_asset` 在项目边界内直接读取。完整覆盖与保留边界见 [MCP 能力审计](docs/protocol/MCP_CAPABILITY_AUDIT.md)。

MCP 不提供代填用户答案、自动采纳自己提案或任意路径写入。任务工具仅写已登记目标，完成时验证原稿与依赖。`begin-batch`、`end-batch` 与 `checkpoint` 管理已获授权的外部文件编辑流程，本身不提供文件写入能力。CLI 或宿主文件工具的能力不能视为 MCP 已开放的能力。

连接区区分通道与任务：灰色未连接、绿空心已连接空闲、黄闪正在编写、绿实心本轮完成、红色异常；异常优先且保留并发任务数量。连接心跳不表示模型已读全部项目。Pages 可在首次下载确认后后台准备独立本机环境，再部署到项目私有目录；启动与配对步骤见[Pages 本机接入](docs/protocol/PAGES_CONNECTOR.md)，无需隧道或 ChatGPT 插件。模型名由配置或 `cewen_identify` 明确报告；未知时不猜测。

无法连接本机 MCP 的模型，仍可使用用户提供的 Markdown、上下文包及[协作 Skill](integration/skills/cewen-collaborate/SKILL.md)。策问不绑定模型厂商，也不自动调用模型生成内容。

## 源码开发

### 环境与启动

使用 **Node.js 24** 与 npm，依赖版本由 `package-lock.json` 固定。以下命令在仓库根目录执行：

```bash
npm ci
npm run dev
```

`npm run dev` 启动带本地文件服务的开发工作台。开发独立网页版时，改用 `npm run dev:web`，默认入口为 `http://127.0.0.1:5174/Designform/`。

| 命令 | 用途 |
| --- | --- |
| `npm run build:all` | 类型检查、桌面前端与独立网页构建、桌面服务和 CLI/MCP 运行时构建。 |
| `npm run serve` | 运行已构建的本地服务，需先生成 `dist/` 与 `runtime/`。 |
| `npm run desktop` | 启动 Electron 应用，需先完成前端和运行时构建。 |
| `npm run package:win` | 构建并打包 Windows x64 发行包。 |
| `npm run licenses` | 更新随应用分发的第三方许可材料。 |

桌面开发服务默认使用用户文档目录下的 `策问工作区/开发沙盒`，正式服务使用 `策问工作区`。`CEWEN_HOME` 可指定独立项目中心；`CEWEN_URL` 可为 CLI/MCP 指定本机回环服务地址。这些环境变量不用于配置独立网页版的文件夹权限。

### 源码结构

```text
src/                   工作台界面、编辑器与图谱交互
shared/                文档模型、解析、设计块与共享业务规则
server/                项目、版本、问询、提案与文件事务服务
browser/               独立网页版的文件系统与平台适配
desktop/               Electron 宿主与发行启动器
integration/           CLI、MCP 与 LLM 协作 Skill
templates/             虚构示例项目
scripts/               构建、打包及资源处理
docs/                  协议、设计说明、验收与发布记录
```

0.9.3 的共享源码发布到 main，固定标签 v0.9.3 同时定位 Pages 与 Windows 产物；发布附件 SOURCE.json 记录源码提交。最终状态以 GitHub Actions、Pages 部署和 Release 附件为准。`main` 为共享主线，任务分支使用 `codex/` 前缀。开发协作要求见 [AGENTS.md](AGENTS.md)；修改业务行为时应同步维护协议与验收记录。仓库默认不运行自动化测试套件，按任务执行必要的类型检查、构建和人工验收，并明确记录未覆盖项。

## 原位编辑与阅读

策划案的文档视图、自由视图均可单击正文原位编辑，右侧上方为工具、下方约三分之一为自动应用到草稿的紧凑属性。选中文字后，可在浮动工具栏切换本机字体、斜体、荧光笔、字体颜色和字体底色；样式随 Markdown 正文保存。系统分层仅分类同层并列，文档依次向后排布。文档栏和总置顶栏移除左右滚动条，项目打开显示实际阶段进度。行为与验收见 [交互协议](docs/protocol/INTERACTION_0.9.2.md) 和 [QA](docs/protocol/QA_0.9.2.md)。本轮构建与人工检查范围见 [0.9.3 检查记录](docs/protocol/QA_0.9.3.md)。
