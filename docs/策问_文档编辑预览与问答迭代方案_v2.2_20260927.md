## 已确认的四项交互

1. 明确拖拽落点：普通拖动仅改变坐标；归入标题高亮区才关联，进入解除关联区才解除。
2. 未归属章节的内容可自由穿插：允许放在章节前后或章节之间，预览不依据画布坐标猜顺序。
3. 下一题仅暂存：本轮汇总核对后提交，允许提前提交已填写的部分。
4. 在预览中调整顺序：显式开启“调整顺序”后拖动段落或章节，退出后恢复干净阅读排版。

以上为用户实际选择，优先于此前方案中的建议默认值。用户随后明确要求开始执行，现已授权本地程序实施。

最新补充：提交本轮回答后，生成交给已连接 MCP 的 LLM 的专用开场白；LLM 先分析整理，再询问用户是否开始下一轮并等待答复。提交回答、复制开场白和采纳提案都不自动授权发布下一轮问题。

## 一、产品目标

用户围绕一份基础文档阅读方案、直接修改内容、回答 LLM 提出的当前轮问题，并审核修改提案，逐轮形成清晰且可追溯的设计。

三种工作状态：
1. 预览：默认进入，以完整标准文档阅读当前内容。
2. 编辑：在自由画布中原位编写和组织文档块。
3. 策问：围绕当前文档逐题回答本轮问题，提交回答、接收追问、审核提案。

沿用原主面板、块状分类目录、星空／分层／思维导图及关系卡片。角色卡、地图卡、道具卡继续是普通文档预设，模块组合不受预设限制。

## 三、导航和品牌

### 3.1 策问按钮

- 左上角使用完整“策问”中文文字标识，两字采用同一字体、字号、字重和基线，建议 18px／600。
- 应用图标继续用于任务栏和窗口身份；软件内不再把图标中的“策”与独立大“问”拼在一起。
- 点击“策问”进入问答状态；按钮可获得键盘焦点，悬浮说明“回答当前文档的问题”。
- 当前文档有待答问题时显示小型数量标记；题目变化时更新数量，不闪烁、不自动跳转。
- 问答状态下按钮高亮；再次点击保持当前题目，不重启轮次。

入口行为：
- 当前文档存在：进入该文档正在作答的轮次和题目。
- 当前文档没有问题：展示“本页尚无待回答问题”，提供“请 LLM 围绕本页提问”和“导入本页问题”；推荐开场白可编辑。
- 当前项目存在但未选文档：在工作区列出该项目有问题的文档，用户选择后开始。
- 停留项目库且项目会话仍在：恢复会话并进入其当前文档问答。
- 没有打开项目：显示选择／新建项目的明确入口，不代入其他项目或演示问题。

### 3.2 项目库与返回

项目库成为可往返的页面：
- 点击“项目库”仅挂起当前会话，不关闭文档、不清除草稿、不释放临时示例。
- 项目库标题附近显示“← 返回《项目名》”，必要时附“有未保存修改”。
- 返回恢复文档标签、当前预览／编辑状态、滚动位置、画布镜头、分类页及当前问答题。
- 删除正在打开的项目、切换到另一个项目、显式关闭项目或退出软件时，才执行保存／放弃／取消流程。
- 启动无会话时隐藏返回按钮。该方案先支持一个活动项目会话，不同时引入多项目窗口管理。
- 示例挂起继续只在内存保留；关闭／退出后清除，保存仍须另存为。

## 四、策划案的预览与编辑

### 4.1 默认状态

- 打开项目／首次打开文档，默认预览。
- 新建空白文档或刚从预设生成的文档，直接进入编辑并聚焦首个可写内容；这是主动创作的例外。
- 当前会话内切换已打开标签时恢复该标签最后的模式；从项目库返回也恢复原状态。
- 重启应用后重新打开项目仍默认预览；恢复出的未保存草稿应明确标识，允许预览草稿。
- 历史版本保持预览只读。

### 4.2 预览模式

显示同一份文档的标准连续排版：
- 不显示网格、块头、拖动手柄、缩放角和每块外框。
- 主标题、章节、正文、列表、表格连续排版，合并相邻普通段落的视觉容器。
- 建议正文 15–16px、行高 1.7–1.85，阅读宽度约 760–920px；窄区域自然收缩。
- 文档主标题只出现一次；章节级别清晰，避免把通用“内容块”当成正文标题。
- 图片保留宽高比和说明；普通角色／道具字段成为紧凑信息段，媒体保留播放控件。
- 地图、对白、分镜等保留各自有用的阅读表现。地图可平移缩放、媒体可播放；修改控件隐藏或引导进入编辑。
- 地图共享源与局部覆盖层仍分别渲染和保存。
- 右侧属性栏按需开启，默认把中央宽度让给阅读；不新增常驻面板。

预览来源：
- 有未保存修改时显示当前草稿，并标注“预览未保存内容”。
- 切换到预览不自动保存、不生成新文档、不重置画布坐标。
- 章节和阅读顺序决定排版；不根据画布 x/y 猜测文字先后。
- 从正文进入编辑时定位到同一稳定块；从编辑回预览时尽量定位到当前块所在段落。

### 4.3 编辑模式

延续自由画布；用户可以自由摆放、关联章节和插入任意模块。

块头样式：
- 视觉高度建议 18–20px，控制图标约 12px，辅助文字约 10–11px。
- 手柄、菜单等实际命中区域保持约 24px，焦点态清楚可见。
- 普通文本块默认省略“内容块”字样；仅悬浮／选中时显示短工具条。
- 章节块显示 H2／H3、折叠入口和更多菜单；真正章节标题保留在正文中编辑。
- 选中时才突出边框和尺寸手柄；无操作时让内容成为视觉主体。
- 工具条位置固定，不因出现消失推动正文。

原位编辑：
- 编辑状态下，单击正文即出现光标；双击选择词语，符合 PC 编辑习惯。
- 标题、段落、列表、表格在原块内修改，格式工具在选区附近或当前工具行出现。
- 正文选字、拖选和输入不触发画布移动；块只通过顶部手柄／边框拖动，画布空白左键平移。
- 右侧仅承载用途、标签、颜色、模块参数等属性，不再承载普通文本正文。
- 同时只挂载一个活动富文本编辑器；输入期间不销毁重建 DOM，保证中文组合输入和光标稳定。
- 失焦／切换块将修改留在当前文档草稿；不出现每写一句就要点击的“完成编辑”按钮。
- Esc 退出文本编辑态但不丢弃已输入文字；Ctrl+Z 撤销本次操作，Ctrl+S 保存文档。
- 长文本随内容增高，减少块内滚动；用户手动限定高度时才出现内部滚动。
- 标题、结构模块和普通文本块使用同一保存与撤销体系；稳定 ID 不因每次键入重新生成。

### 4.4 预览中的“调整顺序”（已确认）

- 默认预览没有拖拽控件；用户点击“调整顺序”后，临时显示段落／章节拖动手柄和插入线。
- 拖动普通内容块调整阅读位置；拖动章节默认携带所属子章节和内容。
- 排序更新同一份文档草稿的源顺序，不重置自由画布坐标。
- 归属变更仍遵守明确落点规则：仅上下插入线表示排序；标题归入区和解除关联区明确标示不同结果。
- 未归属块可以放在章节之间。松手前显示目标位置和归属结果，避免把排序误当归属变更。
- 操作可撤销；退出“调整顺序”仅收起控件，不自动保存文件；历史只读版本不提供此操作。
- 该状态属于预览内的短时结构整理，不引入第三套正文编辑器，也不重新增加常驻大纲侧栏。

## 五、拖拽与章节归属

### 5.1 三种关系分别定义

| 用户操作 | 修改内容 | 预览影响 |
| --- | --- | --- |
| 空白处重新摆放块 | 画布坐标 | 不改变正文顺序 |
| 拖到章节“归入”区域 | 块的章节归属及相应阅读顺序 | 进入该章节 |
| 拖到阅读顺序插入线 | 文档源顺序 | 在指定段落前／后出现 |

只有明确目标区高亮后松手才改变结构。划过标题、重叠其他块或拖离原位置不自动改变归属。

### 5.2 关联

1. 从手柄提起块。
2. 接近可接收的标题时显示淡色章节范围和“归入《章节名》”提示。
3. 同时提供首部／末尾及现有内容之间的插入线，默认追加章节末尾。
4. 松手完成一次可撤销操作，原坐标、归属和正文顺序一起记录。
5. 关联后，章节折叠收起所属内容；移动标题手柄默认带同一章节全部子块，可通过菜单选择仅调整标题外观位置。

### 5.3 解除

- 拖动时提供明确“文档直属内容”目标区；拖入后解除当前章节归属。
- 右键提供“移到上一级章节”“移到文档直属内容”，与拖动执行同一操作。
- 直属内容可自由放在章节前后或章节之间，不强制集中到前言区。解除归属时默认保留当前阅读位置；用户在预览的“调整顺序”状态中决定最终位置。
- 拖到另一个章节即转移；不要求先解除再重新关联。
- 标题移动携带完整子树；禁止移入自身／后代，超出标题级别范围时明确说明。
- 删除标题默认保留正文并提升一级；“删除整个章节及内容”作为单独危险命令并确认范围。
- 分类／文档树中的父子关系与文档内部章节关系分别保存，互不代替。

### 5.4 工程原则

Markdown 源顺序是标准预览的阅读顺序。为支持直属内容穿插在章节之间，块归属需要在公开文档中显式表达：扩展既有稳定块标记，明确父章节身份或文档直属身份；无显式标记的旧文档继续按标题推断。具体标记格式在实现时统一定义，并纳入 LLM 上下文说明。画布伴随文件只记录坐标、尺寸和视觉组合，不能成为第二套章节或阅读顺序来源。当前 LayoutCompanion 中的 section 需要消除与公开归属的歧义。已有布局只在用户执行结构调整时更新，不批量猜测归属。

对段落的拆分、合并、标题级别变更和多块拖动维护稳定身份；引用失效时给出重新定位入口，不静默指向相邻段落。文本拆分后的身份继承规则需要在实现前固定并覆盖验收。

## 六、策问模式：核心作答流程

### 6.1 页面布局

    [策问 ●3]  项目库  文件  编辑  视图 …                项目名／连接状态
    ← 返回文档  《战斗设计》   第3轮：资源取舍              已填写2／共5题
    ┌ 本轮问题 ───────┬ 当前问题 ───────────────────┬ 原文依据（按需）┐
    │ ✓ 1 战斗目标   │ 第3题：失败后如何处理资源？   │ 对应章节及摘录 │
    │ ✓ 2 奖励来源   │ 提问背景／需要你决定的内容   │ 发题时的版本   │
    │ → 3 失败代价   │ ○ A 保留全部                 │ 当前是否变化   │
    │ · 4 回收条件   │ ○ B 损失一部分               │                │
    │ ◷ 5 暂缓事项   │ ○ C 全部失去                 │                │
    │                │ 自定义回答／补充理由         │                │
    │ 查看此前轮次   │ 上一题   暂缓   下一题       │                │
    └────────────────┴─────────────────────────────┴────────────────┘

本轮问题目录复用左侧区域，提供切回“项目文档”的入口；不在原侧栏旁新增第二根侧栏。原文依据抽屉按需展开。中央默认一题一屏，另提供“查看本轮全部”总览。

### 6.2 当前文档与当前轮次

- 默认采用用户正在处理的轮次，优先恢复未提交草稿；没有进行中轮次时再提示最近待答轮次。
- 范围来自问题的文档目标、块锚点或文内模块身份；项目中无关问题不自动混入本页。
- 跨多份文档的问题只计一次，展示所有相关文档。
- 同一文档有并行轮次时明确列出轮次目标、时间和待答数；不把不同 LLM 任务合并成一轮。
- LLM 新增题目只提示“新增 N 题”，不跳走当前题、不清空选择。
- 题目始终显示来源文档／章节、轮次、提问背景；技术身份放入详情。

### 6.3 单题回答

每题包含：题目、背景、决策点、选项、自定义回答、必要的来源入口。

- 单选、多选、纯文字均支持；选项默认不选中。
- 选择某项后仍允许添加理由、边界和反例；支持不选预设选项直接回答。
- “暂缓”和“前提不成立”作为明确命令；后者允许写明修正后的前提。
- LLM 推荐可以标识推荐理由，不代替选择、不改变焦点、不抢主按钮。
- 下一题仅保存本地草稿并前进；不暗中提交、不自动调用 LLM。
- 左侧状态分为未填写、已填写草稿、暂缓、已提交、需要复核；“已填写”与“已提交”有明确区别。
- 问题前提依赖前题时，可以依据本轮草稿预显后续题；提交时按本批依赖顺序再次校验。
- 前题改答导致条件失效，保留后题原答并标为“需复核”，不删除。
- 题目选项改变或引用依据变化时，保留草稿和旧题对照；用户复核后才提交。

### 6.4 本轮总结与提交

末题之后显示本轮汇总：
- 每题所选项与自定义原话；
- 未答／暂缓／前提不成立项；
- 需要复核的题目和变化依据；
- 可一键返回具体题目修改。

主动作“提交已填写回答”，明确显示提交数量：
- 允许部分提交，未答题留在本轮；
- 不以“下一题”或离开页面代替提交；
- 服务按稳定问题身份和发题／回答基准核对，重复提交同一请求不新增重复回答；
- 已提交后改答追加新版本，关联被替代的回答；历史原话保留。

示例内的回答继续仅保留在示例会话。若用户希望正式保存并交给外部模型处理，进入项目另存流程。

## 七、多轮迭代闭环

    用户选择文档与迭代目标
      → LLM 阅读指定版本并发布本轮问题
      → 用户逐题填写／本轮汇总
      → 提交用户原始回答
      → 策问生成“分析本轮回答”的开场白
      → 用户复制到已连接策问 MCP 的 LLM 对话
      → LLM 读取本轮原始回答，分析整理，按需提交候选修改
      → LLM 说明下一轮建议目标，询问用户是否继续，然后等待
      → 用户明确同意后，LLM 才发布下一轮问题
      → 策问提示新一轮到达，用户进入作答

修改提案是其中独立的审核分支：用户可以先核对差异并采纳、部分采纳或退回，再决定继续讨论；也可以先继续澄清。开始下一轮不等于采纳提案，采纳提案也不等于开始下一轮。

### 7.1 三份记录

1. 用户原始回答：只有用户提交的内容能写入此区域。
2. LLM 理解／设计建议：明确显示来源，可以被用户纠正。
3. 正式文档修改：以差异提案展示，由用户决定全部、部分或不采纳。

题目和回答有了记录，不等于设计已经定案；某题只有部分内容落实时保留部分落实状态。没有文档修改的讨论也可由用户显式结束，并记录原因。

### 7.2 提交后体验

- 提交成功后，在本轮汇总位置显示完成卡片，不跳去通用协作任务选择器，不自动关闭当前文档。
- 主按钮为“复制给 LLM 的开场白”；次操作为“预览／编辑开场白”“返回文档”。开场白目的固定为分析本次已提交回答。
- 开场白自动带入项目、文档范围、轮次、问题身份、本次提交对应的回答身份及提交修订；用户不需要填写 ID 或路径。
- 部分提交显示“已提交 3／5 题，另有 2 题未提交”等真实状态，仍可交给模型分析；这不将未答题标记完成，也不结束整个轮次。
- 未连接时显示“回答已保存，可复制开场白到连接策问 MCP 的 LLM 对话”；已检测到连接时显示“检测到 MCP 连接，请在目标对话发送开场白”。开场白仍要求核对当前对话的实际工具能力。
- 复制成功只显示“已复制，请发送给你的 LLM”；取消复制、复制失败或关闭卡片不撤销已经提交的回答，稍后可从本轮汇总重新打开。
- 不把复制开场白写成模型接收成功，不把心跳在线写成正在推理；现有 MCP 不负责向外部聊天窗口发送消息或唤醒模型。
- 分析后的继续确认默认发生在用户粘贴开场白的 LLM 对话中。LLM 提供“开始下一轮／先修正本轮理解／暂时结束”三个明确方向，并等待用户实际答复，不替用户选择。
- 用户同意前不创建下一轮问题文件、不调用发题工具。收到已发布的下一轮后，软件显示来源、轮次目标和题数，再由用户进入作答；不跳走正在编辑的内容。
- 收到提案时展示修改依据、对应问题／回答、影响的文档及差异。模型不能批准自己的提案。
- 上游文档已变化时，先比较新旧基础，保留冲突双方；不覆盖本地草稿。
- 当前文档有未保存编辑时，明确说明 MCP 读取已保存版本；允许用户先保存后重新生成开场白，不静默把私有草稿交给外部模型。
- 切换文档、项目库或视图不丢失问答进度。

完成卡片示意（复用中央汇总区域，不增加顶部工具行）：

    本轮回答已提交                         已提交 3／5 题
    将本轮回答交给 LLM 分析整理；另有 2 题尚未提交。
    [复制给 LLM 的开场白]  [预览／编辑]  [返回文档]
    LLM 会先整理理解，再询问你是否开始下一轮。

### 7.3 状态展示

应用可直接核实的状态使用简短中文：
待回答 → 作答中 → 已提交／可交给 LLM → 已复制开场白 → 收到提案或下一轮。

模型是否正在分析、是否已在外部对话提出继续确认，在当前协议没有回执时不能显示为已核实状态。流程说明可以提示“请查看 LLM 的整理并确认是否继续”。题目内部保留现有 open／answered／partially-decided／decided 语义；本地填写进度是草稿状态，不冒充服务确认。

### 7.5 开场白示例

以下方括号内容由软件从提交成功结果自动填充，普通用户只需核对文字并复制。没有 Quest 的轮次省略 Quest 字段；旧数据没有稳定轮次 ID 时，用原轮次名称和确切问题 ID 列表限定范围，不伪造身份。

```text
我已在策问提交本轮回答，请通过当前对话已连接的策问 MCP 读取并分析整理。
这次先处理本轮回答，整理后请询问我是否开始下一轮，并等待我明确回复。

项目：[项目名称与 projectId]
相关文档：[文档标题与 documentId 列表]
本轮：[轮次名称、已有 roundId；如有 Quest 则列出 questId]
本次提交：[requestId、成功后的 revision]
本次已提交回答：[questionId → answerId、提交后问题文档 hash]
本轮其余状态：[已提交但本次未改答／未答／暂缓／前提不成立／需要复核]

请按以下步骤处理：
1. 核对当前对话确实提供策问 MCP 工具。用 cewen_status 核对项目与当前修订，
   用 cewen_context 或 cewen_read_document 读取上述问题的用户原始回答及相关文档；
   有实际 Quest 时可先用 cewen_quest_read 核对轮次，再补读必要文档。
   若无法读取，说明实际错误并停止，不假装已读，不要求访问编辑器私有草稿。
2. 以本次提交为分析起点。若之后已经改答或文档发生变化，明确列出差异，
   以经核对的最新内容为准；影响结论且无法判断时先询问我，不混用版本。
3. 按“用户明确表达的内容／你的理解与推断／建议修改／待澄清事项”整理结果，
   逐项关联问题或回答。保留我的条件与理由，不替我补答，不把建议写成决定。
   未答、暂缓、前提不成立分别说明，不按默认选项处理，也不要求我重复回答已明确的问题。
4. 有充分依据的文档修改，可以用 cewen_propose 提交可审核的候选修改，
   保留原始回答，带上实际修订、来源问题和依赖哈希。正式采纳由我在策问中决定；
   不自行批准、直接覆盖正式文档或改写历史。分析未产生修改时，不必为凑流程创建提案。
5. 最后说明是否建议再开一轮、建议目标及少量关键议题，并询问我：
   “开始下一轮、先修正本轮理解，还是暂时结束？”然后停止并等待我的答复。
   我没有明确同意前，不调用 cewen_publish_questions 或 cewen_quest_round，
   也不通过其他写入方式创建下一轮问题。
6. 仅当我明确同意开始下一轮后，重新核对相关修订，发布一轮围绕已确认目标的必要问题，
   关联原问题与文档，保留自由回答、暂缓和否定前提的空间，再告知我回策问作答。
   每次我提交下一轮回答后，仍按“读取—分析整理—确认是否继续”的顺序处理。
```

“先修正本轮理解”表示继续讨论和纠正解释，不立即发新题；“暂时结束”保留当前回答及未采纳提案，不删除未决事项。用户答复含糊时继续澄清，不将沉默、复制动作或关闭页面解释为继续授权。

### 7.6 实施时的上下文与接入约束

- 复用现有 `answers` 场景，增加结构化的本轮范围和提交结果；不只把一段自由文字塞入通用开场白。
- 提交回执或从成功快照解析出的结果应能定位 requestId、提交修订、确切问题与回答身份、问题哈希及轮次范围；不能从“当前屏幕最后一题”猜本次提交范围。
- 分开显示本轮已提交记录、本次新增／改答、尚未提交的本地草稿；后者只显示未提交状态，不加入外发开场白。
- 开场白重开或重新生成时核对修订；保留用户手动编辑的提示词，刷新上下文必须明确提示，不能静默覆盖。
- 固定目的入口复用现有预览编辑组件；普通文档问题使用普通 MCP 发题能力，有 Quest 的问题沿用 Quest 能力，不双重发布同一轮。
- MCP 提示模板、工具描述、随软件交付的协作 Skill 和新手说明使用同一约定，避免一个入口要求等待、另一个入口要求自动续轮。
- 当前服务的哈希冲突、幂等请求、原始回答保护和用户采纳机制继续保留；此流程不新增模型代答或自动批准工具。

## 十、验收清单

- 老项目首次打开是标准文档预览，切换编辑后保留原画布布局；视图切换不自动保存。
- 新建文档直接进入原位编辑；中文输入法组合过程中不丢字、不跳光标。
- 不展开右栏也能完成标题、段落、列表、表格修改。
- 正文选字与画布左键平移互不干扰；手柄可拖且视觉细小。
- 仅移动坐标不改变预览顺序；明确落点才关联／解除；直属内容可在章节间穿插，公开归属标记与预览一致。
- 预览开启“调整顺序”可拖动段落和完整章节，退出后无块头；排序不改画布位置，切换状态不自动保存。
- 标题移动携带子树，禁止循环，撤销恢复结构与位置；稳定引用不漂移。
- 预览不显示块头或网格，标题不重复，图片、表格、地图和媒体排版正常。
- 项目库返回恢复当前标签、未保存内容、画布视角、模式和问答进度；示例不创建项目文件。
- 点击策问立即定位本页本轮；无问题、不选文档、未开项目均有清晰入口。
- 每题可选项或自由回答，推荐不预选；下一题只保留草稿。
- 条件问题遇前题改答保留旧答并要求复核；题目改变不覆盖草稿。
- 部分提交、幂等重试、改答追加、并行轮次、跨文档问题计数均符合定义。
- 提交回答、交付模型、接收提案、用户采纳四个状态清楚分开。
- 提交成功后提供可编辑、可复制的本轮分析开场白，项目、文档、轮次、问题、回答与成功修订准确，不混入其他轮次或私人草稿。

- LLM 先分析本轮回答，再询问并等待是否开始下一轮；未同意不发题，修正理解和暂时结束均不自动创建下一轮。
