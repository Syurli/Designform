## 1. 产品方向与本次结论

策问的核心是**项目中的一份份通用文档**。文档默认采用自由画布，用户通过模块组合表达内容，通过分类、引用和问策推进创作。

下一版最需要解决的是三个问题：

1. 用户从官方或自定义基础文档预设创建“角色卡、地图卡、道具卡”等普通文档，也能自己编辑、创建和管理新预设。
2. 用户能从固定的项目文档树找到、打开、移动和引用资料，不用理解当前不同面板的底层分类。
3. 所有操作遵循统一桌面规则：对象选择、右键菜单、快捷键、属性面板、保存和取消具有稳定含义。

现有实现已具备 Markdown、稳定身份、模块、布局伴随文件、版本和引用基础。保留这些能力，重整用户进入和操作它们的方式。

### 工程核对结论

| 已核实的现状 | 使用上的问题 | V2 决策 |
| --- | --- | --- |
| 卡片库把分类、文档、章节节点都画成卡片；另有角色卡等模块 | “卡片”同时指资料、模块和展示方式 | 明确文档用途、文内模块、卡片视图、引用卡的关系 |
| 左侧是分类页与文档页，两种层级路径并存 | 筛选、进入子分类和进入子文档容易混淆 | 统一成项目文档树，筛选单独呈现 |
| 单击目录文档选择条目，双击标题改名 | 找到文档后仍需寻找编辑入口，双击容易误改名 | 单击打开；双击固定标签页；F2 改名 |
| 改分类会清除原父文档关系，子文档还会继承父级分类 | 一次属性修改可能改变用户未预期的结构 | 将其显式命名为“移动到”，展示目标位置和受影响后代 |
| 部分问策、媒体和制作记录写成 guide，普通目录过滤 guide | 资料散落在不同入口，统一文档体验不完整 | 内容按用途可见，系统伴随文件按职责隐藏，不用 guide 一刀切 |
| 文档菜单挂在有滚动裁剪的列表行内 | 菜单靠近边缘时受裁切 | 统一顶层浮层与视口定位 |
| 常态写作使用模态 dialog，模块又有各自面板 | 编辑、导航与参考难以连续进行 | 固定主工作区、文档标签页、跟随选择的属性区 |

以上是代码及已提供截图支持的判断。菜单出现频率、Windows 缩放和输入法行为尚未做本轮运行验证。

## 2. 基础文档预设：官方提供起点，用户自由创建

### 2.1 统一“卡”与预设的含义

**角色卡、地图卡、道具卡，以及其他“xx卡”，都是基础文档预设。官方提供常用起点，用户使用相同能力创建、编辑和保存自己的预设。**

选择某个预设后，创建的是一份普通基础文档。预设配置其初始模块、字段和排版；创建后用户可以自由增删内容。

| 用户看到的内容 | 实际含义 | 操作入口 |
| --- | --- | --- |
| 预设库中的角色卡、地图卡、道具卡 | 官方提供或用户自建的基础文档预设 | 选择创建文档，或进入预设编辑 |
| 从角色卡创建的“阿灯” | 一份独立的普通画布文档 | 打开文档，自由编辑 |
| 文字、字段组、图片、地图、对白等 | 文档中的可组合模块 | 文内插入和编辑 |
| 卡片视图 | 同一批文档的封面与摘要展示方式 | 打开相同源文档 |
| 文内引用卡 | 指向现有文档或模块的引用 | 定位原文，或查看引用预览 |

产品中的预设分为两个层次：

- **项目预设**：用于新建项目，提供初始分类、若干文档及它们的起步组合。
- **基础文档预设**：用于新建一份文档，提供模块组合、字段、默认内容、画布布局和阅读顺序。界面简称“文档预设”。

示例继续承担教学任务。项目预设和文档预设用于开始工作，两者都不限制后续能力。

新增“武器卡”“谜题卡”或用户自己命名的预设，只需编辑预设内容，不需要增加专用工作区或注册新的文档类型。地图卡是包含地图模块及说明、图例、引用占位等内容的文档预设；用户仍可在任何文档直接插入地图模块。

底层保留文档 ID 和模块 ID。一份文档可以包含多个角色、地图或对白块；引用整份文档与引用其中具体模块都成立，引用卡清楚显示目标范围。

### 2.2 创建入口与常用预设

左侧“＋新建”和目录空白右键共用以下入口：

- 空白文档；
- 从文档预设创建…；
- 最近使用或用户置顶的少量预设快捷项；
- 管理文档预设…。

快捷项来自预设库，不在菜单中写死所有“xx卡”。新建预设后即可搜索和置顶，不需要升级软件。

文档预设选择器提供“官方预设 / 我的预设”、名称搜索、用途标签和组成说明。初始没有预设被自动采用；用户主动点击某个预设快捷项，等同于明确选择该预设。

官方首批可提供：

| 预设 | 建议起步组合 |
| --- | --- |
| 角色卡 | 标题、简介、图片、可选资料字段、关系引用占位 |
| 地图卡 | 地图模块、空间说明、图例、地点引用占位 |
| 道具卡 | 名称、图片、用途与规则说明、可选属性、关联引用 |
| 地点资料 | 空间描述、参考图、地图引用占位 |
| 场次文档 | 场次目标、发生地点、角色引用、正文与对白 |
| 规则说明 | 目标体验、规则正文、示意图、待讨论问题 |

这张表是预设编辑的起点。用户可以改名、删除全部预置字段，或加入任何其他模块。

创建的文档默认进入当前选中的分类，未选中时放入“未分类”；预设不强制创建一串分类，也不改变当前项目结构。

单角色预设中，角色称呼可默认关联文档标题；用户可以解除关联。一份文档包含多个角色时，各字段组有自己的称呼与稳定 ID，修改文档标题不批量改名。

“地点资料”描述空间，“场次文档”描述某时某地发生的内容。用户可以把自己的预设命名为“场景卡”，并通过描述说明它的用途。

### 2.3 用户创建、编辑和管理预设

提供三条创建路径：

1. **从空白创建预设**：在预设管理器选择“新建预设”，用同一套文档画布插入模块、安排字段和布局，保存到“我的预设”。
2. **基于已有预设修改**：选中官方或自定义预设，进入预设编辑。官方预设的修改保存为用户版本，保留官方原始项；自定义预设可以更新原项或另存为新预设。
3. **把当前文档另存为预设**：在文档菜单或右键中选择“另存为文档预设…”，选择保留范围，填写名称后保存。

预设编辑沿用普通文档画布，明确标注“正在编辑文档预设”，主保存按钮显示“保存预设”。编辑当前文档只改变当前资料；编辑预设改变后续创建时使用的起点。预设编辑工作稿不登记为普通项目或目录文档。

一个预设可保存：

- 名称、说明、封面、可选用途和预设检索标签；
- 模块组合、字段名称及可选默认值；
- 初始文字或提示占位；
- 画布布局、分组、图层和阅读顺序；
- 明确纳入的素材和引用占位。

“我的预设”支持新建、编辑、复制、重命名、删除和置顶。默认存入本机预设库，供不同项目复用；用户个人内容不自动加入公开发行包。

官方预设与我的预设具有清楚的来源标记。软件升级不覆盖用户版本；用户可以重新采用官方预设。修改或删除任何预设，都不改写已经创建的文档。

用户要将新预设用于既有文档时，明确选择“插入预设内容…”，先查看将新增的模块，再插入当前画布；不因修改用途标签自动重排或覆盖正文。

### 2.4 从文档保存预设的边界

默认保存模块结构、字段、布局与空占位。当前正文、字段值、图片、音频等实例内容按范围列出，由用户选择是否保留，避免把一次创作中的人物和素材带入所有后续文档。

文档用途标签与预设来源分开：用途用于检索，预设来源用于了解创建起点。两者都可调整，不形成强制绑定。

每次使用预设：

- 生成新的文档、模块和块身份；
- 重新连接预设内部的引用；
- 外部项目引用默认成为待选择的占位，显示需要用户指定的目标；
- 需要素材时只使用明确打包的素材或占位，不偷偷链接源项目的绝对路径；
- 排除源项目凭证、历史、缓存和恢复草稿。

从地图卡创建的新地图文档拥有独立身份；希望多个文档共用已有地图时，通过引用选择原地图，局部覆盖层仍各自独立。

在示例中可以临时组合和试用预设，数据保持在当前会话。发起“保存预设”等持久化操作时，沿用先另存为正式项目的规则；取消时不写工程目录，也不写本机预设库。

### 2.5 在其他文档中使用这些资料


场次文档中输入角色名或选择“插入已有资料”，搜索结果显示标题、用途、分类路径和摘要。

用户有三种明确动作：

| 动作 | 表现与后续关系 |
| --- | --- |
| 插入链接引用 | 显示标题链接，点击定位原文 |
| 插入引用预览 | 在当前画布展示原文或选定模块，随源内容更新 |
| 复制为独立内容 | 创建新的内容身份，之后独立修改 |

从目录把文档拖到画布，默认插入引用预览，并显示来源标记。引用预览默认只读，选择“打开源文档”再编辑；避免在场次里改一行文字，却不知道改动了共享角色资料。

删除引用只移除当前引用。删除源文档时显示哪些文档正在使用它，并保留可识别的缺失引用状态。

例如，同一角色可以被十个场次引用。改角色文档的标题或肖像后，十处引用都指向原来的身份；无需逐一维护副本。

## 3. 项目文档栏：一棵树，加上简单筛选

### 3.1 默认结构

左栏改名为“项目文档”，从上到下：

1. 搜索框与“＋新建”。
2. 快速访问：最近、收藏。
3. 可展开的分类与文档树。
4. 按需展开的用途、标签筛选。
5. 可选的已保存集合入口。

分类使用文件夹式图标，文档使用文档图标；模块和章节不作为普通文档重复出现在主树中。当前文档的章节放入“大纲”，知识空间可按需展开模块层次。

现有子文档可以继续作为树的子级保留。章节、子文档和子分类的图标与名称必须区分。

启动项目库继续采用分页。进入项目后的文档树允许纵向滚动，保持路径、展开状态和当前位置；不再把窄侧栏分成两套分页浏览器。

### 3.2 分类、用途、标签与集合的职责

| 项目 | 回答的问题 | 规则 |
| --- | --- | --- |
| 分类 | 这份文档主要放在哪里？ | 一个主要归属，可有层级；映射现有公开分类，不额外创建一套同名文件夹系统 |
| 用途 | 这份文档用来做什么？ | 可选的角色、地点、场次、规则等标记；可自定义，不限制模块 |
| 标签 | 还能从哪些角度找到它？ | 多值，例如“夜间”“支线”“需要配图” |
| 集合 | 这次想一起查看哪些资料？ | 保存引用清单或筛选条件，不复制文档、不改变主分类 |

默认只需要理解分类和文档。用途可随文档预设带入，标签和集合按需使用，不要求新建时同时填写四套信息。

收藏、最近、界面展开和窗口布局属于本机偏好；公开分类、用途和作者明确写入的标签随项目保存。下一版集合可先复用私人工作分组，不额外引入协作权限体系。

文档状态独立表示“草稿、待确认、已确认、归档”，不再建议用同名标签重复维护状态。

### 3.3 点击、选择和移动

| 操作 | 结果 |
| --- | --- |
| 点击分类箭头 | 原位展开或折叠 |
| 点击分类名称 | 选择分类，在中央显示该分类的文档概览 |
| 单击文档 | 在中央打开可编辑临时标签页 |
| 双击文档 | 固定为标签页 |
| 开始编辑临时标签页 | 自动固定，后续浏览不替换它 |
| F2 或右键“重命名” | 原位编辑名称；Enter 确认，Esc 取消 |
| Ctrl / Shift 点击 | 多选或连续选择，不自动切换文档 |
| 右键已选中的多项 | 保留多选，显示批量操作 |
| 右键未选中的文档 | 将操作目标切到该文档，保留当前编辑页 |
| 拖入分类 | 显示“移动到：完整路径”，确认落点后改变归属 |
| 拖到文档上 | 显示“成为子文档”，明确继承规则；不能悄悄当成插入引用 |

在分类筛选或搜索结果中，始终显示当前位置，并提供“在目录中定位”。筛选生效时显示条件和“清除”，避免用户以为资料消失。

主目录的数字只统计文档；章节和模块数量在各自视图中明确标注。删除分类提供“保留文档并移出”，不连带删除正文。

用户修改分类时，界面表现为“移动到”。移入另一文档时成为子文档并继承目标的主要分类；移入分类时解除原父文档，携带整个子树。两种操作都保持用途、标签和引用不变。界面展示整个子树的影响，用户也可先将当前文档移出父文档。不得静默断开层级。

### 3.4 分类栏不承担正文编辑

改名使用原位输入；颜色、用途、标签、别名及引用在属性侧栏编辑。

当前栏内展开大表单会挤走其他目录项，应移到属性侧栏。仅保留轻量的原位重命名和新建输入。

## 4. 主工作台采用稳定的桌面布局

以下为供评审的区域布局，具体像素值是后续原型起点。

| 位置 | 建议布局 | 主要内容 |
| --- | --- | --- |
| 最上方 | 约 32—36 px 标题栏 | 项目名、保存状态、窗口操作 |
| 菜单栏 | 约 28—32 px | 文件、编辑、视图、文档、插入、帮助 |
| 左侧 | 初始约 260 px，可拖动调整 | 项目文档、搜索、分类树、快速访问 |
| 中央上方 | 标签页与轻量工具栏 | 当前文档、插入、撤销、定位、问策 |
| 中央主体 | 剩余空间 | 自由画布或当前文档的阅读视图 |
| 右侧 | 初始约 300 px，可收起 | 文档 / 模块属性、引用来源、大纲 |
| 底部 | 约 24 px 状态栏 | 保存状态、示例状态、缩放和当前工具提示 |

布局以 1280×800 等常见可用窗口开始验证，并覆盖更小窗口与 Windows 缩放。空间不足时先收起非必要侧栏，不把主操作挤成多排按钮。

保留现有色彩和整体视觉语言，减少页面式大标题、大说明卡和重复边框。导航行、菜单行、属性字段采用统一密度；选中、悬浮、键盘焦点和只读状态分别可辨认。

### 文档编辑保持在主区

文档在中央直接编辑。标签页显示未保存标记、只读历史标记；切换文档不重置画布位置和未保存内容。

复杂模块允许进入聚焦模式，保留所属文档面包屑与“返回文档”；普通文字编辑、分类整理不遮住整个工作台。

文档标签页属于下一版基础能力。多窗和任意拆分停靠可以后续扩展；本轮先保证稳定标签页与可收起参考区。

### 左上菜单建议

- 文件：返回项目库、新建项目、打开项目、保存当前文档、保存全部、项目另存为、导出、备份、关闭项目。
- 编辑：撤销、重做、剪切、复制、粘贴、删除、查找。
- 视图：项目文档、属性、大纲、知识空间、缩放、恢复布局。
- 文档：新建文档、从文档预设创建、另存为文档预设、管理文档预设、重命名、移动到、用途与标签、历史。
- 插入：文字、图片、音视频、表格、对白、地图、引用、分镜、时间序列。
- 帮助：教程与示例、快捷键、关于。

频繁操作继续放在工具栏；菜单容纳完整命令。关于显示实际版本、作者、仓库、网页和源码基准。

原有“创作模块、Quest、排演”三个顶级页撤销，能力分别进入文内插入、问策和播放预览。“卡片库”改称“卡片视图”，用于展示当前目录或搜索结果。

## 5. 菜单、属性面板与对话框各司其职

右键菜单适合针对对象执行命令，同时保留可见的“⋯”入口和键盘入口。Windows 的菜单设计同时包含按钮菜单和上下文菜单，二者可以共享命令。[Microsoft 菜单与上下文菜单](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/menus-and-context-menus)

| 容器 | 适合的操作 | 不宜放入 |
| --- | --- | --- |
| 右键 / ⋯ 命令菜单 | 打开、改名、移动、复制引用、删除、属性 | 长表单、完整分类管理器 |
| 小型选择浮层 | 选颜色、选择值、搜索已有资料 | 多步骤新建流程 |
| 右侧属性面板 | 持续编辑分类、用途、标签、模块参数 | 阻断式全屏确认 |
| 模态对话框 | 另存为路径、删除二次确认、冲突处理 | 日常文档写作、项目目录浏览 |
| 状态栏 / 轻提示 | 保存完成、移动完成、可撤销提示 | 必须处理但一闪而过的错误 |

### 文档右键菜单示例

第一组：打开、在新标签页打开、在目录中定位。
第二组：重命名、移动到、添加收藏、复制文档链接、插入到当前画布。
第三组：独立复制、另存为文档预设、导出、查看历史。
最后一组：属性、删除文档。

实际仅显示当前对象适用的命令。历史只读时保留查看、引用和另存为，编辑命令禁用并给出原因。

分类菜单提供新建文档、新建子分类、改名、调整位置、分类属性、移除分类。模块菜单提供复制、复制引用、排列、分组、锁定、属性、删除。

“删除文档”“移除引用”“删除分类”“删除本地项目”必须使用不同名称。项目删除仍执行前版要求的二次确认。

### 菜单行为必须一致

- 右键、⋯、菜单栏和快捷键调用相同命令，名称、可用状态和效果一致。
- 菜单在触发对象附近出现，四边留出空间，自动向上或向左调整。
- 菜单打开不挤动布局；关闭不重排目录。
- 点击菜单外关闭；Esc 关闭当前层并将焦点交回触发对象。
- 方向键在菜单中移动，Enter 执行；Shift+F10 或菜单键打开当前对象菜单。
- 菜单打开期间，删除键、空格等不能穿透到背后的画布。
- 需要继续填写的命令使用省略号，例如“项目另存为…”。
- 菜单层级尽量不超过两层；复杂选择使用可搜索选择器。

键盘与焦点行为参考 WAI-ARIA 的应用菜单规范；仅添加 menu 属性并不足以完成交互。[W3C 菜单模式](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)

### 浮层遮挡必须从公共组件解决

当前目录菜单插在滚动列表行内部；写作菜单还存在局部堆叠上下文。下一版将菜单脱离可裁剪的目录和画布内容区，使用统一浮层承载。

可优先评估浏览器顶层 popover / dialog 的统一封装；popover 顶层显示不受祖先 overflow 裁剪，但仍需要自行完成视口定位和键盘行为。[MDN popover](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/popover)

工程要求：

- 明确当前活动对话框和弹出层的归属，处理 dialog 的顶层顺序与焦点限制。
- 弹窗内的菜单仍保持在该弹窗的交互范围，不仅是追加到 body 并提高 z-index。
- 窗口改变尺寸、所在容器滚动、切换文档或项目时，关闭或重新定位菜单。
- 嵌套菜单跟随触发项，防止鼠标跨越时意外关闭。
- 长菜单可以内部滚动，但不能超出窗口而无法操作。
- 桌面版与网页版共用命令和交互规则，选择合适的浮层适配方式。

## 6. 鼠标、键盘与选择规则

### 6.1 画布手势

| 场景 | 左键 | 右键 |
| --- | --- | --- |
| 二维空白画布 | 拖动平移 | 单击菜单；拖动框选 |
| 三维知识空间 | 拖动平移 | 单击菜单；拖动旋转 |
| 模块把手 | 拖动模块 | 对象菜单；拖动不误触背景菜单 |
| 可编辑文字 | 光标、选词、拖选 | 文字编辑菜单 |
| 模块内小画布 | 聚焦后处理内部操作 | 沿用对应二维或三维规则 |

右键按下先记录位置，移动超过约 6 个逻辑像素才进入拖动；完成拖动不弹菜单。阈值在高 DPI 下验证。二维框选、三维旋转从画布背景发起；模块把手上右键单击打开对象菜单，超过阈值则取消这次菜单意图，不移动模块，也不意外启动背景手势。

三维框选提供明确工具，不将右键同时解释为旋转和框选。绘制、连线等显式工具在工具栏显示当前状态；退出工具恢复导航手势。

单次手势只由一层接管。嵌套地图、外层文档和知识空间不得一起移动。Esc 取消当前手势；失焦或指针取消时按同样规则处理。

滚轮在画布空白处缩放，在长文本编辑区滚动内容。提供回到内容、缩放比例和放大缩小按钮，避免只能依赖手势。

### 6.2 快捷键与焦点

| 命令 | 建议键位 / 规则 |
| --- | --- |
| 新建文档 | Ctrl+N，有活动项目时使用 |
| 新建项目 | Ctrl+Shift+N |
| 打开项目 | Ctrl+O |
| 保存当前文档 | Ctrl+S |
| 项目另存为 | Ctrl+Shift+S |
| 查找当前文档 | Ctrl+F |
| 搜索项目资料 | Ctrl+Shift+F |
| 插入引用 | Ctrl+K |
| 重命名当前目录对象 | F2 |
| 当前对象菜单 | Shift+F10 / 菜单键 |
| 撤销 / 重做 | Ctrl+Z / Ctrl+Y，遵循当前编辑范围 |

这些是拟议默认键位，实施时检查桌面壳和浏览器保留快捷键冲突，并在菜单中显示实际可用键位。

处理优先级：输入法组合和文字编辑 → 当前模块 → 当前画布 / 目录 → 项目命令。

输入文字时 Delete 删除文字，Ctrl+A 选中文字，不能删除或选中背后的文档。输入法组合期间不抢走 Enter、Esc 或方向键。

一次 Esc 只处理当前最上层动作；菜单关闭后不能继续触发关闭文档。面板、菜单和对话框关闭后恢复合理焦点。

## 7. 文档画布、阅读和关系保持同源

每份文档默认是自由画布，至少提供平移、缩放、定位、多选、对齐、基础吸附、图层、内容组、长文本和媒体编辑、撤销、阅读顺序。

三个关系保持独立：

- 分类和子文档层级决定资料放在哪里。
- 阅读顺序决定连续阅读、导出和提供给 LLM 的正文次序。
- 画布坐标和图层决定空间位置及遮挡。

移动画布块不自动改变阅读顺序；图上靠近不自动生成关系。公开布局伴随文件不重复保存正文。

关系网区分目录包含、正文引用、模块引用和手工关联，并能定位来源。系统可从真实引用自动展示关系，用户无需在知识空间再手动补一条相同关系。

共享地图拥有唯一基础来源，场次、战斗和镜头各自的覆盖层独立。引用预览默认不允许直接修改基础地图。

Quest 收为文档关联的问策记录。LLM 可以提问和提出候选修改；用户原始回答、审批和版本按来源保留。模型不代答、不批准自己的提案。

## 8. 保存规则要支持真正的桌面工作台

当前工程以单文档草稿和模态编辑为主。标签页上线前，必须建立逐文档编辑会话，维护各自的未保存状态、选择、撤销、资源及保存基准。

拟议命令含义：

- 保存当前文档：保存活动文档及这次编辑涉及的布局、媒体和必要关联变更，形成一致的事务。
- 保存全部：保存当前项目全部用户已编辑的工作稿；未批准的模型提案继续作为候选。
- 项目另存为：收集当前完整工作状态，包括其他标签页的未保存修改，生成新项目身份与有效内部引用。
- 关闭文档：有修改时提供保存、放弃、取消，只处理该文档；存在关联变更时说明影响范围。
- 关闭项目：汇总未保存文档，提供保存全部、放弃、取消。
- 保存冲突：保留工作稿，展示源文档变化，不能用最后一次写入覆盖外部修改。

跨文档依赖要明确处理：当前文档引用另一标签页中新建且未保存的文档或块时，保存前列出必须连带保存的资料，用户选择一并保存或取消；不能静默提交另一份未完成工作稿。已有源文档的未保存正文变化不因被引用而自动保存。

分类、层级和排序等结构草稿归属于项目，独立于某个文档标签页。其保存可能涉及 PROJECT.md 和多份文档，显示共同提交范围。关闭或放弃单篇文档不自动撤销共享结构草稿；项目关闭时将结构草稿一起列入保存 / 放弃范围。

选择“放弃”同时作废对应的恢复草稿，再次打开不能恢复用户明确丢弃的修改。另存为保留未批准提案的候选身份，不将其应用为正文；新项目建立自己的初始版本，原项目和历史不改写。取消或失败均保持当前项目。

任何命令取消后不产生隐式保存。项目文件变更不能通过无提示的“刷新目录”丢失用户工作稿。

示例模式下 Ctrl+S、保存全部及项目另存为统一进入“另存为新项目”。确认前所有正文、布局、媒体和草稿只在会话内存中：不写 localStorage、IndexedDB、OPFS 或 .cewen 持久草稿，不登记最近项目，不建立索引、版本或自动备份。发行包内原始示例及媒体只读；不能经过现有正式项目 read() 所附带的持久化通道。

## 9. 保留并补足上一版的完整主流程

### 项目库

默认启动进入项目库；列表分页，不纵向加载项目。每张卡显示创建时间、最后编辑时间、路径、收藏与菜单；支持按创建时间、最后编辑时间和名称排序。

搜索、筛选和排序作用于全库，再分页。创建时间保留首次创建的可靠来源，导入和打开不重写；未知时显示未知，不以导入时间冒充。最后编辑时间来自成功保存的内容变化，或核验的外部内容变化。浏览、收藏、界面布局偏好和草稿缓存都不更新这个时间；已保存的文档画布布局属于项目内容变化。

移除记录与删除本地文件分开；后者展示精确项目根路径并二次确认。桌面优先回收站，平台只能永久删除时明确说明实际行为，失败保留记录。执行前校验项目身份及精确根目录，不删除保存父目录、不跟随链接越出项目边界。项目正在打开时先处理未保存工作稿和正在写入的操作；取消即不删除。

### 一体化新建项目

唯一新建流程：问想法 → 选择起步结构 → 编辑开场白与文档目录 → 名称和路径 → 创建并进入文档。

首次无预设选中；推荐必须明确采用。允许跳过问卷、空白开始、自定义结构。复制开场白不要求模型已连接，返回上一步保留用户修改，确认前不建文件。

### 示例

“教程与示例”是唯一入口，按学习目标、难度及领域筛选。选中后直接进入正常工作台，允许完整编辑和播放，持续显示临时状态。

正文、媒体、分类、布局、引用和撤销只写当前会话。关闭有修改时提供另存为、放弃、取消；再次打开回到原始示例。

另存为确认后才建立完整工程。导出、备份和会写附件的生产动作先另存为，取消则不执行。没有真实第三方环境的能力保留未验标记，不自动发起付费生成。

### 教程内容重整

入门讲一份文档；组合讲图片、对白和声音；组织讲分类、引用和覆盖层；进阶讲问策与播放。

纸上远行作为 2—3 份文档的基础教程；游戏、世界观、剧本和短片示例各约 3—4 份主题文档；综合示例保留为进阶。

“雨夜候车室”围绕地点资料、人物和场次文档展开；对白在场次内编辑，角色通过引用使用。“最后一盏灯”围绕一个短场景的分镜、音轨和时间序列展开。这两类示例都允许自由插入其他模块。

## 10. 三条具体使用路径

### 路径 A：建立角色并用于剧本

1. 在“人物资料”分类右键，通过“从文档预设创建…”选择角色卡，或直接使用已置顶的角色卡预设。
2. 中央打开普通画布文档，填写称呼和简介，插入图片；不需要完成固定字段表。
3. 打开场次文档，将该角色从树中拖入，得到有来源标记的引用预览。
4. 在同一场次文档中插入对白、地图和分镜。
5. 通过引用卡打开角色原文，修改后相关引用保持同源。
6. 保存文档，布局、资源和引用共同保存。

这条路径用于验收“角色卡就是普通文档”的实际可用性。

### 路径 B：整理已有资料

1. 在左栏搜索关键词，结果显示分类路径。
2. Ctrl / Shift 多选文档，右键“移动到…”。
3. 目标选择器展示分类树；若有子文档，明确显示将一并移动的数量。
4. 确认后选择和当前编辑页保持稳定，出现可撤销提示。
5. 从搜索结果执行“在目录中定位”，展开到实际位置。
6. 分类、用途和正文引用各自保持预期含义。

### 路径 C：临时学习并保存自己的改稿

1. 从项目库打开“雨夜候车室”，直接进入正常工作台。
2. 修改对白、拖动画布、插入临时媒体，均不建立本地项目。
3. Ctrl+S 打开“另存为新项目…”。
4. 取消时继续临时编辑，零项目文件写入。
5. 确认名称和位置后，当前完整内容成为新工程。
6. 返回示例目录再次打开原示例，内容保持原始状态。

## 11. 工程实施顺序

| 顺序 | 工作包 | 必须先解决的理由 |
| --- | --- | --- |
| 1 | 统一命令、选择范围、浮层与焦点 | 文档树、右键、快捷键和所有模块共用，直接消除菜单遮挡与行为分散 |
| 2 | 通用文档可见性、分类迁移规则、文档 / 模块身份 | 防止撤掉专用入口后资料失联，避免改分类破坏已有层级 |
| 3 | 文档会话、保存 / 另存为、示例内存存储 | 为标签页和临时示例提供一致边界 |
| 4 | 固定主工作台、项目文档树、官方及自定义文档预设的创建 / 编辑 / 管理 | 建立符合日常创作习惯的主操作路径，并让用户扩展起步内容 |
| 5 | 默认自由画布、统一手势、文内模块与引用预览 | 完成文档内自由组合，整合问策及播放 |
| 6 | 项目库与新建向导、示例重整、迁移验收 | 贯通从启动到学习、工作、保存的完整流程 |

菜单修复可以先独立落地，整版验收必须覆盖文档组织、编辑会话及模块组合。无需为了桌面体验重写成另一套框架；用现有技术栈抽出公共组件，保持桌面与网页共用业务规则。

旧文档、模块 ID、引用、用户原始回答及历史保留。旧专用面板的链接转到所属文档和目标块。按内容职责处理 guide：用户创作资料进入统一导航，系统索引与伴随文件继续隐藏。

空白或纯文字文档的生成也要检查，避免因对象列表为空被错误归为隐藏资料。首次查看旧文档不写回，格式调整在用户保存后形成新版本。

文档类型中的 gdd/dd 等旧标识可以保留解析适配；新界面不要求所有创作围绕唯一游戏总纲。项目概览成为可选普通文档，不再作为通用分类树的必需父节点。

## 12. 人工验收标准

下列标准为实施阶段执行，不表示本轮已通过。

### 对象与导航

- 从角色卡、地图卡、道具卡预设创建的都是普通文档；能移除全部预置字段并插入其他模块。
- 用户能从空白、官方预设副本及当前文档创建自定义预设，并在其他项目中使用。
- 预设保存包含模块、字段、默认内容、布局及阅读顺序；从文档提取时素材和内容范围明确。
- 每次应用预设产生新身份，内部引用有效，源项目外部引用成为可识别占位，不修改源文档。
- 修改或删除预设不影响已有文档；应用升级不覆盖用户预设。
- 编辑当前文档与编辑预设的状态、保存入口清楚；示例中取消另存为不写本机预设库。
- 地点资料与场次文档含义清楚，场次引用角色后不生成重复角色。
- 文档树、卡片视图、知识空间和引用预览都能定位到同一源文档。
- 旧问策、制作记录和纯文字文档不会因类型过滤从导航消失。
- 单击、双击、F2、多选和右键行为一致；移动后保留选择和当前编辑。
- 文档改分类时子树影响明确；标签或用途变化不改变正文和位置。
- 目录文档数不混入章节数，搜索条件始终可见。

### 菜单与输入

- 在目录最底行、四个窗口角、长标题、滚动后及 125% / 150% 缩放下，菜单完整可操作。
- 在模态对话框内打开选择器，层级、外点关闭及焦点范围正确。
- ⋯、右键、菜单键和 Shift+F10 展示相同命令。
- 菜单方向键、Enter 和 Esc 生效；命令不穿透到背后的画布。
- 中文输入法组合期间无误确认、误关闭或画布快捷键。
- 删除文字与删除模块、删除文档的作用范围清楚。

### 画布与保存

- 空白左键平移、二维右键框选、三维右键旋转；右键拖动结束不弹菜单。
- 内外画布不会同时移动，文本拖选不移动模块。
- 切换多个未保存文档时各自内容、撤销和布局状态保留。
- 当前文档保存、全部保存和项目另存为的范围与文案一致。
- 引用预览不隐式修改源资料；地图局部覆盖层相互隔离。
- 临时示例全部编辑过程零项目落盘；另存为取消零写入，确认后资料完整。
- 项目库分页、日期、收藏、排序和删除二次确认通过独立虚构项目验收。
- 历史不被改写；模型不能代答或批准自己的提案。
