# 策问 Designform 下一版本产品优化方案

- 日期：2026-09-27
- 状态：产品提案，尚未实施；不代表已完成界面、功能或验收。
- 基线：现有 0.9.0 RC 版本。
- 依据：用户本轮诉求、提供的工作台截图、现有代码，以及此前“文档即画布”方案。
- 本轮范围：整理产品定位、信息结构、交互、数据边界、实施顺序与验收标准。未改软件源码，未执行构建或测试。
- 截图审阅范围：能够确认顶级入口和工具栏存在分散、堆叠的问题；未据此声称已审阅全部运行页面。

## 一、产品定位与这轮纠偏目标

**策问是以通用文档为核心的本地创作与策划工作台。每份文档本身就是自由画布，用户在文档内组合内容模块，通过分类和引用组织项目，并使用 LLM 辅助问询与提出修改。**

产品的基本组成只有一套：

1. 项目包含通用文档和媒体资源。
2. 文档具有标题、分类、标签和引用关系；分类可以留空、修改、重组。
3. 文档画布内组合文字、图片、对白、地图、音视频、表格等模块。
4. 知识空间、目录、卡片展示和播放预览，都读取这些文档及其引用。
5. 保存、版本、另存为和导出遵守统一的项目规则。

角色卡、场景卡、游戏总纲、专项设计和剧本都是文档的用途。它们可以提供可选的起步布局与字段，用户始终能自由增删模块。预设不决定项目能使用哪些功能。

这延续了此前“文档即画布”的定位。下一版应优先纠正入口和编辑流程的偏离，同时补齐真实的画布操作。

### 当前问题与调整方向

| 当前情况 | 下一版调整 |
| --- | --- |
| “创作模块、Quest、排演”成为三个顶级入口 | 收回到文档内插入、问策及播放动作，撤掉三个并列顶级入口 |
| 模块默认围绕独立对象文档创建和保存 | 在当前文档、当前位置插入；是否另建文档由用户决定 |
| 文档自由排版是写作中的附加模式 | 打开文档默认进入可编辑自由画布；连续阅读和 Markdown 源码作为按需视图 |
| 新建设想和从预设创建是两项功能 | 合并为一个新建项目向导，回答、开场白、起步结构及工程创建共同完成 |
| 示例选择器内专门渲染简化内容 | 选择后进入与正式工程相同的工作台，获得完整模块和媒体预览 |
| 示例的完整编辑必须先创建本地练习副本 | 默认以会话内临时项目打开；只有另存为确认后建立正式文件 |
| 多种示例共用大而全的内容生成器 | 按学习目标组织小型示例，综合示例作为进阶路线 |

## 二、项目库成为默认首页

### 1. 启动行为

启动后直接显示项目库，不自动打开上次项目。

上次项目可标注“上次使用”，提供“继续打开”按钮。项目库浏览不应触发工程读入、版本建立或备份。

### 2. 页面布局建议

以下是可审阅的信息布局，保留现有视觉风格；具体尺寸在后续线框稿中确定。

| 区域 | 内容 |
| --- | --- |
| 顶栏 | 策问名称、版本信息入口、设置 |
| 主要操作 | 新建项目、打开已有项目、教程与示例 |
| 筛选栏 | 搜索；全部 / 收藏；排序字段和升降序 |
| 主区 | 固定数量的项目卡片，支持列表显示 |
| 底部 | 总数、当前页、上一页、页码、下一页、每页数量 |

建议常规窗口每页默认 12 项。根据可用窗口高度调整每页数量，窄窗口可改用紧凑列表；每页项目必须容纳在主区内，项目列表不纵向滚动，也不采用无限加载。每页数量选项仅提供当前窗口能容纳的数量；窗口尺寸变化时保留当前项目定位并重新分页。

搜索、收藏筛选和排序先作用于完整项目库，再分页。删除当前页最后一项、修改筛选后，要修正页码，避免出现空页。

### 3. 项目卡片

默认显示：

- 项目名称；
- 创建时间；
- 最后编辑时间；
- 收藏状态；
- 项目路径或位置说明；
- 操作菜单。

项目菜单包含：打开、收藏 / 取消收藏、打开所在文件夹、从项目库移除记录、删除本地项目。

名称过长允许换行或省略，路径可以展开；两个时间应使用完整文字标签，不能只依赖悬浮提示。

### 4. 时间和收藏的规则

- 创建时间来自可靠项目元数据。旧项目无法确认时显示“未知”，导入时间单独标识。
- 最后编辑时间表示内容最近一次实际保存或可核验的外部修改。
- 打开、阅读、切换视图、缩放、收藏和排序均不更新最后编辑时间。
- 示例不登记为正式项目，不混入项目时间排序。
- 收藏和排序属于本机项目库偏好。下一版先支持“全部 / 收藏”；自定义收藏夹分组作为后续扩展，避免增加管理负担。

### 5. 删除本地文件

必须把“移除库记录”和“删除本地项目”分成两个清楚的操作。

删除流程：

1. 用户在项目菜单选择“删除本地项目”。
2. 展示项目名、完整根路径、删除范围，以及正文、媒体、历史等会一并移除的信息。
3. 用户进入第二次确认，再确认执行；首次点击菜单不能直接删除。
4. 桌面版优先提供移入回收站。若所处平台只能永久删除，确认文案明确写明实际行为。
5. 成功后移除库记录；失败保留记录，显示实际错误和仍然存在的路径。

执行层必须校验项目身份和精确根目录，不能把用户选过的父文件夹当成项目根删除。当前已打开且有未保存修改的工程，先处理保存、放弃或取消。取消操作不改文件。

## 三、示例与预设重新分工

### 示例：学习操作与方法

项目库只提供一个“教程与示例”入口。目录按学习目标、难度和内容领域筛选，选择页面展示名称、学习目标、涉及能力与“打开示例”。

点击后进入正常工作台：

- 使用相同的文档树、自由画布、模块编辑、知识空间和播放器；
- 页面持续标注“示例 · 修改仅保留至关闭”；
- 不另造一套只读 Markdown 预览器；
- 用户可以编辑、增加文档、插入媒体、调整分类和引用；
- 原始示例始终保持不变。

“预览示例”就是在正常工程环境内查看和操作内容。选择器不再提供一套不完整的专门预览流程。

### 示例保存与退出

| 行为 | 应有结果 |
| --- | --- |
| 打开示例 | 建立会话内存状态，不新建工程目录 |
| 编辑、插入、撤销 | 修改只保留在当前会话，不写持久草稿、备份或正式版本 |
| 点击保存 / Ctrl+S | 进入“另存为新项目”，说明本示例尚未成为本地工程 |
| 另存为取消 | 保留当前会话修改，零项目文件写入 |
| 另存为确认 | 将当前完整编辑结果保存为新项目，获得新项目身份并打开 |
| 未修改时关闭 | 直接退出，释放临时状态 |
| 有修改时关闭 | 提供“另存为新项目 / 放弃修改 / 取消” |
| 再次打开示例 | 从原始示例重新开始 |

临时状态必须覆盖正文、分类、引用、画布布局、附件和撤销记录。仅给正文加“示例”标记不足以实现要求。

现有项目读取、草稿和自动备份通道会产生持久数据。实现时要建立独立的临时项目存储方式，阻断项目注册、索引、历史、自动备份、.cewen 草稿和浏览器项目持久存储等写入。

示例导入媒体使用内存资源；不得默认复制到正式素材目录。需要将第三方生成结果保存为项目文件时，先要求另存为。下一版不自动触发付费生成任务。

示例模式下，导出、备份、素材生产及其他会创建工程或附件文件的动作，统一先另存为正式项目；取消另存为即不执行后续写入。示例缓存仅存在于当前会话。

正常关闭、切换项目和退出应用均要经过统一的退出流程；异常崩溃后的恢复不作为示例能力，避免借恢复功能重新引入持久文件。

### 预设：可选择的工作起点

预设只出现在新建项目向导内，提供可编辑的目录、少量空白文档和模块组合。它不包含完整教学故事，也不绑定项目类型。

- 首次进入没有任何预设被选中。
- 可以选空白、采用推荐预设或自行组合。
- 推荐不等于选择，必须由用户明确采用。
- 用户可删掉推荐字段和文档。
- 所有项目始终可插入全部模块。

## 四、统一的新建项目向导

统一入口名称为“新建项目”。游戏设想、剧本想法和其他创作意图是同一流程中的输入。

### 步骤 1：了解想法

询问少量有用问题：

- 你想做什么？
- 希望给谁带来什么体验？
- 已有资料有哪些？
- 有哪些范围、时间或形式约束？
- 想先解决什么问题？

允许跳过、不确定和自由填写。不能要求用户先明确游戏 / 剧本 / 电影分类才能继续。

### 步骤 2：形成起步方案

根据回答推荐目录和少量文档，并解释推荐理由。

当前状态明确显示“尚未选择起步结构”。用户可采用推荐、选其他预设、空白开始或手动修改结构。

结构按工作主题组织，例如“创作目标、人物与场景、剧情正文、待讨论问题”；不会因为出现某个模块就强制创建一个外部面板或独立文档。

### 步骤 3：开场白与工程结构共同确认

同页展示：

- 可编辑的 LLM 开场白；
- 将创建的文档目录；
- 用户已有的回答和仍未决定的问题；
- 将采用的起步结构。

开场白包含用户真实回答、创作目标、约束、当前结构和协作规则：先问清未知信息，区分提议与用户决定，未经用户确认不自行采纳。

用户修改开场白和修改工程结构要有明确的一致性提示；重新生成前保留手工修改，不静默覆盖。

### 步骤 4：创建并打开

填写名称和保存位置，确认后一次性创建工程、保存启动说明并进入第一份文档。

复制开场白可在创建前完成；本地问卷整理不依赖模型连接。如果用户选择连接模型继续问询，它仍属于这个流程，并显示实际连接状态。

推荐的主按钮为“创建并进入项目”，旁边提供“复制开场白”。不要让“先和 LLM 聊聊”和“创建工程”变成两个断开的产品入口。

返回上一步保留输入。确认前不生成项目文件。

## 五、文档默认就是自由画布

### 1. 最小可用能力

下一版必须交付真正能工作的画布：

- 平移、缩放、回到内容、全景定位；
- 模块插入、移动、缩放、删除和复制；
- 单选、框选、多选、对齐和基础吸附；
- 置顶、置底及明确的层级管理；
- 可折叠的章节或内容组；
- 长文本编辑、媒体预览；
- 撤销与重做；
- 明确的阅读顺序；
- 保存、版本查看、另存为和导出。

文档默认使用可扩展画布。打开旧文档先按正文顺序生成临时布局；仅查看不能自动改写正文或布局文件。

文字块可直接进入编辑，按原有编辑习惯选择文字；拖动使用模块边缘或标题把手，避免每次想选文字都移动整块。

### 2. 三种顺序分开

| 概念 | 用途 | 修改方式 |
| --- | --- | --- |
| 文档分类 / 目录 | 决定文档如何组织和查找 | 文档属性与目录操作 |
| 内容阅读顺序 | 决定阅读、导出和 LLM 获取内容的顺序 | 章节顺序、阅读顺序控件 |
| 画布图层与坐标 | 决定空间位置和遮挡 | 拖动、布局、置顶置底 |

画布上靠近不自动等于引用；放到上方不自动成为章节标题；位置变化不自动改变 LLM 阅读次序。

连续阅读视图用于检查叙述结构，Markdown 源码用于高级编辑，两者都读取同一份正文。布局伴随文件只保存坐标、尺寸和层级，不复制正文。

### 3. 模块在文档中组合

插入菜单按用户动作归类：

| 分类 | 模块 / 动作 |
| --- | --- |
| 写作与结构 | 文字、标题、列表、表格、分组 |
| 图像与声音 | 图片、音频、视频、媒体说明 |
| 叙事内容 | 对白、可选角色资料组合、可选场景资料组合 |
| 空间与关系 | 地图、地图引用及局部覆盖层、文档或模块引用 |
| 视觉表达 | 色板、分镜、时间序列 |
| 协作 | 提出问题、关联讨论、候选修改 |

“角色资料组合”是可拆解的文字、图片、字段和引用组合，任何模块都可独立使用。用户无需填完专业表单才能记录一个角色。

例如：

- 角色文档：自由文字 + 肖像 + 可选资料字段 + 声音 + 相关场景引用。
- 场景文档：场景说明 + 地图引用 + 本场覆盖层 + 对白 + 可选分镜。
- 战斗设计文档：目标体验 + 规则说明 + 地图引用 + 独立部署覆盖层 + 待问问题。

共享地图保留唯一基础源。战斗、剧情和镜头文档的局部覆盖层分别保存，修改某一层不能改动其他层。

### 4. 三个新增顶级入口的去向

| 现有入口 | 下一版位置 | 可复用的能力 |
| --- | --- | --- |
| 创作模块 | 当前文档的插入菜单、选中模块的属性区 | 模块注册、字段、引用和编辑组件 |
| Quest | “问策”动作及当前文档关联的问答记录 | 问题轮次、用户回答、提案审核 |
| 排演 | 文内时间序列的“播放预览” | 播放器、音轨、时长计算、素材引用 |

复杂模块可以在当前文档内展开编辑，或临时进入聚焦模式。退出后回到原文档和原位置；保存仍统一交给项目。

素材生产属于媒体块上的可选动作，不占据默认顶级导航。

LLM 可以整理上下文、提问和提出候选修改；用户负责回答及采纳决定。模型不能代答，也不能批准自己的提案。

## 六、工作台和左上角功能区

### 建议的信息布局

| 区域 | 常驻内容 | 按需内容 |
| --- | --- | --- |
| 应用壳栏 | 名称、当前项目、状态 | 关于、设置、窗口操作 |
| 左上文件菜单 | 项目库、新建、打开、保存、另存为、关闭 | 导出、备份、项目设置 |
| 左侧目录 | 文档树、搜索、新建文档 | 分类 / 标签筛选；卡片显示方式 |
| 中央主区 | 当前文档的自由画布 | 知识空间、连续阅读、源码 |
| 文档工具栏 | 插入、撤销、重做、定位、问策 | 当前模块的预览或播放 |
| 右侧属性区 | 无选择时可收起 | 当前文档分类 / 引用，或选中模块属性 |
| 底部状态区 | 正式 / 示例状态、保存状态 | 操作提示、错误与冲突 |

建议把“策划案”改为更通用的“文档”，知识空间作为同一批资料的关系视图。“卡片库”收为目录或库的显示方式，避免用户误以为需要建立另一套内容。

状态相关工具按需呈现。版本历史打开后显示版本导航，关闭历史后撤掉整排版本按钮，避免常驻多层工具栏。

### 保存与另存为

- 正式项目：保存写入当前项目；另存为将当前完整状态复制到新位置并打开新项目。
- 示例：保存统一转到另存为。
- 历史查看：只读；恢复以新版本保存。可以将选定历史版本另存为独立项目。
- 另存为包含正文、布局、资源及有效引用，生成新项目身份；不复制凭证、缓存及临时恢复数据。
- 另存为取消、路径冲突或写入失败时，不切换当前项目。
- 修改过的内容先纳入另存为结果，不能仅复制磁盘上的旧版本。

“关于”继续放在应用壳菜单，展示实际包版本、作者信息、仓库、项目网页和源码基准。信息从发行元数据读取，不写成会长期过期的固定版本文案。

## 七、鼠标交互统一规则

| 区域 / 对象 | 左键 | 右键 |
| --- | --- | --- |
| 二维画布空白处 | 拖动平移 | 拖动框选；静止点击打开菜单 |
| 三维知识空间空白处 | 拖动平移 | 拖动旋转；静止点击打开菜单 |
| 模块标题或把手 | 拖动模块；点击选择 | 对象菜单 |
| 正在编辑的文字 | 光标、文字选择、文本拖选 | 编辑菜单 |
| 地图等嵌套画布 | 聚焦后沿用相同平移规则 | 二维框选 / 三维旋转 |

滚轮在画布空白处缩放；长文字编辑区滚轮滚动文字。明确的聚焦状态决定嵌套画布处理手势，避免外层和内层同时移动。

辅助操作可提供“空格 + 左键”在内容上临时平移、方向键微移、按钮缩放等，但基础导航无需中键。右键拖动越过移动阈值后不再弹出菜单。

绘制、连线等显式工具启用时，左键执行当前工具动作，界面清楚标注工具状态；退出工具恢复左键平移。工具手势与画布导航要分别说明。

## 八、示例的分层分类与内容重整

### 现状判断

当前多个示例共用 buildPreset 的大型内容结构。不同示例通常都包含两张地图、声音方案、六个设计专题、角色、场次、分镜、排演和多项 Quest，仅切换学习重点。

分类标题已经有父子关系，但内容仍围绕模块类型展开，新手会先面对大量对象，再理解文档目的。下一版需要调整示例内容和组织方式，不能只把目录缩进加深。

### 1. 教程目录层级

建议四条学习路线：

1. 入门：建立和编辑一份通用文档。
2. 内容组合：在一份文档中组合图片、对白和声音。
3. 分类与引用：关联多份文档，共享地图并隔离局部覆盖层。
4. 进阶协作：问策、候选修改、分镜与播放。

领域标签如游戏、世界观、剧本、短片只用于筛选。先显示学习目标，再显示领域，不把教程目录变成专业工具导航。

### 2. 现有示例的改编方向

| 示例 | 学习目标 | 建议内容规模与组织 |
| --- | --- | --- |
| 纸上远行 · 基础示例 | 通用文档、画布编辑、保存与另存为 | 2—3 份文档；一份导览、一份主要练习文档、可选关联文档 |
| 雾港来信 · 游戏章节 | 规则说明与地图引用 | 约 4 份主题文档；保留必要规则与路线，不预置整套影像生产链 |
| 雾港来信 · 世界观 | 人物、地点与关系 | 3—4 份文档；人物和地点通过引用建立联系 |
| 雨夜候车室 | 剧本文字与对白组合 | 3—4 份文档；对白直接在场景文档中编辑，角色资料独立引用 |
| 最后一盏灯 | 分镜、声音与播放 | 约 3 份文档；从一个短场景开始，分镜和播放序列在文档内组合 |
| 雾港来信 · 综合示例 | 跨文档共享与完整协作 | 进阶示例；分成来源资料、主题文档、讨论记录、媒体资源四组 |

这里的规模是内容编辑目标，不是产品限制。用户可以随时插入其他模块。

每个示例提供：学什么、从哪份文档开始、第一步操作、预期观察结果、可选扩展。引导可收起，不要求打卡或按步骤解锁。

### 3. 示例内部的分类原则

- 一级分类按内容职责组织，如“创作说明、人物与地点、剧情正文、讨论记录”。
- 模块类型标签用于查找，不强制生成同名独立文档。
- 一个场景中的文字、对白、地图引用和分镜可以共存于同一文档。
- 角色、地点、对白和地图有清楚的唯一来源；引用说明引用目的。
- 教学资料与虚构故事正文分开；演示回答、机械配音、示意图和模型未验项明确标注。
- 画布图层只管理遮挡，不用来代替文档分类或教学难度。
- 未使用的预设空字段、重复总览和无教学目标的对象从示例中清理。

## 九、复用与迁移边界

### 保留并整合

- Markdown 权威正文、稳定文档和模块 ID；
- 公开布局伴随文件、媒体资源、跨文档引用；
- 版本、冲突检查和事务保存；
- 地图及局部覆盖层隔离；
- 对白、分镜、播放器、时间计算；
- 用户回答、问策轮次与提案审核。

### 收拢和清理

- 三个独立顶级工作区；
- 模块默认另建文档并单独形成版本的流程；
- 示例专用简化预览器和强制先建练习副本；
- 两个独立的新建入口及默认预选预设；
- 重复工具栏、重复问题系统、示例中冗余对象与领域限定文案。

### 资料迁移

旧资料按普通文档打开，保留正文、引用、媒体、用户原始回答和历史快照。

旧面板链接转到所属文档及目标模块。旧序列保留可播放能力；未知模块至少保留原文并显示说明，不静默丢弃。

首次打开先生成临时视图，用户保存时才写入新布局。需要改变格式时形成明确的新版本，不能改写旧历史。

## 十、实施顺序与范围

本方案的全部用户诉求纳入下一版。建议按依赖拆成可验收阶段，避免只有导航名称改变。

| 阶段 | 交付内容 | 完成门槛 |
| --- | --- | --- |
| A：产品结构与存储规则 | 三张主线框、统一项目状态、示例临时存储、保存 / 另存为规则 | 文档与模块关系明确；示例零落盘可验证 |
| B：文档主工作流 | 默认自由画布、模块文内插入、统一手势、问策及播放入口整合 | 从一份文档完成组合编辑、预览、保存、版本查看 |
| C：项目入口 | 默认项目库、分页、时间、收藏、排序、删除、统一新建向导 | 新建与打开路径完整，删除双确认，预设无默认选中 |
| D：示例与收尾 | 同工作台示例、内容减量、分类重整、旧资料迁移和文案更新 | 学习与工作起点清楚分离；旧资料保留，端到端验收通过 |

可以并行处理项目库与画布，但共享的项目状态、保存行为和引用规则必须先确定。下一版不增加新的顶级专业工作区；专业增强仅在文内组合和已有能力整合范围内处理。

本方案不承诺自动生成成片、真实模型效果验收、云协作或新增第三方付费生成。已有未验能力继续保留明确状态。

## 十一、发布前人工验收清单

以下是拟定验收标准，尚未执行。

1. 无论上次打开何种工程，重启先进入项目库。
2. 构造 100 个虚构项目；分页、三类排序、搜索和收藏组合没有重复、漏项或失效页码。
3. 打开、浏览和收藏不修改最后编辑时间；正式保存后时间正确更新；未知创建日期不编造。
4. 删除两次确认都有明确项目路径；任一次取消零文件变化；失败保留记录；父目录和其他工程不受影响。
5. 示例打开后与正式工程使用相同工作台；能完整编辑文字、媒体、布局、分类、引用及播放。
6. 示例编辑并关闭后，项目目录、库记录、持久草稿、备份与版本没有新增；再次打开恢复原始内容。
7. 示例另存为取消零落盘；确认后仅生成一份完整正式项目，包含当前修改且引用有效。
8. 新建首次没有预设选中；回答、结构和开场白一致；回退不丢手改内容；最终创建一次。
9. 在一个空白文档中自由组合文字、图片、对白、地图和音频；不存在必须切换到外部专业面板的步骤。
10. 画布左键平移、右键框选；三维空间右键旋转；文字拖选不移动模块，嵌套画布不同时拖动外层。
11. 拖动只改变布局，阅读及导出顺序保持稳定；调整阅读顺序后导出和 LLM 上下文随之更新。
12. 两份文档引用同一地图，修改各自覆盖层不影响基础地图或另一份覆盖层。
13. 问策保留用户真实回答；模型提案必须由用户采纳，模型不能自批。
14. 旧示例及旧工程的正文、媒体、稳定引用和历史可以读取，不发生查看即改写。
15. 正式项目的保存、另存为、失败回退及关闭均完整；关于信息匹配实际发行包。
16. 桌面与网页按各自权限方式复核，全部使用独立虚构临时项目。

## 十二、方案的评审重点

建议先评审三张线框稿：项目库、统一新建向导、通用文档画布。

评审重点是用户能否从进入软件到开始一份文档，始终清楚自己在哪里、当前资料是否已保存，以及下一步操作会不会创建本地文件。确认这些主流程后再进入实现。
