# 策问：工作台视觉与交互整合方案

日期：2026-09-23。状态：待评审设计方案。本轮没有修改正式软件、打包或迁移项目。

本方案补充《策问_文档即画布与综合设计站方案_20260923.md》，对白入口以本方案和用户最新说明为准：保留文档内可点击选项的预览，点击独立编辑按钮进入对白编辑页；优化两处样式和编辑能力，不把蓝图默认铺进正文。

## 1. 产品结构与本轮决定

策问是一套本地优先的游戏设计工作台。一份统一设计文档承载文字、图片、色板、对白及参考，文档自身可以自由排版。知识空间负责理解跨文档关系；项目目录负责定位和组织；问询负责逐步做决定；版本负责解释变化；内容概览负责统计和发现待处理内容。

本轮重点是把已有能力组织清楚，形成可持续工作的界面：

- 系统导航与项目内容分开；项目库和当前项目设置有不同入口。
- 中性、低饱和的明暗底色；颜色主要表达分类、状态和少量选中反馈。
- 左侧采用分类导航与条目列表分栏，辅以收藏、最近和分类分页。
- 对白保留已经认可的预览与独立编辑流程。
- 正文与注释叠在同一文档上，但有独立选择、编辑与可见范围。
- 节点移动的物理表现与设计关系的实际修改分开。

统一文件格式不等于所有任务共用一组操作：阅读对白用轻量预演，编辑对白用专用页面，二者仍引用同一文档中的同一份对白数据。此轮不引入独立图片文档或独立参考画板。

## 3. 明暗主题与图标

### 3.1 参考方向

Linear 的官方改版说明强调降低导航的视觉权重，将偏蓝底色向低饱和暖灰调整，并把位置导航与当前视图操作分开。策问借鉴这种信息层级，不复制其整套外观。[Linear 官方设计说明](https://linear.app/now/behind-the-latest-design-refresh)

Obsidian 将基础中性色、交互强调色和语义色分开，并为明暗主题提供不同色值。策问用相同原则管理分类身份和表面颜色。[Obsidian 官方颜色文档](https://docs.obsidian.md/Reference/CSS%20variables/Foundations/Colors)

Notion 允许页面图标在页面与侧栏一致显示，并按需呈现链接和评论。策问借鉴其内容辨识与渐进显示方式。[Notion 官方页面样式说明](https://www.notion.com/help/customize-and-style-your-content)

### 3.2 推荐的两套默认方案

建议命名为“雾纸”和“墨石”。下面是起始配色，不是未经验收的最终数值。

浅色使用灰米纸面与稍暗工作台，降低整屏亮度；深色使用石墨底而非大片蓝黑。正文、图标、边框、悬浮卡、滚动条、下拉框和桌面标题栏统一取主题变量。星空保留空间感，浅色通过更明确的节点、标签和线条获得可读性，不单靠高亮光晕。

功能图标沿用现有 Lucide，统一尺寸和线宽。常态使用中性色，选中使用交互强调色；分类才使用分类色，错误和连接状态使用独立状态色。颜色旁保留名称或线型，避免只能靠辨色理解界面。开发验收要测实际底色上的正文、次级文字、焦点和控件对比度。

品牌只在应用固定区域出现一次。桌面外框显示菜单、当前项目/文档标题和窗口操作；当前项目图标与策问品牌图标明确分开。项目头像可用字符、内置图标或本地图片，不要求用户提供素材才能开始。

## 4. 项目库与项目详情

### 4.1 入口分工

- 应用栏“项目库”：进入已有项目列表，新建、打开和切换项目。
- 左侧当前项目图标或项目名称：打开“项目详情”轻量面板。
- 详情中的“更多设置”：进入当前项目设置页。
- 全局设置：主题、快捷键和个人偏好，不混入项目文案。

### 4.2 项目详情的内容

优先展示图标、项目名称、简短说明与备注。点击名称直接改名；点击图标选择字符/图标/上传图片并裁切。备注可留空，空时只提供“添加备注”的操作，不回填营销文案。

下方折叠放置项目文件夹、创建/更新时间、分类与色彩、默认文档模板、协作约定。文件夹可打开或复制；重命名项目不会自动移动磁盘目录、改项目 ID 或破坏引用。

项目图标、名称和共享备注属于项目资料，随项目复制、导出、版本保存；个人置顶、展开状态和列表视图属于用户偏好。已有 description 可承接简介，长备注另行明确，避免两个字段都叫“描述”。

桌面默认左栏可调宽，建议约 300～360px；分类列约 90～110px，其余留给完整条目名。窄窗口变成分类选择器与一列条目，不硬塞两列。

文档/收藏/最近是少量固定视图页签，不能把每个分类都横排成几十个页签。分类列每屏显示一组并可翻页，常用分类可置顶；切换分类仅替换条目列，保留各自位置与多选状态。底部固定工具区避免随列表滚走。实际条目量大时使用虚拟列表；用户需要时可开启按页显示，不强制每十个文档翻页。

搜索覆盖所有分类和别名，并标注命中归属，不受当前页限制；目录定位能自动切到目标分类页。总纲固定在项目总览顶部，分类数量不影响找到总纲。

### 5.2 行内编辑

- 移除当前无意义方块和常驻 GDD/DD 尾缀；有真实子项才出现折叠箭头。
- 单击打开；F2 或名称旁编辑操作进入改名，Enter 提交，Esc 取消。双击名称可作为同义入口。
- 行尾“更多”与右键菜单提供改名、别名、移动分类、上移/下移、置顶、复制链接等。
- 拖入同类插入线改变顺序；拖到另一分类接收区改变归属；给出目标预览，一次操作可撤销。
- 修改分类颜色在分类标题或分类菜单中完成，菜单写清影响整个分类。
- 框选、多选后的改分类和移动均显示条目数量，不能把批量选择误当单项。

同一文档保留一个主要分类；附加标签、收藏集合和跨系统关联提供多角度查看，不复制文档。排序、主要分类与包含关系分别存储，不能用目录顺序推断设计依赖。改名保持稳定 ID 与链接目标有效，不默认改写正文里引用它的措辞；旧标题是否保留为别名由用户选择。是否同步文件名作为明确动作处理，改路径时预览并更新受影响的相对链接。

## 6. 分类、条目与星团的颜色规则

颜色按一个身份来源贯穿全软件：项目分类基础色 → 左侧分类/条目提示 → 3D 星团和节点 → 分层分类标题 → 卡片归属提示。

当前颜色并非随机：预设分类有固定色，无色分类会按顺序取固定循环色。这容易在增加分类或顺序变化后产生不稳定感。新规则是在创建分类时分配并保存颜色，此后排序、重启、版本切换都不会重新取色。

默认条目继承分类色。分类菜单改色时同时预览整组，显示“分类颜色 · 影响 N 个条目”。条目菜单可以提供“继承分类色 / 自定义条目色”，后者只影响该条目及对应节点，不改变星团的整体身份；行中仍显示所属分类，避免一个独立节点色被误认为新分类。推荐初次使用以继承为默认，自定义放在更多设置。

明暗主题保持同一色相身份，按底色调节明度与饱和度，不机械使用同一个 HEX。用户选定的基础色保持不变；提供明暗预览和“恢复继承”。总纲仍为低调金色文字，与普通节点保持相同卡片/标签体量。

关系含义由线型承担：包含/分类实线，普通关联虚线。选中、高亮只叠加临时状态，不改基础色。美术文档里的设计色板属于游戏内容，与策问界面分类色分开；不会因为提取图片主色就自动改变导航或星团。

## 7. 内容统计与内容检查

### 7.1 文档底部

状态栏显示简短统计，例如“正文 1,286 字符 · 图片 6 · 对白 12 节点”。有选区时优先显示选区数量；点击进入统计详情，不把统计全铺在正文下方。

默认口径为正文可读字符数，不含空白，包含标点；标题、表格可读内容、链接显示文字和对白计入。Markdown 符号、YAML、ID、文件路径与链接地址不计入；代码块默认另列，图片替代描述与注释单独列示。另提供中文汉字数和外语词数，不把二者混成无说明的“总词数”。

折叠内容仍计入。对白按源节点统计一次，不能把不同预演路径、正文预览与蓝图编辑页面重复计算；图片分别展示引用次数与去重附件数。选区统计跟随实际编辑器选择，不只按当前可见 DOM 文本抓取。

底部及时反映本地草稿，并标明未保存；项目汇总默认使用当前已保存版本。将草稿混入全项目报表必须显式选择。外部 LLM 修改文档后重新解析并更新统计。

### 7.2 项目级“内容概览”

页面分“内容统计”和“待处理”两栏或页签。统计支持按分类、文档、角色、版本查看文档数、正文字符、图片、表格、对白台词/选项、色板与注释数量。

待处理列出空文档、未处理问询、悬空引用、失效图片、孤立对白等可定位项目。点击直接回到条目。提供 CSV 导出，适合后续做翻译、配音或审稿工作量核对；不凭字数生成设计质量评分。

版本比较展示新增/删除数量和内容净变化。保存版本统计与最新草稿不能混算，删除 100 字再新增 100 字不应被简单显示为“无改动”。

## 8. 对白：保留已认可的示例入口，精修两个界面

### 8.1 文档内预览

保留用户认可的结构：对白标题、当前角色与台词、可点击玩家选项、独立编辑按钮。

预览样式采用文档中的轻量嵌入块：名称与角色视觉清晰、台词有合理行宽，选项是具有足够点击面积的独立行，悬浮和选中反馈克制。避免大型头像、气泡装饰和分支线挤占正文。

预览提供上一步、重新开始、当前位置和结束反馈；分支较长时可展开访问路径。默认只显示读者需要的内容，条件和变量放进“调试预演”。不可用选项可显示原因；预演变量只作用于本次预演，不写回正式游戏设计规则。

点击选项只推进对白，不切换编辑页面。点击编辑进入专用页；返回时恢复原文滚动位置与预览路径。路径因修改失效时提示并退到最近可用节点，不无声跳往错误分支。

正式页面优先把宽度交给编排区；项目侧栏可临时收窄。属性面板只显示当前选中的节点或连接，窄屏改成底部抽屉。

节点卡面显示角色、台词摘要及选项，每个选项有独立输出端口。拖动标题移动节点；文本区域编辑文本；拖端口连接。空白双击或快捷菜单新建，连线拖到空白可选择下一节点类型。线端有箭头、选项文字或条件标签，避免依赖颜色辨识逻辑。

支持框选、多选拖动、对齐、复制、分组、断开/重连、搜索与适应视图。分组可以是场景或段落，不改变剧情执行顺序。节点摆放仅影响编辑布局，实际连接才决定跳转。

条件与结果采用可读字段，首版不执行用户任意脚本。缺失跳转、无出口和不可达分支提供定位提示；剧情有意循环允许保留。预演可从起点或选中节点开始，并临时调整测试变量。

参考 React Flow 的自定义节点、选择/拖动及连接端口能力，但现有项目不是 React 应用，不为单一模块预先承诺改写整个技术栈。先验证独立节点编辑模块与现有状态/撤销/Markdown 的适配。[React Flow 官方自定义节点说明](https://reactflow.dev/learn/customization/custom-nodes)

## 9. 文档注释层

文档仍是同一张纸面，顶部提供“正文 / 注释层”工具切换。正常阅读不显示一排画笔；进入注释层时出现荧光笔、画笔、橡皮、箭头、文字和贴图等工具。退出后注释可以保留可见，但默认不截获正文点击。

### 9.1 两类注释内容

- 讨论注释：锚定文字、图片或块，支持回复、待处理、已处理。
- 视觉注释：自由笔画、荧光标记、文本框、图片与贴纸，可移动、缩放、旋转、调透明度和层级。

二者共享注释面板、定位、可见范围和版本语义。荧光笔为透明笔画，不会直接改原文颜色；橡皮只擦选定的注释对象，不删正文。粘贴图片时依据当前焦点明确进入正文或注释层，旁边有“转为正文参考”操作。

常用标记可保存为个人样式，例如待确认、节奏问题、美术参考；默认少量预设即可，不把注释变成另一个复杂表单系统。整层支持显示/隐藏与锁定，个别对象支持选择和删除。

### 9.2 锚定与折叠

文字注释使用稳定块身份、引文和上下文；图片涂画使用图像内部相对坐标；空白处拼贴使用章节局部坐标。拖动图片、移动章节、折叠标题时，注释跟随所属目标。

文字重排后，选中文字的高亮应按文本重新定位；自由手绘笔画没有这种天然语义，默认跟随所属块的局部坐标。如果目标被删除、换图或大幅重排，应提示重新定位，不假装画笔永远能准确覆盖原来的文字。

### 9.3 可见范围与保存

“显示或隐藏”是视觉状态；“私人或项目共享”是数据范围，二者独立。默认私人注释；用户可将选中对象发布为项目注释。发给 LLM 前预览本轮选中内容，包含私密注释需要明确选择。

项目注释和公开拼贴纳入版本，与正文和附件一次保存；私人注释进入本地个人数据和草稿恢复，不自动写入公开设计历史。标为已处理不代表自动采纳，只有明确采用才修改正文。

导出提供纯正文、正文含项目注释、注释汇总三种选择。文本批注用 Markdown；视觉笔画保留可编辑数据并生成 SVG/图片供阅读，必要时补文字说明。不能要求纯文本模型从几百个笔画坐标推断美术意图。

## 10. 星图拖动与模式切换

### 10.1 柔和跟随

推荐“直接拖动准确跟手，邻近节点轻柔响应”的手感。被抓住的节点不能明显落后鼠标；相关节点通过阻尼弹簧跟随，近邻有柔和避让，松手后短暂收敛。

包含关系的邻居耦合较强；普通关联只给予很弱提示或不带动，避免高度互联项目一拖就整图震荡。总纲、用户固定节点和不在当前布局区域的节点不被随意拉走。多选成员保持用户选择的整体形状；未选中邻居才产生受限位移。

3D 拖动只保存摆放，不改分类、链接或正文。2D 仍有实际编辑意义，但必须拖到明确分类接收区、端口或可编辑连接段，并出现松手预览才执行。受引力移动的节点不能成为误触发归类或连接的依据；语义命中使用用户真实拖点和稳定目标。

连线时限制目标漂移；摇动断线只在指定手工关系编辑条件下可用，分类线和正文生成的引用不得被一次摇动无差别删除。每次编辑保留一条清楚的撤销记录；不按物理动画每一帧生成版本。

底层采用统一时间步进、有限邻域、位移/速度上限和能量衰减。松手稳定后保存布局；回到窗口或低帧率时不积累巨大位移。提供减少动态效果选项。

### 10.2 镜头切换

保留已经认可的主视图切换节奏，优先修路径而非缩短所有动画。

当前 camera 与 target 各自直线插值可能让视线方向接近退化；OrbitControls 的残留运动和快照恢复也需排查。开发时记录问题发生帧的相机、目标、朝向、尺寸和交互中断状态，不能把推测直接视为已定位缺陷。

改为由一个转场控制器管理目标点、观察方向和镜距：保持安全最小镜距，沿最短稳定方向插值，接近对向时选择固定辅助轴；避免穿过观察目标。分层的终点保持总纲在最高层，最终朝向稳定正视。

转场期间协调 OrbitControls 的残余阻尼与自动旋转，结束时同步控制器内部状态。节点布局变形与相机变化使用同一进度，不让相机已到而图形再扭一次。快切或打开侧栏时从当前可见姿态重建转场，不跳回旧起点。

重新进入 3D 恢复用户有效视角；用户主动拖动应可中断动画，不在松手后强制弹回。固定重现用例包括背面视角、俯视、大幅缩放、侧栏开合、连续快切、窗口变化和减少动态效果模式。

## 11. 数据与版本边界

正文、台词、图片路径、色板、阅读顺序、分类及显式关系保持 Markdown 可读；布局只保存位置尺寸，不再复制正文。LLM 看公开说明与 Markdown 即可开展设计，不需要读策问代码。

建议沿用统一文档方案的路径分工：

    PROJECT.md                          项目身份、说明、分类和基础色
    docs/gdd/、docs/dd/                  正式文档与对白内容
    docs/questions/                     已公开问询
    docs/assets/                        正文、项目图标与共享注释的附件
    docs/layouts/<文档ID>.json           公开排版与对白节点位置，不存台词副本
    docs/annotations/<文档ID>.md         项目讨论、视觉注释说明与预览引用
    docs/annotations/<文档ID>.ink.json   可编辑的公开笔画与锚点
    versions/                           一致快照
    .cewen/                             个人界面、镜头、私人注释与草稿

这些是同一文档自动管理的配套文件，不在项目列表里出现“图片文档”“画板文档”等新种类。图谱个人摆放仍属于个人布局；需要把特定排布作为项目成果时，显式保存为共享布局，再纳入版本。

现有提交白名单主要接收 Markdown 与附件，不能只在前端写一个 JSON 就认为已经接入版本。需补齐共享布局/注释的受控路径、格式校验、原子提交、外部修改检查、复制、导出、快照和恢复。历史版本只读，恢复创建新版本；删除注释展示不自动删除仍被其他版本引用的附件。

统计是按内容重建的索引，不是新的文档权威。分类色、图标和项目备注的修改可以形成项目资料版本；主题、分页、滚动、当前预演路径与镜头不制造设计版本。

## 12. LLM 协作入口

延续“每个协作入口都准备好开场白”的要求，并按真实连接状态区分：已连接显示真实客户端/模型名称和最近活动；未连接的 MCP 入口直接复制连接开场白，不打开通用创作组装器。

本轮新增的场景开场白包括整理分类与别名、检查对白分支、汇总所选注释、比较美术色板、复盘内容变化。每个入口自动带入当前文档或选择范围、公开资料路径、版本和目标，并列出拟交给 LLM 的内容。注释、预演临时变量与候选配色不会未经采纳写进正式规则。

## 13. 开发任务与验收顺序

以下用 A～D 划分范围，替代前一版提案中可能让人误认为工期承诺的候选版本号。实际发行号在范围通过后确定。

| 阶段 | 主要任务 | 必须看得见的验收结果 |
| --- | --- | --- |
| A：日常工作台 | 明暗主题变量、图标、项目详情、分栏/分页目录、行内编辑、分类色统一、文档底部统计 | 两个项目入口不同；分类多时快速定位；改色在目录和图谱一致；改名与撤销不坏引用 |
| B：图谱手感 | 带阻尼的局部跟随、稳定命中、相机路径与快切协调 | 3D 仅改摆放；2D 明确松手后才改关系；视角不绕背、不跳回；低帧率和侧栏开合可用 |
| C：文档与注释基础 | 稳定块身份、章节折叠、纸张、图片自由排版、注释锚点、公开布局/笔画保存与版本 | 中文输入/选区/撤销稳定；折叠移动后注释跟随；外部修改和恢复后正文、图片、笔画一致 |
| D：专用创作界面 | 对白预览精修、蓝图编辑、图像提色/色板、项目内容概览与检查 | 复现并保留已认可示例中的文档内选项预览与独立编辑入口；改台词与分支后预演同步；色板与源图统计分离；统计不重复计数 |

A 与 B 可并行；C 的稳定身份与版本接口是 D 的基础，蓝图外观原型可先行，正式保存不能绕过这个依赖。图片提色计算可独立推进。

正式开发默认不运行自动化测试套件；按工程约定做类型检查、网页/桌面构建与人工验收，并记录覆盖范围。验收始终用虚构示例，真实游戏资料接入仍是独立工作流。
