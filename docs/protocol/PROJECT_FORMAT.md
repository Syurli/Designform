# 策问项目文件格式 v1

这是提供给用户和任意 LLM 的独立读写约定。无需阅读策问源码。

## 入口与目录

项目根目录的 `PROJECT.md` 保存短 YAML 头部：`id`（稳定项目身份）、`name`、`format: 1`、可选 `description`、`example`。

当前稿在 `docs/`：`gdd/` 放总纲，`dd/` 放专项设计，`questions/` 放独立问题，`assets/` 放相对路径附件。只把当前任务需要的文件交给模型；历史按需读取。

文档使用 UTF-8。换行和未修改的文本保留原样。文件名可中文，文档 ID 和锚点使用字母、数字、短横线和下划线，项目内唯一。

## 文档身份与归属

GDD、DD 与问题文档使用简短 YAML 头部：

```yaml
id: dd-resources
type: dd
status: draft
system: system-resources
aliases:
  - 资源循环
  - Economy
sectionSystems:
  rest-cost: system-time
  crafting-choice: system-unassigned
```

`type` 为 `gdd`、`dd`、`question`；普通说明文件不需要进入图谱。`status` 为 `draft`（草稿）、`question`（待确认）、`confirmed`（已确认）、`archived`（已归档）。问题文档也可用 `open` / `answered` / `partially-decided` / `decided` 表示问询进度，图谱仅把尚未落实的问题标为待确认，不把答案自动变成正式规则。

应用 0.4 起在 `PROJECT.md` 的头部声明 `systems` 列表，每项包含稳定 `id`、`title`、可选十六进制 `color`；数组顺序即分类顺序。DD 的 `system` 指定主要归属；普通工作分组保存在编辑器工作区，不写入此字段。没有 GDD 也可以登记分类和写 DD。

`aliases` 是公开的文档缩写与别名列表，每项为普通文字；标题和别名只帮助用户寻找链接候选，不能单凭同名自动写入正式引用。选择候选后才写入相对 Markdown 链接。修改标题或别名不改变稳定文档 ID。

`sectionSystems` 是“规则锚点 → 分类 ID”的公开映射，可在 GDD 或 DD 的 YAML 头部为有锚点的章节单独指定分类。未列出的章节继承所在文档的主要分类；值为 `system-unassigned` 表示明确放入“未归组”，不会因所在文档有分类而重新继承。移除映射项表示恢复继承；映射为空时可省略整个字段。锚点必须与正文 `<a id="…"></a>` 一致，分类 ID 必须存在于项目分类目录，`system-unassigned` 为保留的未归组标识。

章节始终属于原 GDD / DD，文档到章节的目录关系不会因单独分类而消失；另外以分类归属关系供知识视图检索。重命名分类保留 ID，因此映射无需改写。删除分类时，必须在同一提交中迁移引用它的文档 `system` 和所有 `sectionSystems` 项，不能留下悬空分类 ID；原始正文与历史版本保持不变。

`PROJECT.systems` 字段存在（包括空列表）时即为唯一分类来源，缺少该字段才读取旧 `GDD.systems`。首次修改旧项目的分类，在同一版本中迁移登记、去掉当前 GDD 重复字段并写入 `minimumAppVersion: 0.4.0`；旧快照不修改。迁移后的项目使用 0.4 或更新的软件打开。

普通段落不必拥有 ID。需要引用的规则使用锚点和标题：

```markdown
<a id="rest-cost"></a>

## 休息成本

这里写规则正文及仍待决定的边界。
```

该规则的完整身份是 `dd-resources/rest-cost`。改标题、移动段落时保留 ID；复制为新规则时使用新 ID。

## 阅读优先与正式关系

策划正文先写玩家体验、规则、理由和例子。首段简述这份设计负责什么；可选 `summary` 头部字段用于悬停预览。普通阅读不要求读者理解内部 ID 或功能字段。

把联系融入自然语句，例如“玩家沿着[地图结构](dd/DD-001_地图结构.md)规划路线”。GDD/DD 中使用相对于自身位置的真实 Markdown 链接，具体规则追加 `#锚点`。显式正文链接直接形成引用关系，无需重复添加关联表。软件还会为正文中名称唯一的其他文档提供同名词阅读提示，但这种提示本身不新增正式关系。

仅在需要表达依赖、约束等额外语义时，在文末使用关联索引：

```markdown
### 关联索引
| 关系 ID | 来源身份 | 类型 | 目标身份 | 依据 |
|---|---|---|---|---|
| rest-time | dd-resources/rest-cost | 依赖 | dd-time/time-step | 休息需要明确耗时。 |
```

类型支持依赖、约束、关联、引用、替代。目标身份负责跨重命名定位，普通相对链接负责阅读；文档级目标只写文档 ID。反向联系由工具派生，不复制第二份关系。包含关系来自文档结构，不在这里手工制造循环。

来源身份必须属于本文件，文档级来源只写文档 ID，规则级来源包含锚点。既有的规则下关系表仍可读取；无需迁移已有项目。阅读器将识别到的功能表统一后置并折叠，普通设计表格仍原位展示。具体写法可参考随软件提供的 `cewen-collaborate/references/WRITING.md`。

星图以有效的 GDD 为中心。通常一个游戏保留一份主总纲；存在多份时优先 `GDD.md`，其次按路径稳定选择，已归档总纲不作为中心。无总纲时不凭空生成设计内容。

## 独立问题

一个可追踪问题一份 Markdown，多个 DD 引用同一问题。在问题内分开保存背景、可选方案、用户原始回答、模型解释、决定记录、文档落实。推荐选项不代表用户作答；改答追加记录，不润色历史原话。

最终采纳的规则写回相关 DD；问题文档保存依据和各 DD 的落实状态。编辑器私人笔记与阅读批注默认不公开，发布为问题后才进入文档。

## 历史与提交

`versions/V000001/docs/` 是当时的完整快照；每版有可读说明和校验清单。`versions/BASELINES.md` 保存命名基线；`INDEX.md` 是导航。不要直接修改旧快照。恢复旧稿会创建新版本。

每轮需要精确保留时显式提交并确认成功；文件监听只能捕获实际观察到的稳定状态。`.cewen/` 是编辑器工作区，模型无需读取或修改。只有索引可以重建，私人笔记、未提交草稿和恢复日志仍需备份。

## 编辑后的检查

### 0.5 图谱编辑与正文块

三维位置、二维位置、固定位置及阅读镜头保存在 `.cewen/` 的阅读视图中，三种视图分别记忆。拖动位置不产生公开设计版本。图谱的分类与手工关系变更先进入 `.cewen/` 草稿，点击保存结构版本或正文保存后，通过同一哈希校验事务写入公开 Markdown。恢复未提交草稿仍须核对其原始哈希。

分类实线来自 DD 的 `system`、总纲目录及 DD 内部章节归属。只有主要分类可以通过改接归属端口调整；目录和章节不能被当作普通关联随意断开。关联虚线区分手工关系索引、正文链接、问询目标等来源。同一端点对允许并存手工关系与正文引用；多处正文提及聚合为一条展示线，修改时选择具体出现位置。

正文编辑采用 Milkdown/Crepe，最终文件仍为 Markdown。文件头和文末关联索引由工作台保留；普通表格、图片相对路径和规则锚点仍在公开文件中。不能可靠往返的自定义 HTML 或扩展结构回退到源码；打开后不编辑，不应重排文件。图片附件先随私人草稿保留，正式保存时与正文一起提交。

0.5.1 的缩放图片使用标准 HTML 子集，例如 `<img src="../assets/map.png" alt="地图草图" width="480">`。`width` 为像素整数，保持纵横比，并受阅读容器宽度限制；仅支持 `src`、`alt`、可选 `title`、`width` 四类带引号属性。未缩放图片仍可使用普通 Markdown 图片。相对附件路径随导入、复制和迁移一起重写；其他自定义 HTML 不会静默转写。

### 0.6 开发中的统一设计文档

正文仍是 GDD/DD Markdown。一份文档可包含文字、图片引用、对白和色板；不因此创建独立“图片文档”“对白文档”或“色板文档”。对白与色板使用 `cewen-dialogue` / `cewen-palette` fenced YAML，稳定 ID 和完整字段由当前软件附带的 `docs/protocol/DESIGN_BLOCKS_0.6.md` 说明；只有本项目没有这份说明时，应向用户索取并核对后再改设计块。对白在正文内提供可点击选项的预览，专用页面编辑同一个源块；节点坐标只代表布局，显式连接字段才决定跳转。

公开排版位于 `docs/layouts/<文档ID>.json`，项目共享注释位于 `docs/annotations/<文档ID>.md` 与 `.ink.json`，均是原文档的伴随文件，不复制正文或出现在知识目录。读取、哈希提交与恢复规则由当前软件附带的 [公开伴随文件协议](DOCUMENT_COMPANIONS_0.6.md) 说明。私人注释、未保存草稿及个人镜头仍在 `.cewen/`，未经用户明确选择不交给外部 LLM。

文档可在 YAML 中设置 `color: "#RRGGBB"` 覆盖所属分类在目录和图谱里的提示色，删除此字段恢复继承；游戏色板不影响分类提示色。`PROJECT.md` 中的 `documentOrder` 以分类 ID 映射文档 ID 列表，仅决定目录顺序，不代表内容包含或设计依赖。旧项目可缺少上述新字段与伴随文件；读取时不应凭空补造文件或改变历史快照。当前 0.6 开发功能仍待完整人工验收和发布，不把本节当成发行确认。

保留身份，核对相对链接，不改历史目录；报告修改文件、设计理由和未决问题。涉及多文件时以明确批次提交，或在全部落盘后告知完成；不要把中间文件状态声称为整批已完成。

## 问询字段与批次

问题头部可包含 `round`、`baseRevision`、`targets`、`mode: single` 或 `multiple`。`follows` 指向前题；`when: {questionId, option}` 要求前题已回答且选项原文匹配，未满足时保留题目但暂不能作答。背景放在“问题背景”，选项以 `- A：`、`- B：` 开始。每次改答追加“回答 ID、时间、基础修订、选择及当时原文、用户自定义原话”，不覆盖旧答案。

模型提案包含 `id/title/reason/baseRevision/questionIds/dependencies/changes`。每项 change 是 `path/baseHash/text`；dependencies 至少记录所引用问题的文件哈希。来源问题候选保留用户原话，另写模型解释与决定；用户采纳时工具维护逐 DD 落实表。

多文件外部协作先使用 CLI/MCP `begin-batch`，全部落盘后 `end-batch`，以一轮说明发布版本；普通编辑器单文件修改可由监听观察后发布。没有运行中的服务时，后续打开只能记录最终存在的文件，不会伪造中间版本。

工作草稿保存在 `.cewen/drafts`，服务断开时浏览器另保留应急副本。草稿不等于正式文档，也不属于公开版本。不要将 `.cewen` 全部交给模型；需要共享批注时由用户显式发布或选择。
