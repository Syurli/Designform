# 0.9.3 项目复制后的占用恢复

## 原因与处理

原桌面锁只通过 `pid` 判断进程是否存在，没有使用记录内的 `expiresAt`，也没有登记所属电脑和目录。拷贝项目或进程号重用后，无关进程可能让已失效的锁持续报告 `PROJECT_BUSY`。

新锁登记 `pid`、随机 `token`、`kind`、桌面 `host`、`projectRoot` 与 `expiresAt`。桌面与网页统一使用 30 秒租约，每 10 秒更新一次。过期记录可回收；桌面还识别其他电脑、其他真实目录及已经退出的桌面进程。浏览器不推测电脑身份，继续使用浏览器互斥锁与租约。接管时再次检查令牌、租约时间及失效条件，避免删除刚刚完成续租的记录。

损坏或不完整的锁不会自动删除，仍保留 `LOCK_DAMAGED` 与人工处理说明。正常操作完成后，等待已经开始的续租完成，再只释放自己的令牌。所有者暂停或阻塞超过租约时，其他宿主可能接管，因此应避免同时让多个客户端长时间写同一项目。

## 本地性能版安装

本次安装版包含尚未提交的性能优化，仓库主线没有完整对应源码。保留安装版的文本 `resources/runtime/serve.js`，仅用当前源码编译出的 `fileLock` 替换其同名函数，并增加桌面主机身份。桌面入口从现有源码重新编译，引用保留的服务文本；预加载与桌面归档重新生成。原界面资源、性能服务逻辑、CLI 与 MCP 保留。安装前备份原桌面归档、服务文本与安装记录，不读取或修改原归档中的二进制内容。

本地构建脚本 `scripts/build-local-lock-repair.mjs` 接受安装目录作为参数，只生成 `.local/lock-repair/` 下的待安装文件，不自动覆盖运行中的安装。
