# 0.3.0 双版本发布检查

本轮采用类型检查、生产构建和人工界面/协议操作，没有运行自动化测试套件。

已实际执行：

- Windows 本机从新开发目录构建桌面前端、独立静态网页与 Node/Electron 运行时，类型检查通过。
- 独立网页生产预览从空项目中心创建虚构示例，显示 35 个条目与 84 条关系。
- 在网页编辑总纲并正式保存，界面确认已保存到 Markdown，版本条显示 V000001 和 V000002，修改说明为“网页生产版保存检查”。
- 网页项目中心使用文件夹选择按钮，明确标识正式磁盘项目与浏览器示例的不同保存位置；未使用远端策划存储。
- 桌面本地 API 在独立验收目录创建基础 GDD 项目，保存改动，读取两个版本的清单，均通过哈希校验，未要求恢复。
- 新建基础项目发现格式说明中的演示链接被当成真实缺失文件，已把该演示改为行内代码，避免空白/基础模板产生这条误报。
- Git 暂存检查排除了 `.local/`、node_modules、旧包、构建输出和私有研究资料；公开代码及文档中未检出本机用户名、绝对用户路径或常见凭证格式。

仍需用户环境复核：原生 Chrome/Edge 文件夹授权、权限撤回后的重新授权、网页与桌面交替打开同一真实磁盘项目、浏览器首次导入旧 SQLite 工作记录、物理断电及跨机器/显卡表现。本机内嵌浏览器的示例操作不能代替这些验收。真实游戏接入仍独立进行。

网页开发热更新曾中断活动文件操作，后续读取按文件租约返回忙碌提示，没有把未完成操作宣称为已保存。浏览器关闭页面后需等待租约到期；生产使用不要在正式保存尚未结束时关闭页面。最终保存检查改在独立生产预览完成。

发布地址、使用边界及 Git 工作流见 [双版本开发与发布](../双版本开发与发布.md)。
