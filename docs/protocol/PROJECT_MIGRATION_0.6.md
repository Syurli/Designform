# 0.6 开发中的项目接续与迁移说明


## 既有项目

`PROJECT.md`、`docs/gdd/`、`docs/dd/`、`docs/questions/` 与 `versions/` 仍是公开项目的基础。0.6 的设计块、公开布局与项目共享注释都是可选内容；旧项目没有 `cewen-dialogue`、`cewen-palette` 或 `docs/layouts/`、`docs/annotations/` 时，应继续按原 Markdown 阅读，不自动生成空白伴随文件、重写旧正文或改动历史快照。

首次编辑旧分类时，沿用现有受控迁移：将当前 GDD 头部的 `systems` 写入 `PROJECT.md`，同一提交删除当前 GDD 中重复的 `systems`，保留分类 ID、名称和颜色；历史版本原样保留。文档颜色 `color` 可省略，省略即继承所属分类。目录排序 `documentOrder` 可省略，缺少时使用稳定的默认顺序。分类、目录排序与实际设计关联分开保存。

对白与色板的正式文字、台词、选项、颜色值只保存在原 GDD/DD 的 fenced YAML 设计块中；布局 JSON 只记录位置与尺寸。图片继续在 `docs/assets/`，不迁成独立图片文档。项目共享注释按文档 ID 放在 `docs/annotations/`；个人注释和未保存草稿仍属 `.cewen/`。私人内容不能因升级被自动发布。详情见[设计块协议](DESIGN_BLOCKS_0.6.md)和[公开伴随文件协议](../策问_公开伴随文件协议_0.6.md)。

## 使用与回退边界

0.6 功能可能向公开 Markdown 添加新设计块或伴随文件。准备使用新工作台处理既有项目时，先保留完整备份，并在副本上检查正文、附件、分类与历史。旧版程序可能忽略新设计块或伴随文件，不应在新旧程序间同时编辑同一个项目。若需要回到旧版，使用升级前的项目副本；不能假定旧版保存会完整往返新结构。

正式发布前仍需人工核对：旧项目首次打开不改文件；分类迁移只产生一条完整新修订；新旧文档正文与资源链接一致；对白、色板、布局和共享注释经保存、重开、版本快照、导出、恢复后仍可读；历史快照不被原地修改。真实游戏资料接入另行验收，本轮只使用虚构示例。发布结果由最终验收记录补充。


验证结果见 [0.6 验收记录](WORKSPACE_REVIEW_0.6.0.md)。真实项目的接入仍在游戏项目对话中独立执行。
