## 界面与回答记录

使用独立工作区和虚构项目，四道同轮问题分别验证普通选项、依赖前题的回答、空白暂缓和问题反馈。旧格式带 `anchor: {documentId: ""}`，目标普通文档真实存在。

- 一题页面只显示简化标题、必要背景、候选和自由回答，没有等级、登记范围、入库说明、来源不存在大块警告或处理下拉栏。来源、历史及真正需要核对的信息默认折叠。
- 选择、文字输入、清除选择和独立问题反馈正常，已回答数量在输入后同步更新；前题选择在本机暂存后能开启条件题。
- 页面重开后本机回答及本轮汇总恢复。汇总自动包含本轮四题，普通回答两题、暂缓一题、反馈一题，无逐题二次勾选。
- 汇总末尾一次保存并复制：公开问题追加三个原始记录、空白题不写答案，只产生一个新版本。开场白包含实际版本、题数、问题与回答身份，并允许 MCP 不可用时用现有 CLI 读取。
- 再次复制后版本身份与原始记录数量均不变。已保存的问题反馈在题目页正确回显。
- 修改已保存回答并清空内容，汇总显示暂缓；保存时追加暂缓记录并保留旧原话，开场白同步列出该题与其他空白题。此项使用虚构项目，不修改真实游戏回答。

界面使用生产资源，在默认浏览器窗口人工检查。截图保留于本机开发缓存，不把私人路径或真实资料截图提交仓库。

## 发题协议

通过本地服务在虚构项目创建关联普通文档的 Quest，读取结果确认没有 `anchor` 字段。追加一题后确认问题关联真实目标且不继承空锚点。明确传入不存在的文档锚点返回 `ANCHOR_UNRESOLVED`，不保存该任务。旧题与既有原话保持原文件内容。

简洁问题规范同时提供给问询开场白、MCP 独立发题与 Quest 发题工具描述、协作 Skill 和使用说明；无需重启当前对话才能在新复制的开场白中取得规范。
