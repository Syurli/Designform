# 0.9.2 连接会话显示修正

## 问题与本机证据（2026-09-29）

用户报告一个 Codex 程序在连接面板出现多个客户端，并且顶栏显示未连接。代码确认 `createPresence` 为每个独立 MCP 适配器生成会话身份，服务按会话维护心跳；旧文案错误地将会话数量称为客户端数量。顶栏另有错误：只选择访问过当前项目的在线会话，未访问当前项目时即使通道连通也显示未连接。

只读本机核对时，五个在线策问 MCP 适配器通过各自的 cmd 父进程由同一个 codex.exe 启动；服务还有六条已断开会话记录。数字随客户端会话生命周期变化，不能据此推断有多个 Codex 安装或桌面窗口。在线会话当时仍使用 App/0.8.0 的 MCP 启动入口，桌面应用为 0.9.2-local-collaboration；仅更改桌面快捷方式不会更新已有 MCP 配置或进程。

## 行为规则

- 顶栏优先显示访问当前项目的在线会话，没有时显示其他在线会话；无任何在线会话才显示未连接。读取失败显示状态暂不可用。
- 当前项目访问单独写明，不能把尚未访问项目当作断开，也不能将其他项目的任务说成当前项目任务。
- 各接入开场白统一显示“在线会话”数量，不宣称检测到多个客户端程序。
- 详情按客户端名称、版本、模型名称、模型来源及在线状态合并卡片。分组是展示同类会话，不承诺它们来自同一个桌面实例；不同模型和断开状态分别呈现。
- 项目访问与最近活动从分组内全部会话汇总；离线记录不计入在线数。
- 服务端原始会话身份、心跳、并发任务和工作锁不合并，不修改项目、版本或客户端配置。

## 验证记录

本轮未运行自动化测试套件。`npm run build` 与 `npm run build:web` 均通过，包括类型检查；保留既有 Vite 配置、大体积块与动态导入提示。只读本机接口确认在线会话及断开记录；手工执行展示函数核对未访问项目仍在线、当前项目优先、未知型号分组、不同型号分别展示、断开不计数、全部离线及状态不可用分支，结果符合规则。

检查期间本地桌面服务已关闭，后续实时接口复核收到连接拒绝，不将其记为修正后的在线界面验收。仅同步前端文字资源至现用 `App/0.9.2-local-collaboration/resources/dist`，新增文件优先、HTML 入口最后更新；保留旧资源与所有运行时，不关闭或重新启动用户进程，不改 Codex 配置。安装来源追加记录到 `LOCAL_BUILD.json` 的 `frontendUpdate` 字段，原 ZIP 来源保留。原生界面、真实会话重连后的展示仍待用户下次打开确认；线上未发布。
