# 0.9.3 策问流程精简修订

## 作答与回答汇总

作答区仅显示题序、问题描述、必要背景、预设方案及自由回答。分类、文档、轮次由左侧目录承载，不在中央重复列出优先级、登记范围、入库说明或来源清单。旧问题正文不改写，显示时过滤已知协作模板段落；新问题按照下述编写规范生成。

选择方案或填写文字即算已回答，空白题保持暂缓。题目不合适时使用独立“题目有问题”按钮，并可在回答中说明原因。取消该标记恢复普通回答。去掉“本题处理”下拉栏、汇总中的逐题勾选与独立“提交”步骤。

回答输入与切页继续自动保存到本机，保持原问题身份及原存储键。汇总自动展示同一轮全部问题及回答；末尾的“复制开场白，请 LLM 分析”先一次保存本轮有效回答到公开问题 Markdown，并创建版本，再复制分析开场白。“预览 / 编辑开场白”使用同一保存流程。空白题不代选答案，不影响已填写题的保存；其他轮本机回答不参与。

改答以追加记录保存，保留此前用户原话。修改已保存答案后清空内容，本次记录为暂缓，不回填旧答案；再次选择或填写时自动恢复普通回答。重新复制已保存回答不会重复写入答案或创建多余版本。历史版本只读，临时示例交接前另存正式项目。真实题目或前题条件改变时保留旧回答：修改当前表单即可采用当前题目，旧题仍可在折叠区查看；移除的选项不擅自转成新选项。

## 来源与 MCP 生成

旧 Quest 创建流程无条件序列化锚点，未提供锚点时生成 `anchor: { documentId: "" }`；问题继承此值，界面又将其当成失效来源。已有文档本身并未丢失。

空锚点现在表示未指定摘录，不触发不存在或待复核提示。新 Quest 没有明确锚点时不写该字段，新问题不继承空锚点；明确锚点必须能够定位，服务拒绝失效或歧义的锚点。实际来源诊断与原始回答放入“查看依据与此前回答”，不以来源定位失败阻止用户表达。

问题的稳定身份、目标文档和轮次放在头部；问题背景只解释已有依据、尚未确定的具体设计边界。不得重复登记范围、优先级、入库目的、操作说明或来源文件位置。标题直接描述问题，不拼接 `Q编号 · P等级`。推荐方案要写收益和代价，不预选。自定义回答、暂缓和问题反馈由界面提供，不再作为额外选项写入问题模板。

## 分析开场白

开场白只给出项目、短版本号、已回答/暂缓/问题反馈数量、短项目号与本轮读取引用，不展开逐题 UUID、hash 或相关文档清单。直接使用 cewen_context 读取原始问答，以 Q/D 短号表示问题和文档，正文按需读取。只交接公开保存版本；没有 MCP 但可执行本机命令时用 CLI 的 answers 命令，无需重启宿主。提案可用同一短号，由软件补全保存基准。详见 [token 精简规范](ANSWER_CONTEXT_0.9.3.md)。

LLM 区分用户原话、理解推断、建议修改与待澄清项。先完成分析，再询问用户是否开启下一轮，等待明确答复。复制开场白、保存回答或采纳提案不自动授权续轮，MCP 心跳也不证明模型已收到消息。

## 验证

按工程约定不运行自动化测试套件。类型检查、桌面、网页和运行时构建通过；独立虚构项目的人工界面及协议检查见 [验收记录](QA_INQUIRY_FLOW_0.9.3.md)。真实项目正文、历史及未保存回答不作为测试夹具，也不进入公开仓库。
