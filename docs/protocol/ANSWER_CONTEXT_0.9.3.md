# 0.9.3 回答分析的 token 精简

开场白只保留项目名称、短版本号、回答数量、一个读取引用和简短分析要求。项目 UUID、逐题回答 UUID、文档 UUID 清单、64 位 hash、重复轮次名称不进入开场白。正式文件与历史的稳定身份不改写。

## 按需读取

```json
{"projectId":"P短号","documentIds":["@a10.轮次短号"]}
```

使用已有 `cewen_context`，直接读取公开保存版本 V10 的本轮问题与最后一次原始回答，无需先调用 status 或读取全项目。结果为 Markdown：Q1、Q2 表示本包问题，D1、D2 表示该版本文档；只给相关文档的短号与标题。保留必要背景、实际选择、原话、前题条件、暂缓与问题反馈；不返回选项全集、历次改答、关系图谱、私有工作区、文件哈希或空诊断。

需要 D1 正文时，把引用改为 `@a10.轮次短号/D1`。正文省略 YAML 头部与编辑定位标记，真实文档链接投影为短号；代码示例和外部链接不改写。原始正文不做摘要或截断。图片附件仍需单独读取。

短号绑定同一保存版本。后来改答不会混入已复制版本；重新复制才读取新版本。部分轮次通过简短题序范围限定，归档题仅在汇总明确包含时交接。未知、歧义或失效引用返回简短错误，不回退读取全项目。

没有 MCP 但可运行本机命令时，使用安装包 `策问CLI.cmd answers <项目短号> <回答引用>`，引用以引号包住。旧 MCP 已接受任意非空 documentIds，可直接透传新引用，无需为这次分析重启宿主。新版适配器及 CLI 原样输出字符串，不额外包 JSON 引号或美化空白。

## 无需模型传 hash 的提案

沿用 `cewen_propose`，字段结构不变：

```json
{"projectId":"P短号","proposal":{"id":"suggestion1","title":"完善教学","reason":"根据 Q1 的条件补充教学步骤","baseRevision":"@a10.轮次短号","questionIds":["Q1"],"dependencies":{},"changes":[{"path":"D1","baseHash":null,"text":"# 教学\n\n完整候选正文。"}]}}
```

实际提案 id 使用工具允许的英文字母、数字、下划线或短横线，例如 `suggestion1`。软件从该版本定位 Q/D，补全正式身份、路径与基础哈希；保留原 YAML 头部，把正文短链接还原为真实相对链接。来源题附加提案建议与理由，不改写原始回答或此前决定；用户审核采纳后记录实际落实。接口只返回提案 id、标题与状态，不重复候选正文或内部 hash。

读取过程不要求模型生成、携带或逐题核验 hash。软件内部继续处理文件冲突，仅保护相关问题、关联依据和实际修改文件，不把整个项目作为默认提案依赖。用户采纳属于人工审核提交；模型直接写入仍不能改写用户回答及决定。分析完成后等待用户明确同意，再发起下一轮。

本修订的检查见 [人工验收](QA_ANSWER_CONTEXT_0.9.3.md)。
