# 策问：双版本开发与发布

应用 0.7.1；公开文档格式 1、接口协议 1。网页和 Windows 桌面共用同一主线与项目格式。

## 使用入口

- 网页：[GitHub Pages](https://syurli.github.io/Designform/)。使用桌面 Chrome / Edge，点击“选择本机文件夹”授予读写权限。正式项目直接写入这个目录，GitHub 仅提供应用静态资源，不接收项目内容。
- 桌面：[Windows 便携包](https://github.com/Syurli/Designform/releases/latest)。解压运行“策问 Designform.exe”，无需 npm 或单独安装 Node。CLI/MCP 启动器和接入说明随包提供。
- 源码：[Syurli/Designform](https://github.com/Syurli/Designform)。公开仓库不包含用户游戏工程、私人草稿或本机授权句柄。

## 文件与能力

| 项目 | 独立网页版 | Windows 桌面版 |
|---|---|---|
| GDD / DD / 问题 | 授权目录内的 Markdown | 用户指定目录内的 Markdown |
| 历史、恢复、基线 | 项目 `versions/`，相同清单与哈希 | 同左 |
| 分组、批注、提案 | `.cewen/workspace.json` | 同左 |
| 索引 | 从 Markdown 解析到内存 | 可重建 SQLite 索引 |
| 最近入口 | 本机 IndexedDB 中的文件夹句柄 | 本机项目中心的入口记录 |
| 自动恢复点 | 当前浏览器专用本机存储，最近 7 份 | 本机项目中心，最近 7 份 |
| 文件协作 / 交换包 | 支持 | 支持 |
| 持续 MCP 连接 | 不支持；不会伪装在线 | 支持 stdio MCP，显示真实连接状态 |
| 运行要求 | HTTPS / localhost、安全上下文、支持文件夹授权的桌面浏览器 | Windows x64 |

网页版的“体验虚构示例”保存在浏览器专用本机存储（OPFS）。它不是用户磁盘中可见的普通文件夹。需保留时，在“交换”中导出到本机文件夹，再从项目中心打开该目录。清除网站数据会删除示例、自动恢复点和最近入口，**不会删除已授权磁盘项目的 Markdown 与 versions**。正式新项目必须选择本机目录，不会悄悄退回浏览器缓存。

不支持文件夹授权的浏览器可以尝试虚构示例；正式文件夹操作会提示使用 Chrome / Edge 或桌面版。不提供只在网页上假装保存成功的降级方式。

## 两端接续工作

1. 在当前端完成保存，关闭这个项目的页面或应用。
2. 在另一端选择同一个包含 `PROJECT.md` 的文件夹。
3. 核对项目名称、最新版本与当前稿；继续编辑。

网页只持有授权句柄，不知道 Windows 绝对路径；界面中的 `/folders/...` 是本机授权目录的内部定位符，不是网络地址。重新启动浏览器可能需要再次授权，点击最近入口会请求权限；失效时重新选择同一文件夹。

浏览器 Web Locks 只能协调同源网页；文件接口没有跨进程独占创建和通用原子目录重命名。因此**同一项目采用一个策问写入端，不在桌面与多个网站来源同时编辑**。文件租约与哈希冲突检查提供额外保护，不能代替这个使用边界。页面在写入中被关闭时可能需要等待约 30 秒租约到期，再重新打开并按恢复提示操作。编辑器草稿和事务日志保留在 `.cewen/`。

网页发布版本时最后写入完成清单，保留暂存副本直到成功。启动时可按清单补齐相同内容，遇到不同内容停止覆盖。两端均能处理这种中断的发布。没有完成清单的快照不会当成可信历史。

0.3.0 首次打开旧版项目时，把 `.cewen/workspace.sqlite` 只读迁移到 `workspace.json`，保留原文件。此后以 JSON 为准；旧版 0.2.x 不理解新的工作记录，请在备份后统一升级，不往返使用旧程序修改整理数据。公开 Markdown 和历史格式没有改变。

## 开发约定

- `main`：可发布的共享主线。
- `codex/<任务>`：独立功能或修复分支，合并前检查两种构建。
- `vX.Y.Z`：不可随意移动的发行标签，同时定位两端代码。
- `package.json` 和锁文件固定应用版本与依赖；`integration/mcp.ts`、发行说明同步更新。
- Git 记录软件源码的开发历史；游戏项目自己的 `versions/` 记录策划迭代，二者彼此独立。

开发环境为 Node.js 24。

```powershell
npm ci
npm run dev             # 桌面同源文件服务开发，默认 5173
npm run dev:web         # 独立网页开发，5174/Designform/
npm run build:all       # 类型检查、两端构建、桌面运行时
npm run package:win     # Windows x64 便携 ZIP
```

输出分别为 `dist/`、`dist-web/`、`runtime/` 和 `release/`，全部忽略，不写入 Git。`.local/` 保存迁移归档及本机验收资料，同样不上传。`npm run licenses` 在更新运行依赖后刷新随包附带的原始许可。

## GitHub 发布

- 推送 `main`：Pages 工作流构建 `dist-web/` 并发布到 `/Designform/`。
- Pull Request：只执行类型检查与两端构建，默认不自动执行测试套件。
- 推送 `v*` 标签：Windows 工作流校验标签版本，生成 ZIP 与 SHA256SUMS.txt，发布 Release。
- 桌面程序不自动更新；用户下载新包、解压到新目录后打开原项目即可。
- GitHub Pages 的页面缓存可能短暂保留旧资源，遇到发布切换可刷新；未实现离线 PWA 安装。
- 仓库公开可查看源码，但未擅自选择软件开源许可证。依赖许可在 `THIRD_PARTY_NOTICES.md` 与 `public/licenses/`。

平台依据：[浏览器文件访问说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[sql.js](https://github.com/sql-js/sql.js)。
