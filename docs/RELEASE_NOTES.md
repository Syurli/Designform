# 策问 Designform 0.9.4.2

修复 MCP 工具已发现但项目列表一直失败的问题。连接握手不再等待项目库刷新和完整历史校验，未选择项目时也能使用项目工具，服务重启后能恢复会话与心跳。

## 更新

- MCP/CLI 使用独立轻量握手；初始化与重连预算为 20 秒，轻量心跳预算为 5 秒。
- 项目列表只读取入口和历史清单，并发刷新共用一次读取，避免短时重试形成长队列。
- 连接错误保留具体阶段、脱敏路径、耗时与 HTTP／超时错误码，不再统一提示服务未运行。
- 项目中心保留最近 100 条脱敏时序，包含队列及历史清单耗时，便于排查；不写入策划项目。
- 保留 0.9.4.1 的回答自动记录、按轮汇总、前题导航及即时待答数量。

历史正文读取、恢复与版本发布仍进行完整校验。网络超时不会自动重放写入。

## 使用

完整解压 Designform-0.9.4.2-Windows-x64.zip，运行“策问 Designform.exe”。MCP 入口为同一目录的“策问MCP.cmd”。已有项目直接打开原目录，回答与历史继续保留。网页与 Windows 使用同一 main 源码及 v0.9.4.2 标签。

附件包含 ZIP、SHA256SUMS.txt 与 SOURCE.json，记录校验值和源码提交。项目格式继续支持 1 / 2，接口协议为 1。

## 验证

类型检查、两端构建及运行时打包通过。独立项目中心的真实 stdio MCP 人工验收包含未选项目的列表、项目身份与 V000049 历史读取、同一适配器经历服务停止／重启后的恢复、长握手与短请求独立超时及 HTTP 错误诊断。未在本机运行自动化测试套件。详见 [连接修订与验收](https://github.com/Syurli/Designform/blob/v0.9.4.2/docs/protocol/MCP_CONNECTION_20261008.md)。
