# 策问：下一轮创作与关系编辑方案

状态：待评审的产品与实施方案，尚未修改应用实现。日期：2026-09-22。

依据：当前 0.4.0 分支代码、用户本轮反馈、开源编辑器官方资料。用户已确认本轮需要飞书式富文本块文档：文字、图片、链接、普通表格、可拖动内容块。数据库式多维表格不纳入本轮。

最新交互约定：3D 中的拖动只负责摆放；2D 中的拖动承担实际的分类和关系编辑。以下方案已按此修订。两种视图的区别是操作职责，不是两份独立文档数据。

## 1. 本轮目标

让用户能够在策问里独立完成“写文档 → 建立联系 → 整理空间 → 保存并追溯”，并让 LLM 对同一份公开文档执行等价操作。

首要任务是替换现有正文 textarea、前移建立关联的入口、统一操作和保存规则。星图仍保持已认可的视觉形态与主视图切换节奏；新交互围绕现有形态扩展。

## 2. 当前实际情况

- 当前正文编辑仍是文本框，虽然隐藏了头部元数据，也有格式按钮，但不是块编辑器。
- 手动关系入口位于“文档信息与更多操作 → 管理关系”：添加关系进入草稿，保存版本后生效。目标选择仍容易暴露身份编号。
- 正文中的显式 Markdown 相对链接能够形成引用关系；阅读器自动识别同名词条、加下划线和浮层，并不等于建立了正式关系。
- 当前结构为“总纲 → 分类 → DD → 文档内规则条目”。没有真正的任意“父 DD → 子 DD”层级字段。本轮把所说的“子 DD”理解为各专项 DD。
- 3D 与关系分析中的线型尚未统一。星图没有手工节点拖动，但已经具备按视图缓存、导出和恢复布局的基础。
- 桌面菜单有基础复制粘贴命令，编辑面板有保存快捷键；还没有统一覆盖正文、星图、弹层与历史模式的快捷键体系。

这些是代码核查结果，不代表下面的方案已经实现。

## 3. 先把三件事分开

| 操作层 | 用户要表达的意思 | 保存位置 | 正式策划版本 |
|---|---|---|---|
| 空间摆放 | 我想把这个节点放在更好看的位置 | `.cewen/views/` | 不创建 |
| 分类归属 | 这份 DD 主要属于哪个设计系统 | `PROJECT.md` 分类目录、DD 的公开归属字段 | 保存时创建 |
| 设计关联 | 这两个设计如何相互引用、依赖或约束 | 正文链接，或文末可读关系索引 | 保存时创建 |

例如：在 3D 中把“移动系统”拖到“表现设计”星团附近，只是摆放变化；在 2D 中拖进“表现设计”的分类接收区并松手，则直接改变分类，不要求再去属性面板选择一次。拖向关联连接点则增加关联。

主切换继续保留“3D / 分层”。3D 用于全局浏览与空间整理；分层是 2D 结构编辑工作区。关系分析仍是选中节点后进入的次级页面，使用相同的 2D 接线规则，聚焦该节点的关联；不新增一个并列的顶级关系编辑页面。

一份 DD 默认一个主要分类。跨系统的联系用关联表示；个人收藏夹、工作分组和标签可以多选，保存在编辑器侧，不生成正式分类实线。这样分类、个人整理和设计语义不会混在一起。

如果以后支持真正的 DD 嵌套，应独立定义父文档、循环校验、分类继承和移动行为，不能把“建立关联”当作“建立子文档”。

## 4. 手工建立 DD 关联：三种自然入口

### 4.1 在写作时建立引用

输入 `[[`，或选中文字按 `Ctrl+K`，按标题搜索项目文档，也可以定位到带稳定锚点的章节。用户看到标题、分类和摘要，无须输入文件路径或身份 ID。

选择目标后，正文仍是自然语言，例如“移动中的攻击行为受武器系统约束”。其中“武器系统”变为可点击的文档链接。悬停显示摘要，点击可以打开；反向引用自动显示在目标文档的关系面板。

文件里保存标准 Markdown 相对链接；`[[` 只是输入入口，不要求普通阅读器或 LLM 认识专有语法。选择器解析真实路径，避免按标题拼出不存在的文件名。

“提到了某份 DD”默认只表示引用，不自动解释成依赖或约束。需要更强语义时，可以从该链接的小浮层明确设置。相关依据保留原句，避免强迫用户再写一次同义说明。

自动识别的同名词继续提供阅读导航，但浮层明确标注“同名词条建议”，并提供“建立正式引用”；显式链接标注“已引用”。同名文档有多个候选时由用户选择，不猜目标。

### 4.2 在节点或文档菜单中关联

右键 DD →“关联到…”→ 搜索另一份 DD。默认创建普通关联，关系类型和补充依据可选。也可“新建并关联”，打开直接写作的草稿。

更具体的关系以完整短句呈现：“移动系统 依赖 角色属性”，比“source / target / type”更适合策划人员。关闭或取消不会残留半条正式关系。

### 4.3 在 2D 中直接编辑结构和关系

在 2D 分层或次级关系分析中，选中节点后出现连接点。从关联连接点拖向另一节点，或将 DD 拖到已显示的关联线端接收点，形成普通关联的草稿。小浮层允许改成引用、依赖、约束等类型，并显示方向句。

2D 的节点本体可以直接拖入分类接收区以改变归属，也可以拖到空白处整理布局。操作意义由清楚标出的有效落点决定，不能沿用“节点本体永远只摆放”的规则。端口和接收区使用形状、线型及“归属 / 关联”提示区分。菜单入口与拖动调用相同操作，熟悉手势不是使用前提。

3D 不启用接线吸附、拖入分类改归属或晃动断线；这些拖动始终只调整空间位置。“编辑结构 / 关系”入口定位到对应的 2D 节点，避免操作时因深度和遮挡误接。

## 5. 连线表达

| 类型 | 线型 | 方向与说明 |
|---|---|---|
| 总纲 → 分类 → DD → 规则条目 | 实线 | 表达结构归属；平时可以不画箭头，选择时显示“属于” |
| 普通关联 | 虚线 | 无箭头，表示相互相关 |
| 引用、依赖、约束、替代 | 虚线 | 带方向；悬停或选择显示完整关系句 |

“A 依赖 B”的箭头指向 B；不能将同一个箭头再解释为修改影响的传播方向。若以后做影响分析，应明确展示该分析方向。

节点颜色继续表达分类。线型和文字承担关系语义，不能只依靠颜色，尤其要保证浅色模式可读。

总览默认突出分类结构；选中节点时显示相关虚线。提供“结构 / 关联 / 全部”显示筛选，关系分析页显示更完整的关联，避免为了区分线型而让全图始终布满虚线。

同一对文档在正文中被引用多次，总览合并为一条引用线，详情显示“引用 3 处”。不同语义类型仍可展开查看，不能只因端点相同就合并成一个没有来源的关系。

普通关联只保存一份，双向查看由索引推导。取消某一处正文链接，其他引用仍存在时，引用线继续显示。

## 6. 编辑器选型

这类开源项目提供的是可嵌入的编辑器组件。策问仍需负责文档工作区、分类、关联、版本、附件和主题整合。

| 候选 | 匹配点 | 主要取舍 | 建议 |
|---|---|---|---|
| Milkdown + Crepe | Markdown 工作流、块编辑菜单、拖动内容块、图片、表格与链接操作；MIT | 仍需适配策问链接、附件、元数据隔离和未知语法保留 | 优先验证 |
| Tiptap | 编辑器核心 MIT，自定义节点和交互扩展能力强 | 需要更多界面开发；官方 Markdown 扩展目前标为 Beta | 强定制备选 |
| BlockNote | 现成的现代块编辑体验 | 官方明确 Markdown 导出有损，完整保存倾向块 JSON；许可按包区分 | 不作为当前首选 |
| Vditor | MIT、中文支持、所见即所得、HTML 转 Markdown、图片粘贴 | 更接近 Markdown 编辑器，策问需要的块交互仍需定制 | 快速接入备选 |

依据：[Milkdown Crepe 官方文档源码](https://github.com/Milkdown/milkdown/blob/main/docs/api/crepe.md)、[Crepe 功能定义](https://github.com/Milkdown/milkdown/blob/main/packages/crepe/src/feature/index.ts)、[Milkdown 源码与许可](https://github.com/Milkdown/milkdown)、[Tiptap Markdown 状态与限制](https://tiptap.dev/docs/editor/markdown)、[Tiptap 核心许可](https://github.com/ueberdosis/tiptap/blob/main/LICENSE.md)、[BlockNote Markdown 导出说明](https://www.blocknotejs.org/docs/features/export/markdown)、[BlockNote 各包许可](https://github.com/TypeCellOS/BlockNote)、[Vditor 官方仓库](https://github.com/Vanessa219/vditor)。

推荐先给 Milkdown + Crepe 做小范围适配验证。是否采用，以策问文档往返保存和实际写作体验为准，不能只看演示页面。

以上能力参考官方当前文档及主分支源码，正式接入时需要核对并锁定具体发行版本。Crepe 默认图片处理可返回临时 blob 地址；策问必须替换上传回调，接入项目附件持久化，不能直接照搬演示配置。

### 本轮支持的正文能力

- 标题、段落、加粗、斜体、删除线、列表、引用、分隔线、代码块、普通表格。
- `/` 插入内容块、拖动块排序、选中文字后的轻量格式浮层。
- 粘贴截图、拖入图片、添加图片说明；粘贴链接或选中文字插入链接。
- 内部 DD / 章节链接、悬浮摘要、反向引用、当前文档大纲。
- 中文输入法、正文撤销重做、草稿恢复、查找替换和源码模式。

图片落在项目 `docs/assets/`，正文使用相对路径。新增附件先随草稿保留，保存时与正文进入同一个版本；删除正文图片时，不删除历史版本仍需要的附件。

剪贴板带实际图片数据时直接接入本地附件；仅有外链时保留链接并区分“外链图片”和“已保存本地”。网页端受跨域或来源权限限制时明确说明，不能显示一个假成功的本地副本。

办公软件复制的文字、列表、基础表格、图片优先保留语义。复杂页面排版、合并单元格、嵌套布局和任意颜色样式不保证原样复刻；遇到无法可靠表示的内容应保留原文或提示简化，不能静默丢失。

### 文档工作区排版

使用主工作区内的文档页，给长文足够高度；星图右侧仍可快速阅读，进入专注编辑时可以展开工作区。

```text
顶部：项目导航                         LLM 状态 · 主题 · 系统操作
文档栏：当前位置 / DD 标题             草稿状态 · 保存版本 · 更多
左侧可收起：项目目录                   右侧按需展开：大纲 / 引用与批注
正文：可直接编辑的标题
      分类标签 · 设计状态

      正文与内容块；块边缘出现拖动柄，选区出现格式操作
      文中 DD 链接可以预览和跳转

底部轻提示：草稿已保留 / 已保存版本
```

不在正文之前排列路径、ID、关系表、版本说明输入框。文档属性放在“更多”；保存说明默认自动生成，可以补充。关系概览按需展开，功能性索引继续在 Markdown 文末，不打断正文阅读。

## 7. Markdown 和编辑器数据的边界

正式权威源继续是 `.md`，编辑器内部可以使用自己的树结构或 JSON 做运行态，但不另存一份需要单独维护的正式正文。

| 内容 | 处理方式 |
|---|---|
| 元数据、稳定身份、未知字段 | 编辑器外层保留，仅明确修改对应属性时更新 |
| 正文、图片引用、DD 链接 | 块编辑器负责，保存为可阅读 Markdown |
| 显式语义关系 | 优先依托正文链接；额外语义存在公开文末索引，界面折叠 |
| 三维坐标、固定位置、镜头、布局撤销 | `.cewen/views/` 等编辑器私有数据 |
| 未提交正文、关系和附件 | `.cewen/drafts/`，不视为可随意清除的缓存 |
| 正式内容与关系变更 | 当前 Markdown 和公开 `versions/` 快照 |

打开文档而未修改时不重写文件、不生成版本。修改一处尽量只改对应范围；遇到未知 Markdown、显式锚点或扩展块时保留原文，不能将不认识的部分直接删除。这个要求属于选型门槛。

样机若无法可靠保留某种语法，该块显示原文占位并允许源码编辑；无法安全分离时，该文档暂用源码模式，禁止有损保存。不能为了换编辑器而静默规范化整篇旧文档。

文档更名保留稳定身份；修改文件路径时同步修复受影响引用。外部 LLM 修改或移动文件后重新解析，发现断链或同名歧义时提示，不将其悄悄绑定到另一份文档。

## 8. 全软件快捷键

按当前焦点理解用户意图，正文、星图、弹层、历史阅读共用命令定义。桌面菜单、按钮和键盘走相同命令，避免 Electron 与网页各执行一次。

| 快捷键 | 行为 |
|---|---|
| Ctrl+C / X / V | 正文内按系统习惯复制、剪切、粘贴，支持富文本及图片；输入框保持原生行为 |
| Ctrl+S | 保存当前项目明确处于编辑中的文档及关系改动，形成一个版本；没有改动则不造空版本 |
| Ctrl+Z | 撤销当前操作区域的最近操作，正文与布局不会相互抢夺 |
| Ctrl+Shift+Z / Ctrl+Y | 重做 |
| Ctrl+A | 正文内全选正文；画布获得焦点时选择当前可操作的节点 |
| Ctrl+K | 正文内添加、修改外部链接或项目 DD 链接 |
| Ctrl+B / Ctrl+I | 正文加粗 / 斜体 |
| Ctrl+F | 当前正文查找；全项目检索另有明确入口 |
| Esc | 优先取消拖动、接线、浮层，再清除选择；不连续触发多个层级 |
| Delete | 有焦点且明确选中关系时取消该关系；选中节点时进入归档/删除操作，不从后台误删文档 |

2D 画布获得焦点时，可定义 Ctrl+C 为复制选中 DD 的结构化内容，并同时提供普通文本链接；Ctrl+V 创建副本，生成新身份，并正确处理所选文档之间的引用。默认不沿关联线递归复制其他文档。

2D 的 Ctrl+X 表示待移动，原文档先不删除；到明确的目标分类粘贴时完成移入并保留原身份。没有有效目标时显示选择分类，Esc 取消。跨项目粘贴第一阶段只做复制，不做隐式跨项目删除。3D 的复制以文档链接和阅读内容为主，结构性的复制、移入入口定位到 2D 执行；正文输入框始终按文本焦点处理。

画布复制粘贴需要作为独立功能验收，不能仅靠拦截键盘宣布“全局支持”。历史文档只允许复制，禁止剪切、写入或保存覆盖历史。

补充约束：识别富文本 `contenteditable`、选中文本和中文输入法组合状态。应用已定义且当前焦点可执行的命令，处理后阻止浏览器默认行为，例如保存时不再弹出网页另存为；未处理命令交回宿主，操作系统不可覆盖的组合保持原样。菜单显示当前可用快捷键，不可用时禁用并说明原因。

## 9. 3D：全局浏览与空间摆放

- 节点本体拖动、空白拖动镜头。达到小幅移动阈值后才判定为拖拽，避免点开文档就误移节点。
- 3D 默认沿当前镜头平面移动，保留拖动起点的深度；旋转观察角度后可从另一方向调整。开始拖节点时暂停镜头控制，结束、取消、失焦时可靠恢复。
- 总纲继续锁定中央。拖动分类节点可带其成员整体移动，拖动单份 DD 只移动该 DD。
- 邻居轻微避让，只影响局部；同时考虑文字标签遮挡和节点间距。固定的节点作为障碍，不被挤走。
- 放手后短暂收敛停止，不让整张图持续漂移，也不每次操作重新随机布局。
- 拖过分类星团、节点或连线不改变归属，不建立关联；快速晃动也不触发断线。
- 3D 与 2D 分别记忆布局。3D 的摆放不会修改 2D 的分类层级或文档结构。
- 一次拖动及其挤开的所有邻居是一条撤销记录。Esc 恢复本次拖动前全部受影响位置。
- 提供“固定位置、整理当前分类、恢复自动布局”。这些是视图操作，不创建策划版本。

Houdini 官方提供连接点接线、摇动断线、拖入线中插入节点等操作；其网络线可以表达数据流、父子或依赖等不同语义。策问借鉴手感，同时保持文档关系的意义明确。[Houdini 连接操作](https://www.sidefx.com/docs/houdini/network/wire.html)、[Houdini 节点摆放](https://www.sidefx.com/docs/houdini/network/layout.html)。

## 10. 2D：具有实际意义的节点编辑

2D 默认是可直接操作的结构工作区，不要求用户先打开通用关系表单或额外切到另一套编辑模式。拖动经过有效目标时显示具体结果，松手直接执行为草稿；移动途中不提交，取消或无效落点不产生半完成的关系。

### 拖动行为表

| 2D 操作 | 放手后的结果 | 数据变化 |
|---|---|---|
| DD 拖进另一个分类的接收区 | 修改主要分类，原分类实线改接到新分类 | 公开归属字段进入草稿 |
| 拖动分类归属实线的分类端，接到新分类 | 与拖入分类完全等价 | 替换归属，保留 DD 身份及既有虚线 |
| 将 DD 的分类归属线端拖到空白处，出现“取消归类”提示后松手 | DD 进入“未归组”，文档继续存在 | 清除主要分类字段，进入草稿 |
| DD 拖到关联线端的接收点，或从关联端口拖到另一 DD | 新建普通关联，可就地改类型 | 显式关系进入草稿 |
| 拖动单条显式关联的端点，接到另一 DD | 替换这一关系的起点或终点 | 精确修改对应关系 |
| 将单条手工关联线端拖到空白处，出现“解除关联”提示后松手 | 删除该条关系，保留两端 DD | 对应关系删除进入草稿 |
| 节点拖入可编辑的普通关联线中段 | 展示改接或插入候选，选择明确结果后执行 | 一组关系变更作为一次操作 |
| 快速晃动 DD | 解除高亮的可断开手工关联 | 批量关系修改进入草稿 |
| 拖到无接收标记的空白处 | 整理 2D 排版，邻居避让 | 只保存 2D 布局 |

“拖进分类”以分类容器、栏头或清楚显示的接收区为准，不凭鼠标离哪个分类节点更近来猜。进入目标时预览“移入表现设计”，放手即可改变；不弹出再次填写分类的表单。

归属接收点使用实线提示，关联接收点使用虚线提示；同时提供文字标签，避免只靠颜色区别。没有有效目标时不吸附；普通 DD 本体不自动被识别为父文档，防止无意引入未支持的 DD 嵌套。

空白松手的意义也由拖动对象区分：拖节点本体是摆放；拖一条已有可编辑线的端点，则可以解除该条关系，必须在松手前显示明确的解除提示。尚在新建中的线拖到空白处只取消新建。总纲到分类、DD 到内部规则等结构线不套用“取消归类”，历史关系不可编辑。

单纯排版仍有必要，但只是空白落点的行为；2D 的核心用途是直接改结构与关系。类内视觉顺序本轮仅是布局，不暗中改写正文顺序。

### 接线与改接

从连接点拖到目标，或将现有线端拖到另一节点，可以新增关联或更换目标。悬停目标时显示吸附反馈、关系类型与完整句子。放开前可以 Esc 取消。

直接改接首先适用于单条手工关联。正文引用须定位具体原句后改目标；一条线聚合多个引用位置时先选择修改哪些位置，不默认改掉全部。结构实线的改接执行分类变更命令；章节所属文档等其他结构关系不能套用分类操作。

2D 中，从端口拖线或把节点拖入线端接收区都能形成接线操作。悬停显示吸附和改动预览，松手直接执行；擦过线条或非接收区域不触发。一次操作只能产生一种明确意图，接线与分类接收区冲突时只高亮一个目标。

新增接收点与已有关系端点必须分开：拖节点到标为“新增关联”的端口或新连线端，增加一条关系并保留旧线；抓住既有线端再拖动，才是改接这条关系。悬停预览写出新增或替换，不能仅靠视觉接近判断覆盖哪条线。

对普通关联 A—B，可以提供“改接为 A—C”或“经 C 关联，即 A—C—B”的具体预览，由用户选择后一次执行和撤销；插入时明确旧关系是否被替换。无方向的普通关联没有足够依据自动判断哪一端应该被换掉。

对“A 依赖 B”，把 C 放在中间不能直接推导出“A 依赖 C、C 依赖 B”。依赖、约束等关系默认只支持明确改接；如以后增加关系链插入，需逐条确定新关系语义。分类实线也不接受把一份普通 DD 自动插成父文档。

### 快速晃动

作为 2D 内的高级效率功能，提供启用开关；启用后直接适用于 2D 结构与关系工作区，无须为每次晃动再进入单独模式。3D 始终不响应断连手势。

第一阶段仅解除用户手工建立的普通关联。识别到手势时高亮待解除的虚线、显示数量，松手提交为一次草稿操作，可立即 Ctrl+Z。

断连不删除 DD、不把邻居自动串联。断连成立后，本次拖动不同时触发插线或改分类，避免一次松手产生两种相互矛盾的操作。

分类实线、正文引用、问题关联不跟着晃动删除。解除正文引用必须修改其来源句中的链接，保留文字；不能只从画布藏掉一条线，否则下次解析会重新出现。

“依赖、约束、替代”等语义较强的关系先保留菜单删除和端点改接。后续可配置是否纳入晃动，不能把第一次晃动变成清空设计结构的动作。

所有手势都有右键菜单等价操作，并在降低动态效果的系统偏好下减少动画。

## 11. 保存、撤销与版本

正文、分类与关系的变动共用项目编辑会话。修改立即保留草稿；顶部显示“有 2 篇文档待保存”等范围。Ctrl+S / 保存版本将当前明确参与编辑的改动和附件作为一个批次提交。

2D 里拖入分类、接线、改接或断线就是编辑文档数据，不能仅修改图上的线。每条可编辑关系必须能定位到公开文件中的实际来源；批量改动先核查所有来源文件，再形成同一事务。刷新和重开后仍从 Markdown 重建一致结果。

以前关闭并留存的其他草稿、导入候选和 LLM 提案，不因本次保存被自动采纳。无变化不产生新版本。单纯摆放自动保留到视图数据。

图谱可以即时投影草稿关系，但需要标注“待保存”；保存后才成为正式版本中的关系。文档与图谱不各自维护两份互相冲突的关系草稿。

撤销尚未保存的操作直接恢复草稿。撤销已经保存的内容产生新的待保存修改，下次保存创建补偿版本，历史仍然保留。布局撤销不写文档版本。

2D 每次语义拖动，把归属/关系变化与该次避让、位置变化组成一条撤销记录；不能第一次 Ctrl+Z 只把节点移回去，却保留已经改掉的分类。正文使用自己的文本撤销，3D 使用摆放撤销。

2D 与正文修改同一份项目草稿，切换到 3D 时立即反映节点分类色、归属线和关联线，并保持待保存状态。3D 自动布局中的节点可以向新分类平滑迁移；已固定节点保留位置并更新归属表达。无关节点不重新排布。切回 2D 保留选中节点和编辑上下文，继续沿用已验收的视图过渡节奏。

历史快照保持只读，可以临时转动和查看图谱，不能直接改线或改分类。版本切换仍根据该版本的正式文档重建结构及关联；历史布局可取保存的视图或确定性布局，不能借当前摆放伪造历史内容。

## 12. 实施任务

### 第一阶段：关系模型与编辑器验证

1. 为图谱边补充可追溯来源：分类字段、章节归属、正文引用及位置、显式索引、问题目标。修改关系时先定位来源，不依赖临时 ID 前缀猜测。
2. 统一分类、关联的命令与修改预览，支持同一端点对的多个引用来源。
3. 验证 Milkdown + Crepe 对现有 Markdown、图片、表格、DD 链接、锚点和中文输入的保留能力。通过后锁定依赖、打包本地资源并维护第三方许可。

### 第二阶段：优先交付手工创作闭环

4. 新文档工作区与块编辑器，接入草稿、源码模式、图文剪贴板和项目附件。
5. 标题检索式 DD 链接、反向引用、右键关联；自动同名词与正式关系明确区分。
6. 统一快捷键、保存范围、正文撤销和桌面菜单；同步网页文件夹授权路径。
7. 3D、分层与关系分析统一实线/虚线和方向文字。

### 第三阶段：图谱直接编辑

8. 3D 纯摆放拖动、局部避让、固定位置；3D / 2D 分别保存布局。
9. 2D 拖入分类直接改归属、端口接线、线端改接、草稿同步与整次撤销；作为核心交付，不能仅做可拖拽的展示图。
10. 2D 普通关联线插入预览、画布复制粘贴、可关闭晃动断连；明确修改来源与版本保存范围。

所有阶段保持桌面与网页同源实现。先验证公开文档的可靠性，再增加高级手势；本轮不更换星图引擎，也不同时引入完整实时多人协同、数据库多维表格或无限 DD 嵌套。

### LLM 协作同步

新操作需要在 MCP / 文档协议中保持相同语义：文档内容修改、分类修改、关联增删和布局修改分开。LLM 完成设计关联不需要读取三维坐标或策问工程源码。

文档“请 LLM 完善”、关系面板“检查依赖”、选区“帮我改写”等入口准备带当前任务、文档及版本的专用开场白。不能重新打开通用场景选择器，也不把复制开场白显示成已连接。

更新项目自带协作说明与 Skill：优先自然正文链接、功能索引靠后、不要按词语相似性擅自宣称依赖、保存前核查外部修改。多文件变更采用同批提交和版本/文件哈希检查；冲突时保留双方修改供处理。
