# 策问：文档即画布与综合游戏设计站

日期：2026-09-23。状态：设计提案，未实施到 0.5.1，不修改既有项目和历史。

后续补充见同目录《策问_工作台视觉与交互整合方案_20260923.md》。对白按用户最新确认保留“文档内选项预览 + 独立编辑按钮/编辑页面”，只优化预览样式和蓝图式编辑界面；开发顺序以补充方案的 A～D 阶段为准。

## 1. 最终方向

用户只需要一种设计文档；文档本身就是可排版的设计画布，不单独新建图片文档，不再插入独立画板后跳转编辑。

同一张文档纸面可组织文字、图片、表格、便签、参考来源、台词与分支，并提供注释、关系、问询与版本。GDD、DD、美术设定、对话稿、关卡说明等是用途和模板，不是相互隔离的文件格式或应用。

用户最初选择正文排图与独立画板分开，后进一步要求文档统一，并提出文档本身作为画布。本方案采用最新方向：统一文档自由排版，同时保留章节、阅读顺序和 Markdown 可读性。

## 2. 文档即画布的具体含义

同一份内容有三个彼此独立但共同保存的属性：

1. 章节归属：它属于哪一级标题，决定折叠、目录和整章操作。
2. 阅读顺序：它在文章或对白中应该先后如何阅读，决定 Markdown、搜索与 LLM 上下文。
3. 空间位置：它在纸面摆在哪里、显示多大、是否与别的块并排。

拖动图片在纸面换位置，默认只调整空间位置。拖到明确的段落插入线，才改变阅读顺序；拖到另一章节的接收区时，显示目标章节并在松手后改变归属。不能按屏幕上距离某个标题更近，就默默把它移入该章。

文档默认纵向延展、适合阅读，可调整纸面宽度；需要横向组织参考时可以扩大工作范围。阅读顺序提供按需显示的编号。提供“整理摆放”“对齐”“等距分布”和“防止重叠”；允许用户明确叠放图片，不强制把所有参考排成表格。

正文文字可直接编辑。块边缘或手柄负责移动、缩放，文字区域负责选字，避免拖动与文本选择争抢输入。连续正文保持自然输入，复杂区域才显示块边界。

## 3. 纸张与章节

### 3.1 笔记本底纹

- 提供浅方格、横线、点阵、素纸，建议默认很淡的方格。
- 浅色继续柔和灰蓝或灰米底；深色使用低对比细线，不使用刺眼纯白。
- 底纹只帮助阅读和对齐，不增加厚阴影、污渍等装饰。横线间距随正文行高调整，表格和密集内容不叠加干扰线条。
- 纹理浓度、阅读宽度、大纲开关属于个人偏好；不改策划正文、不生成设计版本。普通导出默认素底，展示导出可选择保留底纹。

### 3.2 标题带内容折叠

折叠范围从当前标题之后到下一个同级或更高标题之前，包含所有子标题、图片、对白、便签及其空间布局。嵌套折叠保留各层状态。

折叠章节后，其后的章节自动向上排列；展开时恢复内部相对布局。以章节局部坐标保存自由排版，避免折起上文后下文仍停在原始绝对坐标、留下大片空白。

支持当前章节、全部展开/收起、展开到指定级别。目录跳转、搜索和关联跳转会自动展开相关祖先。隐藏内容仍参与搜索、保存、版本与 LLM 阅读。

光标位于折叠范围内时先移到标题；删除折叠标题要明确区分“仅删标题”和“整章删除”。整体移动章节会连同正文、图片和注释锚点一起移动，保留撤销路径。

## 4. 图片、对白与灵感都属于这一份文档

### 4.1 图片与参考

粘贴或拖入图片后即可在文档上摆放、等比例缩放、对齐、并排或叠放，选中时才显示对应工具。支持说明、来源、替代文本、替换与打开原图。

可以将某组图片和便签收为一个可移动组合，但不会因此产生独立文档。图片下方能写“借鉴点”“不采用的部分”和相关设计链接，保留参考的用途。参考、候选方向和已采纳设计需区分，导入图片不等于采纳。

同一附件可在不同位置引用。移动或删除一个展示块不自动删除原始图片；清理未使用附件另行显式处理。全项目的资料浏览只是对文档中图片、来源、标签的聚合索引，不另存一份图片文档。

### 4.2 对话编排

用户直接在当前文档加入对白：角色、台词、玩家选择、条件、跳转、结束点。正文默认提供可点击选项的对白预览；通过独立编辑按钮进入蓝图式对白编辑页面。预览和编辑操作同一套内容，不各存一份。

初版用简单声明式条件和临时预演变量，不执行任意脚本。提供缺失跳转、孤立节点和不可达结尾提示；有意循环是合法设计，不一律阻止。

对白的流程箭头与全项目知识关联线分开表达。对话节点位置不是剧情顺序，正式先后关系由显式跳转决定。

### 4.3 便签与设计说明

便签是正式文档内容，适合灵感、设计理由、待验证猜想。它与注释有区别：便签参与正文导出与 LLM 默认上下文，注释主要用于讨论。需要时可把便签转换为正文或问询，而不是继续扩大页面上的临时内容堆积。

### 4.4 图片提色与独立配色区块

两种入口指向同一种文档内配色功能：选中图片 → 提取配色；插入 → 色板。后者可以从空白手工配色，也可以从已有参考图提取；不新增色板文档类型。

首版建议支持：

- 默认提取 5 个代表色，可调整到 3～12 色；全图或用户框选区域提取。
- 将相近像素聚合为颜色群后展示代表色和近似面积占比，不逐个统计 JPEG 中微小色差。
- 显示 HEX、RGB、HSL，可复制色值、增删/合并颜色、调整顺序、锁定或手动修改。
- 将候选采纳为“设计色板”，为每色标明主色、辅色、强调色、中性色或自定义用途，以及色彩意图。
- 手动排除背景或裁去黑白边；默认不擅自忽略大面积背景，因为背景也可能正是场景主调。
- 区分“按面积的主色”和“视觉强调色”。后一项属于启发式推荐，不把其权重标为面积百分比，不声称算法可以客观确定作品情绪。
- 图片上点选取色作为补充，方便保留面积很小但对美术有意义的颜色。

用户调整后的设计色板与原图统计保留各自身份。人工改色后不能继续把原百分比标为新颜色在原图的占比。需要重提取时先生成新的候选，由用户选择更新，不能覆盖已经定调的结果。

后续可支持多张图片对比：默认按每张图片等权整理风格倾向，另提供按总采样像素合并的统计；明确两种权重，避免大图天然压过小图。可增加冷暖、明度和饱和度分布、多个方案对比，以及导出色板 PNG / 色值列表；引擎颜色资源导出另行适配。

本机提色建议流程：从项目附件读取并解码，按图片方向及用户区域采样，缩小到有限像素量；忽略完全透明像素，半透明按明确的 alpha 权重统计；转换到感知色彩空间聚类，合并近色，按有效采样权重计算近似面积占比。大量运算移到后台工作线程，避免阻塞正文输入。首版明确使用 sRGB 色值；面积、冷暖和情绪判断分别展示，不承诺专业印刷校色。

色板正文以可读表格保存色值、用途、说明及参考占比；关联源图片路径与内容哈希，记录取样范围、色彩空间、算法版本和人工调整。布局仍只存尺寸位置。原图替换后提示来源已变，原图删除仍保留色板及来源失效说明。

用户可对单个色标或整个色板注释，LLM 协作入口可带入色值、用途、明确分享的参考图，帮助比较几种定调方向。算法提色不需要 LLM；将配色解释成设计建议才属于可选协作任务。

## 5. 注释体系

注释可锚定文字选区、整块内容、图片中的矩形区域或文档空白点。点位使用相对坐标，图片缩放和块移动时随目标移动。

默认在旁边显示小标记；点击展开讨论。支持回复、已处理/重新打开、筛选未处理、跳回原文。阅读模式可隐藏标记，注释不挤占正文布局。

两种可见范围：

- 私人注释：保存在编辑器私人数据中，默认不提供给 LLM。
- 项目注释：公开保存并纳入项目历史，可显式带入协作上下文。后续多人能力可复用，但本期不承诺实时多人协作。

注释依赖稳定块身份，不只记坐标。文字选区同时记录引文、上下文与偏移；正文改变后重新校准，匹配不可靠则标为“原文已变化，待重新定位”，不能贴到看似相同的另一句话上。被批注的图片被替换或内容块被删除时，保留线程并提示目标变化。

注释可以提取为待讨论问题、形成修改提案；只有采纳后才更新设计正文。“标为已处理”不等于设计方案已采纳。

## 6. 一站式工作台的整体组织

### 6.1 界面分工

- 应用栏：项目库、真实 LLM 名称与状态、主题、设置。
- 项目目录：统一文档列表与分类、标签、工作分组；全项目搜索。
- 主工作区：知识空间或当前文档。知识空间保留 3D/分层和次级关系分析；文档提供直接写作、自由排版和折叠大纲。
- 右侧上下文面板：当前选中内容的属性、注释或关系；按需打开。
- 项目工具：问询、版本、资料聚合、试玩记录与导入导出。

文档窗口成为持续工作的主要区域，工具栏根据当前文字、图片或对白选择变化。避免新增所有功能后再把按钮永久堆在页顶。

新建仍叫“新建文档”。可选用途模板：总纲、系统设计、关卡、角色、叙事、视觉参考、试玩复盘、自定义；模板只预置段落或区块，之后可以自由混合。

### 6.2 核心工作闭环

收集灵感与参考 → 写明设计意图 → 组织规则与对白 → 建立相关设计联系 → 与 LLM 深挖 → 用户回答 → 提案与采纳 → 记录版本 → 试玩反馈推动下一轮。

全项目资料视图负责找素材，知识图负责理解跨文档关系，问询负责做决定，版本负责解释变化。它们共同指向同一文档内容。

默认只将文档和用户明确选定的知识条目加入全局星图，避免每张图、每句对白都变成节点。便签摆放、图片重叠和画面箭头不自动推断成正式依赖。

## 7. 本地文件与任意 LLM

统一文档继续以 Markdown 保存全部设计文字、台词、图片路径、说明、阅读顺序、章节与显式语义关系。需要被定位、排版或批注的块使用稳定身份，不为每个普通字词制造元数据。

自由布局需要坐标、尺寸、层级等额外信息；建议作为该文档的公开配套排版数据自动维护。它不是用户要另建的文档，也不重复存正文。公开项目注释同样通过稳定身份关联，不藏进私人缓存。

建议路径（待实现时定稿，不自动迁移旧项目）：

    PROJECT.md
    docs/
      gdd/游戏总纲.md
      dd/驿站设计.md
      questions/...
      assets/...
      layouts/<文档ID>.json       公开排版信息，界面不显示为独立文档
      annotations/<文档ID>.md     已公开的注释线程，默认不混入设计正文
    versions/...
    .cewen/...                   私人注释、折叠、镜头、光标、草稿

模型只读 Markdown 即可理解内容；排版任务才按需读取布局信息。导出普通 Markdown 时按阅读顺序给出完整正文、图片与说明、线性对白，外部阅读器不支持自由排版也能使用。

公开排版属于创作成果，与 Markdown、附件、公开注释按同一次保存和快照提交；复制、移动、导出、版本恢复必须一起处理。折叠、缩放视角和底纹不参与设计版本。

版本查看可显示正文变更、图片替换、对白分支变化和排版变化。设计变更与纯排版变更提供分别筛选；历史始终只读，恢复创建新版本。

## 8. LLM 协作

保留“专用开场白 + 真实连接状态 + 用户采纳”的原则：

- 完善章节：带当前章节、约束、相关 DD 与未决点。
- 整理参考：带明确分享的图片和说明，要求指出借鉴点与不确定处。
- 检查对白：带角色目标、台词、条件、分支，检查动机与断点。
- 讨论注释：只带用户选中的线程，不能默认读取私人批注。
- 复盘试玩：区分用户原话、观察、推断与拟改规则。

无视觉能力或未收到图片的模型不能假装读过图；文件协作不伪装为 MCP 在线。软件的格式说明、Skill 和工具接口须能单独读懂，模型无需查看策问工程。

## 9. 技术路线与开发分批

当前 Crepe 支持连续正文、块拖动、图片处理，策问已有 Markdown 往返保护和版本事务。标题折叠和纸张外观可以在这个基础上完善。

自由二维排版是编辑器架构升级，不能靠给现有 DOM 加绝对定位完成。需要外层统一块与章节容器管理身份、摆放、选择、注释、撤销；富文本编辑器负责文字编辑。读写都投影到同一 Markdown 权威模型，禁止画布和正文各维护一份副本。

关键交互须先做技术原型：文字跨块选择、中文输入法、拖放与复制粘贴、撤销边界、外部 Markdown 修改、折叠后布局、注释重定位。块为空或尚在输入法合成时不能被布局刷新重建。

Ctrl+A/C/X/V 按当前焦点区分文字操作与画布块操作；Ctrl+S 始终统一保存；文本输入与块移动接入可预测的撤销体系，不能一次撤销到另一处用户看不到的内容。

开发顺序建议：

1. **0.6：可靠的设计笔记本。** 底纹、完整标题折叠、大纲、图片拖序/对齐/尺寸、稳定注释锚点；配色块与本机提色可作为独立模块同期推进。先验证统一文档模型和完整 Markdown 往返。
2. **0.7：文档直接自由排版。** 章节布局容器、可移动文字/图片/便签、多选与对齐、公开布局随版本保存。无独立画板入口。验收自由排版与线性导出的语义一致。
3. **0.8：对白与资料闭环。** 同文档对话编排、分支预演、资料聚合、试玩记录和场景化 LLM 协作。

这些版本号用于划分候选范围，不是工期承诺。先让单用户本地工作流可靠，再考虑实时多人、云同步与引擎专属导出。

## 10. 参考与本次边界

官方参考：

- [Milkdown Crepe API](https://milkdown.dev/docs/api/crepe)：块拖放、图片上传和缩放的基础。
- [ProseMirror 折叠示例](https://prosemirror.net/examples/fold/)：节点视图与装饰状态控制折叠。任意 Markdown 标题范围、选择保护与版本语义仍需策问实现。
- [MDN Canvas 像素读取](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/getImageData)：浏览器可读取指定区域像素与指定色彩空间；直接处理远程图片需考虑同源限制，策问优先使用已导入的本机附件。

本轮交付方案和交互示例，未改动 0.5.1 正式编辑器。示例可切换底纹、收起章节、移动参考图片/文字块、显示阅读顺序、操作示例注释与对白分支，以及查看候选颜色和修改设计色板。提色百分比为明确标注的演示数据，不是真实图像算法结果；不代表完整自由排版编辑器或提色算法已完成，也不读写真实项目。
