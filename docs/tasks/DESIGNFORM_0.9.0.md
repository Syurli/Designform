## 1. 版本目标与不可变原则

### 1.1 一句话目标

让用户和 LLM 在同一项目内，自由组合各类创作模块，通过“文档／卡片 → Quest → 决定与提案 → 素材生产 → 排演 → 再次 Quest”的流程推进复杂创作。

### 1.2 必须遵守的产品原则

1. **预设仅初始化内容。** 预设提供初始目录、示例、常用模块排序和教程推荐，不授予或剥夺功能。所有受支持模块在所有可编辑项目中均可发现、插入、读取、引用和提出修改。
2. **文档类型不形成权限边界。** 战斗 DD 可以放分镜；剧本可以放地图；地图可以同时服务于剧情线、战斗设计和分镜。只读历史、未授权私人内容、未安装的扩展等技术／权限状态仍应被尊重。
3. **同一内容一个权威来源。** 正文、表格、卡片、图谱、分镜网格、排演与 MCP 都是同一份数据的不同入口，不能各自存一份可独立漂移的台词、地图或镜头描述。
4. **共享源与使用实例分开。** 共享地图保留一份基础数据；战斗、剧情、镜头各自的标注和呈现配置属于使用实例。修改使用实例不应污染共享源。
5. **创作信息与界面排版分开。** 镜头顺序、排演时长、声音起止是正式创作信息；窗口位置、展开状态、缩放和卡片摆放不是。公开文档布局仍沿用受控伴随文件。
6. **过程、决定和落实分开。** 用户已回答、用户已确认决定、提案已采纳、全部目标已落实不是同一状态。
7. **人工确认必须来自实际操作。** LLM 可以建议、发布问询、暂存提案，不可通过自报字段批准自己、伪造用户答案或静默启用收费任务。
8. **离线主流程可用。** 无模型连接时仍能编辑、阅读示例、回答问题、播放已有素材和导出生产包。示例不得伪装真实模型在线。
9. **软件开发与真实项目隔离。** 公开仓库和测试只使用虚构资料与授权素材。

### 1.3 本版必须完成与明确不做

| 必须完成 | 明确后置 |
|---|---|
| 全项目通用模块注册、插入、引用和筛选 | 可执行第三方插件市场 |
| 独立 Quest 工作区、多轮状态、文档内问题与 MCP 增量续轮 | 对任意外部聊天客户端的无条件自动唤醒 |
| 角色、地点、地图、剧情线、场次、分镜、配音资料的最小实用模块 | GIS、完整游戏关卡编辑器、三维导演台 |
| 图片＋声音的二维分镜排演、轻量时间调整 | 专业剪辑、调色、复杂音频工作站、口型生成 |
| 通用生产包、一条可验证的桌面 ComfyUI 图片任务链路、配音任务导出与音频回导 | 同时接入大量生图／TTS 厂商、自动替用户选模型 |
| 媒体版本、回导预检、依赖变化提示 | 自动删除未引用媒体与历史压缩 |
| 新预设、新独立示例、综合示例、可跳过／快进的操作教程 | 完整 MP4 渲染出口；本版优先可复现排演包 |

“接口已留出”“按钮存在”“静态示意图”“构建通过”均不能替代相应用户流程的验收。

## 3. 统一内容与引用模型

### 3.1 核心对象

| 对象 | 职责 | 不应承担的职责 |
|---|---|---|
| Project | 身份、公开分类、入口文档、全局规范 | 根据创建预设封锁模块 |
| Preset | 初始化目录、文档、示例和推荐工作流 | 持续控制项目权限或改写已有内容 |
| Document | 可读正文与内容组织；可含任意注册模块 | 为每种项目另建文件引擎 |
| ModuleDefinition | schema、解析、编辑、渲染、索引、上下文、迁移与依赖提取 | 保存某个角色或镜头的实际内容 |
| ContentObject | 一份有稳定身份的角色、地图、场次、镜头等内容 | 在每个视图复制一份数据 |
| ReferenceInstance | 某处对对象的引用及本地显示／覆盖层 | 暗中改写被引用对象 |
| Quest / Question / Round / Decision | 设计目标、问题、轮次、回答、决定及来源 | 作为游戏内任务执行引擎 |
| PlaybackSequence | 选定路径、镜头出现实例、画面时长、音频及字幕对齐 | 保存重复台词或三维摄影机真实坐标 |
| MediaAsset / MediaVersion | 不可变媒体文件、元数据、候选与采用关系 | 每次正文保存物理复制全部媒体 |
| ProductionBatch / Job | 生产基准、提示词、输出要求、任务状态与回导映射 | 任意代码执行或无限重试 |

### 3.2 权威来源规则

- 每个 ContentObject 只保存在一个所属文档的受控结构块中；独立卡片可使用一个专门文档作为容器。对象目录／搜索索引均可重建，不成为另一份权威数据库。
- 默认引用跟随当前已保存对象；排演审阅快照、生产任务和历史阅读使用固定版本引用。
- 至少区分 `projectId`、`documentId`、`objectId`、`subObjectId`、`instanceId` 和可选修订。显示名称、镜号、文件名、数组下标不能替代身份。
- “引用”与“复制为独立副本”必须是两个操作。复制生成新 ID 并重映射内部引用；引用仍指向原对象。
- 对象移动文档保留 ID；改名保留 ID；复制、导入预设和跨项目复制执行可审查的 ID 映射。
- 跨项目实时链接不作为本版必需能力。跨项目交换先复制相关依赖并映射为当前项目身份。
- 允许创作语义关系成环，禁止归属树成环。递归展开引用必须有访问集合与深度／预算上限。
- 删除被引用对象前展示影响；用户可改指向、解除引用或保留明确的缺失标记，不能静默删除使用方内容。
- 未识别模块保留原始源码，显示受限预览／诊断；禁止读写往返时丢弃未知块或未知字段。
- 项目可选择入口文档。游戏总纲是可用模板，不再是剧本或综合项目的必选根。无总纲时可使用 PROJECT 入口组织图谱。

### 3.3 共享地图必须满足的例子

```text
地点卡：雾港货运站
  └─ 地图卡：货运站平面图（唯一地图源）
       ├─ 战斗 DD 中的引用 → 掩体／交战／撤离覆盖层
       ├─ 剧情线中的引用   → 角色路线／剧情触发点覆盖层
       └─ 分镜中的引用     → 人物／机位示意覆盖层
```

基础底图、通道和共享地点身份只维护一次；战术标记与摄影机示意不相互覆盖。覆盖层可以在需要时提升为可共享对象，但默认归属于其使用上下文。

地图裁切或底图替换需记录变换或标为需要复核，不能把原标注按像素错误地贴到新底图。没有明确标尺时只表达归一化二维示意坐标，不推断真实距离。

## 4. 数据与兼容策略

### 4.1 文件契约先行

本次新增正式时间序列、Quest 可交接数据和媒体对象引用，建议在 T090-01 冻结新的**项目格式 2**，而不是把不兼容内容写进格式 1 后仍宣称完全兼容。

- 0.9 继续以旧解码器读取格式 1；未升级项目不在打开时被自动改写。
- 使用新能力前提供“在副本升级”的预检、空间估算与清单，原目录保留。
- 旧 `versions/` 保持原始字节与旧格式语义，新历史通过清单识别格式，不重新编号或重签旧历史。
- 老应用打开格式 2 必须清晰拒绝编辑；不得悄悄忽略新媒体、Quest 或镜头并覆写项目。
- MCP 旧工具保持兼容或提供明确适配。当前 `context.project.entry` 的形态曾发生变化，新任务必须冻结输出 schema，不能继续静默漂移。

### 4.2 建议目录职责

```text
PROJECT.md                        项目身份、入口与格式
 docs/                            可读创作正文与注册结构块
   quests/<id>/                    Quest 目标、轮次与决定记录
   questions/                      问题权威记录；文档内只是引用视图
   layouts/                        公开文档排版（不存台词和正式时间轴）
   annotations/                    公开视觉注释与共享说明
   media/                          受控媒体索引与采用引用
   production/                     可共享任务清单与经过脱敏的结果信息
 assets/objects/<sha256>/           新格式中的不可变媒体对象
 versions/                         文本／结构快照＋媒体引用清单
 .cewen/                           私人草稿、UI 视图、缓存、临时队列与凭证
```

上述目录属于**待实现的新格式**。必须同步文件白名单、事务、扫描器、备份、历史验证、复制与导出，不得只创建目录就绕过现有安全规则。`docs/quests/` 的层级记录不能以一般正文节点无差别铺满图谱。

完整排演包必须包含锁定序列所需的全部媒体版本；“仅当前稿包”和“含历史包”分别按可达性收集。新格式媒体对象不允许自动垃圾回收；空间清理只提供预览与手工确认，旧历史引用的对象不能删除。

- [ ] 复用单选、多选、自定义、暂缓、前提不成立、条件题、改答追加和草稿恢复。
- [ ] 独立问题可关联到 Quest，已有 Question ID 与原始回答不得重建丢失。
- [ ] 分别维护作答状态、决定状态和落实状态；Quest 可以因取消／仅讨论无写回而关闭，但必须显示真实理由。
- [ ] 依赖变化或用户改答使有关候选标记为需复核，不自动覆写答案或宣布结论仍有效。

**验收：** 对同一设计目标完成三轮问答；第二轮允许用户改答；第三轮生成同时修改 DD、分镜和地图覆盖层的提案，部分采纳后显示准确未落实目标，补齐后才完成落实。

## T090-06：MCP 增量协作与续轮

### 拟定工具面

| 组 | 拟定能力 |
|---|---|
| 能力发现 | `cewen_capabilities`、`cewen_modules`：返回模块 schema、协议、读取／写入／媒体能力及限制 |
| 对象访问 | `cewen_objects`、`cewen_read_object`：按对象／子对象分页读取，不要求获取整篇巨型文档 |
| Quest | `cewen_quests`、`cewen_quest_create`、`cewen_quest_read`、`cewen_quest_publish_round`、`cewen_quest_events` |

| 排演与生产 | 读取排演结构、时间冲突、缺素材与任务状态；生成生产计划和受控回导预检，不开放任意路由代理 |

最终工具名称可在契约阶段合并，但能力、权限与验收不得缺失。

### 任务要求

- [ ] 所有修改携带 requestId、Quest 基准、相关公开文件／对象哈希；既要校验直接修改文件，也要校验决定依据。
- [ ] 增量事件包含游标、新回答、改答、提案状态、依赖变化；定义分页、去重、游标失效、重连和全量重同步。
- [ ] 事件以实际提交为依据，不在数据库里维护一份可能与正式文件矛盾的“已完成”状态。
- [ ] 默认仅返回本 Quest、本轮变化及显式依赖，图片与音频二进制按需读取；不得每轮发送全部 `docs/` 和全部历史。
- [ ] 明确 `recoveryRequired`、未封版、未知模块及不完整读取状态，不静默截断。
- [ ] 兼容有订阅／自动编排能力和无自动接续能力的宿主；无能力时提供带真实 Quest／修订／游标的“继续这一轮”请求。
- [ ] UI 显示真实“等待用户”“等待模型调用”“生成中／正在接收”“离线”，不能以 MCP 心跳等同于正在生成。
- [ ] 不默认加入代填答案、批准提案、任意磁盘读取／命令执行、恢复应用等工具。
- [ ] 私人工作内容仅通过用户显式共享进入上下文；客户端能力声明不是数据权限授权。

MCP resources 的订阅通知是可选能力，且上下文处理由宿主决定；Sampling 也需要客户端声明支持。因此“提交答案后所有客户端自动继续生成”不是可无条件承诺的协议行为。依据：[MCP Resources](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)、[MCP Sampling](https://modelcontextprotocol.io/specification/2025-11-25/client/sampling)。

**验收：** 通过真实 stdio 客户端完成三轮；退出后换会话可从游标接续；相同请求重试不重复发布；无订阅客户端仍可用续轮请求；未授权私人记录不被返回。

- [ ] 失败重试限次；不确定是否已扣费／已入队时先查询，不盲目重发。
- [ ] 通过 manifest/jobId/objectId/panelId/lineId 匹配；文件名只作为辅助。无 manifest 支持人工映射，不猜目录排序。
- [ ] 核对 MIME、hash、目标身份、依赖基准、路径、大小与解码；无法匹配／过期／损坏单独列出。
- [ ] 回导成功只创建候选版本。采用动作才改变正式引用，并进入同一版本事务。
- [ ] 同一结果重复回导可识别，既不覆盖现有采用，也不制造重复候选。
- [ ] 有效结果与异常结果分组预览，用户可选择只接收有效部分；事务边界和结果清单必须一致。
- [ ] 源素材已变化时显示“基于旧版本生成”，可保留但不自动替换锁定排演。
- [ ] 生产队列和凭证不作为公开文档；可交接的任务元数据经过脱敏。

**验收：** 一个批次混合正常图、第二候选、过期结果、错 ID、重复结果和一条配音；系统正确分类，用户采用后各视图一致，未采用候选不改变正式排演。

最低内容规模是验收夹具目标，不是产品内容数量限制：

| 内容 | 目标 |
|---|---|
| 文档 | 不少于 18 份；包含项目入口、游戏总纲、至少 6 份专项设计、剧本／影像总览及协作资料 |

| 地图 | 2 张示意地图；其中一张以同一 objectId 服务战斗 DD、剧情线和分镜 |
| 剧情 | 1 条主线与至少 2 条可选分支，显式选择一条作为排演路径 |
| 分镜 | 4 个场次、12 个镜头、18 个连续画面，包含一镜多图与多候选图区别 |
| 声音 | 至少 16 条台词、8 条可听的授权／自有演示配音，另含明确缺失的音频状态 |
| 排演 | 一段 60～90 秒二维排演，包含跨镜台词、停顿和字幕 |
| Quest | 至少 4 个：待回答、多轮中、部分落实、已完成；保留至少 2 个独立问题 |
| 素材任务 | 图片和配音两个生产包；包含有效、过期、重复、错位、待人工映射的回导样本 |
| 版本 | 可查看的一次初稿、一次决定采纳、一次素材采用／排演调整的真实示例版本链 |

演示语音应可理解，不能用提示音冒充配音。离线预置轮次标记为“示例回放”，不冒充当前用户回答或真实在线模型输出。主流程中缺失的素材有清楚占位；损坏／恶意回导夹具置于独立练习包，不污染默认示例。

### C. 综合示例的主线验收故事

1. 用户从综合示例打开战斗 DD，查看货运站地图上的交战区域。
2. 打开剧情线，看到同一地图及不同的角色路线覆盖层。
3. 打开分镜，看到同一地图及摄影机示意覆盖层。
4. 用户对“逃离出口是否提前暴露”发起 Quest，完成多轮回答。
5. LLM 提出涉及战斗 DD、剧情节点与两个镜头的修改，用户先部分采纳再补齐。
6. 仅对受影响画面和台词导出生产任务，导入演示结果，选择候选。
7. 播放排演，在一个具体镜头暂停并提出节奏 Quest。
8. 查看历史，能找到决定、实际修改、素材来源和采用版本。

**验收：** 以上八步可在无外部生成服务时使用明确标注的演示包走通；真实 MCP 另做一次非回放验收。
