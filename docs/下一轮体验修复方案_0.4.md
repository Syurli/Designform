# 策问下一轮体验修复方案（拟 0.4）

状态：0.4 功能分支已实施并进入验收；本文保留设计目标，实际实现和覆盖以 `protocol/AUTHORING_REVIEW_0.4.0.md` 为准。只使用虚构示例；真实游戏接入继续与软件开发隔离。

## 目标与优先级

让用户在策问中直接写策划、组织设计、邀请模型协作。当前最大的阻力在于人工创建链路与技术信息外露，应先解决写作流程，再完善星图表达。

| 用户反馈 | 已确认的原因 | 本轮方向 | 优先级 |
|---|---|---|---|
| 1. 项目目录要选择，不能要求手填 | 文件夹选择只接入了独立网页；桌面仍显示路径输入框 | 所有目录操作统一使用选择器与位置摘要 | P0 |
| 2. 悬臂粒子随 DD 数量变化，带轻微动画 | 当前固定 4200 个悬臂粒子，无自身运动，版本变化不调整粒子预算 | DD 驱动的星尘规模、局部生长与低速流动 | P1 |
| 3. 浅色分类节点不明显 | 沿用粉彩色并统一压暗；星图、目录和图例映射不一致 | 两套语义分类色，强化真实节点，统一所有视图 | P1 |
| 4. 总纲核心仍僵硬 | 核心实体及叠加光团很大，缺少柔和变化 | 收紧实体与光晕，固定中心，微弱呼吸 | P1 |
| 5. 接入给 LLM 开场白，不给用户配置 JSON | 当前要求复制配置并手改安装路径 | 自动生成可直接粘贴的接入/协作开场白 | P0 |
| 6. 常见游戏 DD 分类应可选 | 系统类别仅来自已有 GDD；基础项目只有“体验方向” | 通用类别库、游戏类型预设、自定义分类 | P0 |
| 7. 新建流程繁琐，像表单，暴露内部字段 | 先填写表单并提交占位文档，再进入整份 Markdown 源码编辑器 | 直接写作、渐进呈现属性、星图上下文创建 | P0 |
| 8. 从零构思太简陋，所有协作环节都需要开场白 | 目前只有零散接入与操作入口，缺少完整的创作起点 | 常见开场白库＋游戏设想组装器；一份设想连接手动创建和 LLM 协作 | P0 |

“P0”表示阻碍首轮使用，优先完成；不代表当前文件已经丢失或软件无法运行。

## 1. 文件夹选择贯穿所有目录操作

新建项目显示“项目名称、保存位置、选择文件夹、开始创建”，保存位置用简短可读摘要展示，完整路径可按需查看。桌面打开系统原生文件夹窗口；网页打开浏览器目录授权窗口。复制项目、打开、导入和导出使用同一交互约定。

- 选择父目录后显示即将创建的独立项目文件夹名，避免用户误以为项目散落在父目录。
- 记住上次有效位置；取消选择保留此前位置，不清空用户输入。
- 在实际创建时验证写权限；不可写、权限撤回、同名或目录移动时给出对应处理方式。
- 手填路径从主流程移除；仅有特殊需要时再提供辅助方式。
- 桌面壳通过限定的目录选择接口返回选择结果；不向页面开放任意操作系统命令。
- Electron 桌面与它打开的本地浏览器也应覆盖；宿主可用时由同源服务请求原生选择器，不能把网页授权句柄误当成 Windows 路径。

原生目录选择能力可使用 Electron 的 `dialog.showOpenDialog`，选择 `openDirectory`。[Electron 官方文档](https://www.electronjs.org/docs/latest/api/dialog)

## 2. 从新建表单改为写作工作台

推荐流程：

```text
＋ 新建 / 星图右键 / 分类下新建
    ↓
进入写作页：直接写标题和正文，可选分类与大纲
    ↓
草稿自动保留，可退出后继续
    ↓
保存 / Ctrl+S：正式创建 Markdown，并生成一个版本
    ↓
星图中出现对应 DD，局部生长；之后继续编辑同一文档
```

普通新建默认是专项设计 DD，记录问题和编辑总纲拥有明确入口。已经有主总纲时优先提供“打开总纲”，不因为误点默认创建第二个核心。

### 页面布局

采用主工作区内的写作页面，正文保持较大的可用高度与舒适行宽。项目目录可收起；章节导航和文档属性按需展开。减少大模态窗口中的标题、说明、分割线及重复选择控件。

```text
┌─────────────────────────────────────────────────────────────────┐
│ 策 问    当前项目                             LLM 状态    主题   │
├─────────────┬───────────────────────────────────────────────────┤
│ 项目目录    │ 专项设计  [套用大纲⌄] [章节]          [保存版本]   │
│ ＋ 新建     ├───────────────────────────────────────────────────┤
│             │                                                   │
│ 分类 / 文档 │  旅途中的补给 ← 直接编辑标题                       │
│             │  [资源与经济⌄]  [草稿⌄]                           │
│ 未完成草稿  │                                                   │
│             │  设计目标                                         │
│             │  让玩家在继续前进与补充资源之间作出选择。           │
│             │                                                   │
│             │  玩家如何获得补给                                 │
│             │  在这里继续写规则、理由与例子……                   │
│             │                                                   │
├─────────────┴───────────────────────────────────────────────────┤
│ 草稿已保留 / 已保存 V000003                    更多 → 文档信息   │
└─────────────────────────────────────────────────────────────────┘
```

- 标题、正文是第一层；分类、设计状态是小型中文标签；路径、稳定身份与完整源码由“更多”进入。
- 格式工具保留常用项，按选区或需要出现；关系与文件路径操作不再占满常驻工具栏。
- 默认是阅读友好的正文写作视图，支持熟悉的 Markdown 快捷输入；高级用户可切换源码。
- 模板提供写作提纲和空白提示，不把“请填写……”保存成已经成立的设计规则。
- “本次修改说明”自动给出简短默认值，保存时可选编辑，不长期占据底部大块空间。
- 引用沿用自然文句、变色下划线、悬停摘要与点击跳转。额外语义关系继续后置管理。

### 数据与草稿的完整约束

截图中的 ID、type、status、system 有些属于公开文档身份与语义字段，不能全部删掉或移入私有数据库。它们保留在简短文件头，由软件维护，默认写作界面隐藏。相机、布局、私人笔记、未提交草稿继续在 `.cewen/`，不进入公开正文。

- 新文档可以提前分配稳定身份和候选文件名，但第一次正式保存之前只持有私有草稿。
- 增加“未完成草稿 / 继续写作”入口。重启后能找回尚未生成正式文件的新稿。
- 新稿附件先随草稿暂存，首存时与 Markdown 同批提交；不提前生成孤立附件及版本。
- 对已有文档编辑继续以打开时哈希判断外部冲突，保留用户稿、当前稿与基准稿。
- 切换写作/源码视图、打开再关闭，不能自动重写文件或产生版本。
- 修改正文保留未知 YAML 字段和注释、稳定 ID、锚点、普通表格、功能关系表和附件相对路径。
- 对尚未支持的 Markdown 片段保留原文，不通过整篇富文本转换丢失内容。
- 问询文档中的原始回答与决定记录不能因重新排版被删改或重排。

实现采用原始 Markdown 的结构解析与局部修改，先交付稳定的正文写作与往返保存，再扩展复杂富文本能力。

## 3. 分类：设计领域与游戏类型预设

“文档种类”“设计分类”“工作分组”各自承担清楚的职责，普通创建只默认 DD 并提供可选分类。

| 项目 | 含义与行为 |
|---|---|
| 文档种类 | 总纲、专项设计、设计问题 |
| 设计分类 | 这份 DD 主要负责的设计领域，公开且可供 LLM 理解 |
| 游戏类型预设 | 帮用户挑选适用的类别和大纲，不替用户确定玩法 |
| 工作分组 | 如“本周待讨论”，用于个人整理，不改变文档的正式系统归属 |

首批候选类别：玩法与体验、操控与镜头、战斗与技能、角色与成长、世界与关卡、任务与叙事、物品与装备、资源与经济、AI 与行为、界面与引导、音画与反馈、存档与进程。联机、社交、运营与商业化按需启用，不默认塞入每个项目。

游戏类型预设候选：通用、动作、角色扮演、射击、策略战术、模拟经营、解谜探索、卡牌与构筑、叙事；允许组合选择。选择预设只改变推荐选项，实际选用并保存的内容才进入项目。

允许自定义、重命名、设置分类色与排序。默认一个主要分类，跨系统关系继续通过正文链接表达，避免复制多份 DD。类别删除时处理成员迁移，不连带删除文档。

不能要求用户先写 GDD 才能分类。建议增加项目级分类登记入口，最小公共定义随 `PROJECT.md` 携带，DD 继续引用稳定的分类 ID。没有总纲时显示“尚无总纲”，不生成冒充用户设计的中心文档。

- 项目级清单存在时（包括空清单）即为唯一来源；字段不存在才读取旧 `GDD.systems`，不把两处逐项混合。
- 旧工程只读打开不迁移；升级时保留分类 ID，迁入项目文件并去掉当前 GDD 的重复定义，以一个新版本记录，历史快照保持原样。
- 项目文件、分类和相关 DD 的改动同批校验、提交。历史图只读取该版本自己的清单，不能套用当前分类。
- 不能简单递增现有格式常量而使旧历史被判无效；项目文档格式、历史清单格式与最低应用版本要明确区分，保留已有快照的读取能力。
- 上下文包、交换包和导入预检同步包含公开分类名称与 ID，不能只给 LLM 一串无法解释的分类编号。

## 4. 星图右键作为快捷入口

赞成增加右键入口：操作对象就在星图上，比离开星图去找表单更容易理解。所有入口最终进入同一个写作工作台。

| 点击位置 | 推荐菜单 |
|---|---|
| 空白星空 | 新建 DD、记录问题、新建设计分类 |
| 分类节点 | 在此分类新建 DD、修改分类名称/颜色、查看所属文档 |
| DD 节点 | 打开写作、更改分类、添加批注/标记 |
| 总纲 | 编辑总纲、新建专项设计 |

分类下新建自动带入类别。右键空白位置可以提供临时展开起点，但不由屏幕位置推断知识关系，也不直接改变版本中的正式排版规则。

区分右键单击和右键拖动，保留已有镜头操作；菜单展开时不转动镜头。空白左击仍取消选择，Escape 关闭菜单。增加可见“＋”按钮与条目菜单，键盘/触屏用户也能进入同样操作。历史阅读时不提供会写入旧版本的创建动作，明确引导回到当前稿。

## 5. DD 数量驱动的银河与柔和总纲

### 悬臂粒子

- 统计当前查看版本中未归档的独立 DD 文档；总纲、问题、章节、关系不重复计入。
- 每份 DD 对应一段有固定身份的微粒，文档增加时局部生长；移除或归档时局部淡出。
- 少量文档保持疏朗，文档多时丰富悬臂；采用增长递减与总预算上限，不能无限增粒子。
- 零 DD 只显示适量背景星空与已有总纲，不绘制一座与文档规模无关的浓密银河。
- 搜索和筛选只调整可见层次，不重新随机生成整座银河；历史切换反映对应版本的 DD 数量。
- 真实 DD 有明确实心星点、标题与可点击范围；装饰微粒不计入节点，也不代表一条规则或一条关系。
- 星尘缓慢流动、弱明暗起伏；文字和真实文档位置保持稳定。速度、振幅、数量都设上限。

### 总纲核心

保持主总纲位于中央、使用普通尺寸金色文字。缩小目前过大的实体和光团，实体候选大小约为普通 DD 的 1.4～1.6 倍，以清晰识别而不遮挡为准。

生命感来自收敛的光晕呼吸和少量环绕微尘，呼吸初始候选为 6～10 秒的小幅周期；不让核心位置漂移，不让文字缩放，不加入大幅旋转环、闪光或持续喷射。悬停/选中可短暂增强局部轮廓。

这部分参数先作为调试候选，不展示成用户必填设置。现有“静止”、系统减少动态效果与后台节能必须同时控制新效果；恢复动画不跳相位。

保留已认可的星图/分层转换 1150ms、关系分析进入/返回 520ms、内部焦点 360ms，以及空白取消、右侧阅读面板展开后的视角避让。

## 6. 浅色主题提升分类可辨识度

不再整体提高底色亮度，继续保持柔和雾灰基调。针对类别建立独立的浅色映射，使用更深的蓝、青绿、紫、赭金、砖红等颜色。

- 星图真实节点增加清晰中心与薄轮廓，降低装饰星尘相对存在感。
- 星图、分层、目录、图例、卡片使用同一分类身份与主题映射。
- 总纲的金色仍独立可辨，不把所有强调状态都变成金色。
- 分类文本保持可读；选中/悬停使用轮廓等辅助，不仅改变颜色。
- 面向识别的图形和选中轮廓以至少 3:1 的相关背景对比为检查目标，普通小字以 4.5:1 为目标；装饰星尘不承担信息识别责任。[W3C 图形对比](https://www.w3.org/WAI/WCAG21/understanding/non-text-contrast.html)、[文字对比](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)、[避免仅依赖颜色](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color)

## 7. 把开场白做成贯穿产品的协作能力

同时提供“常见开场白库”和“开场白组装器”。范例用于快速起步，组装器用于表达自己的游戏；两者使用同一份可编辑的游戏设想。无需先连接 LLM，就能在本地生成和预览完整开场白。

### 7.1 从一句设想开始，按需补充选项

页面从“一句话描述你想做的游戏”开始。下方是少量可组合标签与可展开的补充项，右侧实时预览自然语言开场白；窄屏上下排列。不要再改造成七八个必填字段依次排列的大表单。保留“直接创建空项目”，所有创意选项都可跳过。

| 输入组 | 常见选项与规则 |
|---|---|
| 起步范例 | 小规模解谜原型、卡牌构筑探索、策略战术、模拟经营、叙事冒险、只有模糊想法；都是可改写的起点，不是已确定玩法 |
| 游戏类型 | 动作、角色扮演、射击、策略战术、经营模拟、解谜探索、卡牌构筑、叙事；可多选、自定义或待讨论 |
| 本轮目标与内容规模 | 验证一个核心玩法、可玩演示、规划完整作品、尚不确定；先明确本轮产物，不用“独立/3A”代替实际范围 |
| 主要玩法 | 探索、战斗、构筑、解谜、经营、建造、叙事选择；多选并补充“玩家反复做什么”，可以完全自由输入 |
| 协作方式 | 先问我问题、给几种方向比较、基于已知约束起草初稿、只帮我整理已有想法 |
| 按需补充 | 平台、视角、单人/合作/对抗、期望单局长度、团队与时间预算、主题氛围、参考作品及具体借鉴点、不想要的内容；每项可自定义或待定 |

游戏内容规模、制作资源、游玩时长是不同维度，不能互相推断。选择“策略”不自动认定回合制，选择“小团队”不自动规定内容时长。范例推荐与用户选定内容有明确区分；没有确认的建议留为候选。

用户已经编辑的文字不能被切换范例或选项静默覆盖；提供明确的“用当前选项重新生成”操作，保留手改稿或可撤销。自动预览在尚未手改时正常更新。全部空白也能生成“请先帮我澄清方向”的有效开场白，不要求用户填满所有选项。

### 7.2 同一份设想，两个出口

1. **与 LLM 一起开始**：预览、自由编辑、复制完整开场白。可以先讨论再建项目；未创建时明确“尚无本地项目”，不虚构路径、版本或连接。已有项目则附当前项目、选中文档和本轮任务范围。
2. **我自己开始创建**：进入名称与文件夹选择，确认后建立项目。只写入用户确认的创作起点和选定分类，不自动生成几十份空 DD，不把模板建议写成正式规则。随后直接开始写总纲或 DD。

两个出口使用相同的输入，不让用户重新填一遍。“复制”不创建项目，“手动创建”不要求先接入模型。草稿选择与自动生成文本先保存在私人工作区；用户创建时确认的起点可写入 `PROJECT.md` 的“创作起点（待细化）”章节并随版本记录，后续细化再归入 GDD。

创作起点按“已知条件、想尝试的方向、未决问题”自然写作；记录设想不等于已经确定规则。若先手动建好项目再复制开场白，任务自动转为“继续当前项目”，不让模型另建重复工程。取消目录选择或创建失败时，原设想仍保留。

示例开场白（虚构游戏方向）：

> 我想做一款以探索和路线选择为主的单人游戏。本轮先验证核心玩法，不急于规划完整作品。已确定的是玩家需要在行进中作出资源取舍；战斗、世界题材和单局时长暂未确定。我目前是独立制作，希望先控制内容数量。
>
> 请先复述你理解的核心体验，指出还缺少哪些关键决定，再优先问我最多五个会影响原型方向的问题。每题给出两到三个可行方案、你的推荐及代价，并允许我自由回答、暂缓或否定前提。不要把未选方案当成我的决定。
>
> 我希望使用策问整理结果。目前尚未创建项目，请先完成这轮讨论；等方向明确后，再按策问的公开文档规范整理总纲、必要的专项设计和待讨论问题。正文以人阅读为先，用自然文句链接相关设计，技术字段由规范维护。

上述限制来自该范例选择，其他范例不能默认继承“独立制作”等未选条件。界面还会补齐实际可用的接入材料或文件交付说明。

### 7.3 常用协作场景统一准备开场白

| 入口 | 开场白应自动带入的内容 | 希望 LLM 完成的任务 |
|---|---|---|
| 从零构思 | 用户游戏设想、已确定/待定项、本轮目标 | 澄清方向、比较方案或给出候选初稿 |
| 导入现有策划 | 用户选定材料、目标项目、已有版本 | 盘点与映射原文，标出冲突和缺失，不擅自重写决定 |
| 接入/恢复协作 | 客户端能力、项目位置、接入说明、最新修订 | 验证真实连接，确认正在操作的项目和版本 |
| 深挖某个方向 | 当前 DD、相关文档、未决问题 | 生成带推荐、代价和自由回答入口的问询 |
| 新写或完善 DD | 当前正文、分类、适用规范、用户目标 | 整理候选修改，区分事实、推断与待定 |
| 检查关系与冲突 | 用户选中的设计范围和关联 | 给出依据、影响范围和修改建议，不制造不存在的规则 |
| 落实已回答问题 | 原始回答、已确认决定、涉及的 DD | 提出明确回写范围；不擅自把未采纳建议落实 |
| 版本复盘或交接 | 用户选定的两个版本、变更和未完成事项 | 解释差异、影响与下一步，让另一 LLM 能接续 |

统一按钮用具体任务命名，如“让 LLM 深挖这份设计”“复制交接开场白”；点开即可看到已经填好上下文的文本，不让用户面对空白提示词编辑框。支持用户保存个人范例与自定义附加要求，但不在第一版增加复杂的模板脚本编辑器。

统一生成结构为：**本轮任务 → 用户设想或所选内容 → 已定/待定 → 实际可用的接入方式 → 期望产物与协作规则**。任务与用户原文直接保留，技术能力信息由软件补齐。不是每次都附全项目正文：优先选中范围与相关摘要，需要更多时由模型通过可用工具读取。

所有未来 LLM 协作功能的完成标准都包含：有默认开场白、当前上下文自动填好、允许预览与编辑、支持自定义、明确输出与写入范围、接入失败有诚实的替代路径。此规则同步写入产品开发约定、接入说明与随软件交付的 Skill。

### 7.4 接入信息由软件准备，连接状态由事实确认

连接面板的主操作改成“复制给 LLM 的开场白”。当前项目、实际文件夹、策问安装位置、MCP 启动器、接入说明与 Skill 路径由软件填写，不再让用户替换路径或理解配置 JSON。技术配置保留在供代理读取的独立接入资料中。

默认开场白适用于任意具备相应能力的 LLM 客户端；客户端选择作为可选项。另提供“从零讨论”“导入现有策划”“基于当前文档深挖问询”的任务目标，避免接入后模型不知道下一步做什么。

示意开场白，真实界面会把所有上下文直接填好：

> 请帮我接入策问，并继续当前游戏的策划讨论。先读取附带的接入说明和项目入口，检查当前客户端是否已有策问工具。若没有，请根据你当前的本机操作权限完成必要接入；必须由我在客户端确认的步骤，请明确指出。接入后读取项目总纲、文档目录与最新版本，并报告实际项目名称和修订。先列出关键缺口，再给我一轮带推荐方案和自由回答入口的问询；不要代填我的答案，也不要自行采纳设计建议。若当前环境不能访问本机或注册 MCP，请说明情况，并使用文件或上下文交换方式继续。

接入可以简化为对话，但 MCP 仍由宿主客户端连接服务，普通聊天文本不能保证完成客户端注册。[MCP 官方架构说明](https://modelcontextprotocol.io/specification/2025-11-25/architecture)

“已复制开场白”“读过本机文件”“CLI 调用成功”都不等于 MCP 在线。成功提示需实际工具调用/连接确认，模型名只显示真实提供的名称。网页开场白以文件协作为默认，不能把 Pages 地址当作本机 MCP 地址。项目路径只在用户主动复制时提供，不包含令牌、模型密钥或私人笔记。

未创建项目或纯网页无法获知绝对路径时，不拼造不存在的路径。开场白只引用对接收方实际可用的入口；不能访问本机的 LLM 需由用户附上选定文档/上下文包。公开可读规范可随交换材料一起提供，使模型不用阅读策问源码。

开场白历史、个人模板及未发送输入默认是私有编辑器数据；只有用户确认纳入设计的内容进入公开文档。生成、复制、调整范例均不增加设计版本；正式创建、保存文档或采纳设计决定才进入既有版本流程。

内置范例和组装规则随应用发布；用户个人模板和建项之前的设想草稿保存在本机应用数据（网页为本地浏览器存储）；已有项目中的组装草稿保存在 `.cewen/`。个人模板只有用户主动分享或导出时才离开本机。已有连接通过验证后，开场白省略重复安装内容，直接承接本轮任务。

## 开发拆分与交付顺序

| 阶段 | 任务 | 交付检查 |
|---|---|---|
| A：创建与写作闭环 | 目录选择；公共分类登记；未命名草稿；正文优先的写作页；草稿恢复；附件暂存；第一次正式保存 | 从新建项目到保存第一份 DD，无手填路径、无 YAML、无占位版本 |
| B：创作起点与模型协作 | 范例库；类型/规模/玩法组装器；手动与 LLM 双出口；分类预设与星图右键；八类场景开场白；真实连接验证 | 选项可跳过和自定义；一份设想两种起步方式；每个协作入口都有可用开场白 |
| C：星图表达 | 两套分类色；DD 规模驱动悬臂；柔和核心；暂停/减少动态/历史联动 | 浅色可识别、银河随内容增长，原有阅读与切换节奏保持 |
| D：两端验收与发布 | 网页和桌面共用行为；文档/草稿无损检查；更新接入规范与使用说明 | 提供新便携包与 Pages 候选供用户验收，通过后发布稳定版 |

默认不执行自动化测试套件。必要的类型检查与生产构建照常执行，重点通过虚构项目人工走完整流程，记录实际覆盖与未覆盖项。

## 下一轮人工验收路线

1. 用选择器创建空项目；取消一次选择，再选择中文及空格路径，确认不覆盖已有目录。
2. 尚无 GDD 时直接新建 DD；选择常见类别或自定义类别，进入正文，没有技术字段挡在开头。
3. 写一段内容并添加图片，不正式保存就关闭重开；能在未完成草稿找到原稿，版本数未增加。
4. 第一次 Ctrl+S：生成一份 DD 与一个完整版本；正文无占位指导语，图片和分类一起落盘。
5. 在星图分类上右键新建，继承分类；右键拖动仍移动镜头，不误弹菜单；空白左击仍取消选择。
6. 外部编辑器或 LLM 修改同一份文件时，界面保留冲突双方；写作/源码来回切换不丢 ID、字段、锚点、链接、表格和原始问答。
7. 在深浅主题分别查看总纲及不同分类，缩放和打开阅读面板后仍清楚；总纲更柔和但不遮住 DD。
8. 比较 0、少量、数十及大量 DD，新增/归档/历史切换有局部生长与回退，不产生全图跳位；暂停、减少动态与切到后台都生效。
9. 把软件生成的开场白原样交给另一个 LLM 客户端，核对它读到的真实项目和版本；接入失败时给出确切状态并可走文件协作。
10. 从范例起步、全自定义、全部待定各走一次；选项生成通顺的开场白，手改预览不会被静默覆盖，复制不会创建项目或生成设计版本。
11. 用同一份设想分别进入手动创建和 LLM 协作，不重复填写；手动创建仅写入已确认起点，不把待定项和推荐方案变成正式规则。
12. 对已有 DD 发起深挖、检查冲突、落实回答、版本交接：开场白包含正确的范围与版本，没有私有笔记、凭据或虚构路径；未采纳的内容不被自动写回。
