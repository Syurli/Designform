# 策问正式开发任务与验收清单

日期：2026-09-22。状态：首版 0.2.0 功能已落地；下表保留原始验收标准。实现映射、已执行与尚未执行的场景见 [首版验收记录](首版验收记录_20260922.md)，不把实现完成等同于全部场景通过。

依据：[正式开发方案](策问_正式开发方案_20260922.md)、[文档目录与版本规范](策问_文档目录与版本规范_20260922.md)、[独立接入流程](策问_独立项目接入流程_20260922.md)。

## 1. 排序原则

- 以下 M0—M5 共 50 项属于首版必达任务，不能因为视觉已完成就跳过存储和版本基础。
- 每项完成要有代码 / 说明产物及实际检查记录；计划中的验收不算已经通过。
- 所有工具开发、构建及场景检查使用虚构示例与独立夹具，不访问或接入真实战术巫师资料。
- 默认不新增、执行自动化测试；用类型检查、构建、人工交互、文件往返和恢复演练记录证据。如后续改变此偏好，再单独确定自动化范围。
- 现有视觉和动效作为回归基线；版本演进是新增业务能力，沿用既有视图和风格。
- 版本落盘与历史可视化都是 P0。M1 首次正式保存即建立版本，M2 补齐阅读、比较、恢复和生长展示，不能在 M2 才开始保留用户历史。
- 每阶段有可交付结果，不把全部工程集中到最后才能运行。工期在 M0 技术验证后估算，当前不作无依据的日期承诺。

## 8. A1：战术巫师独立实机验收

此阶段不是工具开发中的示例任务，当前不启动。由用户在游戏策划对话中发起，参照独立接入流程执行。

| ID | 动作 | 完成证据 |
|---|---|---|
| A1-01 | 核对固定版本和用户指定资料范围 | 应用 / 协议 / 格式版本、源资料清单、独立目标路径 |
| A1-02 | 小批预检、映射与审核 | 用户看过实际候选差异，歧义被保留为问题 |
| A1-03 | 提交独立真实项目 | 来源只读；文档、问题、关系和版本快照完整 |
| A1-04 | 实际多轮问询与往返 | 游戏任务中的 LLM 读取当前 Markdown，用户回答，修改采纳并留下版本 |
| A1-05 | 历史与视图验收 | 旧版可读；3D / 分层的增长与差异符合真实修改 |
| A1-06 | 恢复、重复接入和问题回流 | 没有重复项或串写；缺陷用脱敏复现回到工具开发任务 |
| A1-07 | 独立验收结论 | 明确通过范围、未通过项目、未决设计问题；是否扩展导入由用户决定 |

流程内不修改策问源码。发现工具缺陷则固定现场、暂停受影响操作，开发侧修复并另发版本，再回到游戏工作流继续。

## 9. 首版人工验收场景

以下是原始验收标准。实际执行结果和未覆盖边界已记录在 [首版验收记录](首版验收记录_20260922.md)。AC-16、跨机与专项原生窗口检查尚未宣称通过。

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| AC-01 | 无模型从空白创建项目，写 GDD、两份 DD 和关系 | 关掉再开内容完整，目录独立；没有示例设计混入 |
| AC-02 | 关闭策问，用普通编辑器改标题、正文、关系和问题，再重开 | 界面与文件一致、原排版保留；观察到的变更形成公开版本，未观察的中间覆盖不伪造历史 |
| AC-03 | 同时在策问与外部修改同一文件 | 有三方差异，双方稿保留，不静默覆盖 |
| AC-04 | 两个窗口改不同 DD，随后提交 | 无关改动重验后可继续；涉及共同依据时提示更新 |
| AC-05 | 外部重命名、移动、删除、重复 ID、缺失锚点 | 身份正确续接或报告冲突；不复制内容、不复活删除 |
| AC-06 | 多文件保存中断后重开，再模拟外部插入新稿 | 识别未完成批次，恢复不覆盖第三种内容，不假报完成 |
| AC-07 | 同条目加入两个工作分组，删除其中一个组 | 正文仍一份，系统归属及正式关系不变 |
| AC-08 | 给片段批注，随后删除或移动该段，发布为问题 | 失效锚点保留摘录；发布后出现可读问题文档，私有笔记不自动公开 |
| AC-09 | 从首次保存起记录新增、修改 / 改名 / 移动、删除 / 归档，再重复保存未改内容 | 版本目录可读且不造空版；项目 / 文档 / 条目历史一致；归档区别于删除，图谱差异正确，身份与镜头稳定 |
| AC-10 | 播放版本、快速拖轴、进入分析后返回、外部新增提交、减少动态效果 | 最终停在正确的选定版本；无旧目标回弹或卡片闪空；历史只读且正文 / 附件 / 关系不混入最新内容 |
| AC-11 | 只更改问题答案，不更改设计规则 | 有问答修订与文字差异，无虚构的图谱生长 |
| AC-12 | 后续编辑、导入、替换附件、恢复旧稿、撤销较早批次，再手工改坏快照 | 恢复产生新版本，父修订与恢复来源分别正确；正常操作不改变既有快照及 manifest 哈希；后续记录不无提示消失；人为损坏有提示 |
| AC-13 | 同批导入两次、名称相似的不同 DD、过期提案 | 不重复、不误合并、不覆盖新的修改 |
| AC-14 | 问询包含推荐选项、自定义、暂缓和前提错误 | 推荐不等于答案；原话、模型解释和正式决定分开 |

| AC-16 | 第二个 LLM 仅拿项目说明及公开文档继续两轮 | 不读源码 / 数据库 / 旧聊天；能理解当前规则、问题和已采纳决定 |
| AC-17 | 备份复制到另一目录或电脑，删除索引再打开 | 当前与历史、相对附件完整；索引可重建；私有工作记录按备份范围恢复 |

| AC-19 | 桌面与浏览器共用项目、服务重启或断开 | 同一内容源；保存状态真实，草稿不丢，重新连接后核对磁盘 |
| AC-20 | 开发示例、正式空白项目和模拟外部项目分别操作 | 不串项目、不扫描真实游戏目录；发布包无真实摘录和本机源路径 |

规模检查使用约 100 份 DD、1000 个知识条目、3000 条关系的合成数据，记录实际性能后再确定下一轮优化。不得用实际游戏资料替代规模夹具。

## 10. 每项开发任务的统一完成条件

1. 实现所列能力并保持封板交互；新增代码有必要且完整的中文说明。
2. 文档格式或协议有变化时，同步更新独立说明、示例和迁移说明。
3. 变更有持久化结果；不能只是前端显示成功。
4. 失败路径不无提示丢稿；保存、导入、恢复和冲突显示真实状态。
5. 执行适用的构建 / 静态检查与人工场景，记录实际结果；未执行明确标注。
6. 不依赖真实游戏数据，不把私有内容加入工具仓库或发行样例。
